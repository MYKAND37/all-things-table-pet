# 逻辑：当 → 如果 → 就

> 规则、道具、液体、动画、状态 —— 这个应用的中心。
>
> 这一篇原来在 README 里，2026-09-24 拆出来。README 是门面，这里是细节。

## 关于逻辑：当 → 如果 → 就

**逻辑管理**现在是一张节点图：可以平移、可以缩放，**点任何一个方块改它**。
一条规则就是一行从左到右的链子：

```
┌────────────────────┐
│ 当：被甩出去        │   ← 点开选事件
└─────────┬──────────┘
          │
┌─────────▼──────────┐
│ 如果：生命 > 0      │   ← 点开改条件
└─────────┬──────────┘
          │
┌─────────▼──────────┐
│ 就：说「哇啊——！」  │   ← 点开改动作
│     痛苦 +20        │
└────────────────────┘
＋如果  ＋就  部位 全身   |   冷却 1.0s  只一次  删规则
```

为什么是图不是卡片列表：卡片列表说的是同样的东西、同样的顺序，而问题就出在这儿 ——
**一列卡片读起来是"一堆东西"，而一条规则不是一堆东西，是一条有方向的链子**，
方向恰恰是难看见的那部分。

方块本身很笨：它只知道自己要显示什么字、以及被点的时候报哪条规则的哪个节点。
规则**是什么意思**在引擎里，方块**写什么字**是构建它的人决定的 ——
所以画的部分可以靠眼睛检查，而意思的部分完全不在 Canvas 的子类里。

### 一套逻辑是给谁的：角色、道具、液体、**部件**

规则是同一套规则，**但"当"和"就"两边都要知道自己在说谁**。所以逻辑面板是**三层**的：

```
                     ┌ 桌宠A ● │ 桌宠B │ 道具 ┐   ← 第一层：文件夹，在图右上角
  角色 │ 部件 │ 粒子 │ 液体                        ← 第二层：这只桌宠的哪一类
  角色 │ hand_L │ head │ …                        ← 第三层：这一类里的哪一个
```

- **第一层是文件夹**，因为"每样东西的规则住在它自己的文件夹里"这件事在界面上也该看得见：
  一只桌宠一个文件夹（● 是"这只正在场上"），外加一个全局的**道具** —— 道具的规则是所有
  桌宠共用的，它不属于任何一只。放在**图的右上角**，免得和一排模块按钮混成一条横栏；
- **第二层**是这只桌宠的四类：**角色**（它自己）/ **部件**（它的每根骨头和每个节点）/
  **粒子** / **液体**（它声明的那几种）；
- **第三层**才是具体写给谁。点进去就是原来那张规则图，一行没变。

**编辑哪一只不需要把它召唤出来**：文件夹选的是"谁的东西"，测试场上是"谁在动"，
两件事分开，所以可以给一只没上桌的宠物写规则。**每样东西的规则住在它自己的文件夹里**：

```
characters/<角色>/logic.json                       角色自己的规则
characters/<角色>/liquids/<液体>/logic.json         一种液体的规则
characters/<角色>/parts/<骨骼>/logic.json           一个部件的规则（和它的图并排）
props/<道具>/logic.json                            一个道具的规则（所有角色共用）
props/object-logic.json                            旧的：全挤在一个文件里（只读，搬家前的）
```

**搬家是加法，不是减法**：读的时候新位置优先，**新位置没有才回退到旧文件**；
写的时候只写新位置，旧文件一辈子不动（那是用户的数据，不是我们的缓存）。
所以升级不会丢任何规则，而每个主体存过一次之后旧文件就自然退休了。

（唯一要小心的那条：**新位置存在但是空文件，不回退**。空的意思是"这个东西没有规则"，
不是"没找到"——回退就等于应用把用户删掉的规则又装回去。这条在这个项目里踩过一次，
所以 `tools/store_check.py` 现在同时盯着它。）

**部件是主体**，这是"让手流汗"变成一条规则的关键：它写在**手**这个主体上，
而不是写在角色身上、每次判定都问一遍"这是不是手"。部件自己的规则

- 听得到**发生在那个部件身上**的事（被抓、被打到、被道具碰到……规则里的"部位"照样可以写前缀，`hand` 管左右两只手）；
- 也听得到**发生在整具身体**上的事（被甩出去、落地、被点一下——手当然也是被扔出去的那具身体的一部分）；
- **听不到别的部件的事**，也听不到道具的事。

"喷粒子""喷液体""说一句话"这些动作，在没有指名部位时会**落在主体自己身上** ——
所以一条长在手上的、每隔一会儿就"喷粒子 汗"的规则，汗就落在手上。

（这一步只加了主体：规则先存在老地方。状态的两级、以及"每种东西一个文件夹"
见 `docs/PART_SUBJECTS.md`，那是接下来的两步。）

**为什么不用两套编辑器**：一支蜡烛烧完和一只角色流血，都是同样三个盒子写出来的。
两套界面意味着两套都要维护、两套都要学，而它们的区别其实只有"谁"。

道具和液体自己的事件：

| 事件 | 什么时候 |
|---|---|
| 出现时 | 这个道具第一次被放上桌子 / 这种液体第一次被喷出来 |
| 每隔一会儿 | 只要它还在场上 |
| 落地 | 它刚碰到地面 |
| 被打到 | 它撞到了角色，`部位` 是被撞到的那一节 |

**一个引擎只在这个主体真的在场上时才跑**：不然一支没人点的蜡烛会自己烧完 ——
"它在不在"是每个客体规则本来都得自己写一遍的条件，所以这一步由引擎替它做掉。

**「落地」这一行现在是真接上了的，而且只是最近才接上。** 表写了很久，但测试场里从来
没有人把事件送给 `liquid:<id>`：液体的引擎一辈子只见过「出现时」和「每隔一会儿」，
所以任何一条 `当 落地` 的液体规则都是死的 —— 不报错、不写日志，就是不发生。
现在液体按名字收「落地」，`值` 是这一帧有多少滴落地（和粒子一个形状：一次喷出来的
四十滴是一声，不是四十条规则）。

判定是**这个液滴第一次被地面拦住**，一辈子只报一次，而这句话本身是量出来的：先试
「它在地上」——静止的水洼每帧都成立，等于每秒六十次；再试「落下的速度够快」——水洼
第二层的滴被邻居挤下去时速度正好 300px/s，120 滴的水洼十秒里误报 8 次；再试「它至少
落了一个滴的高度」——从堆顶滑下来的滴是真的落下来了，可它不是新到的液体。「第一次」
既不会漏也不会重，因为一滴东西只可能第一次到地上一次。

反过来，**角色也能对道具动手**：「推一下道具」（选道具 + 力度 + 方向）和
「清掉道具」。这就是"这些东西可以成为客体"的另一半 ——
客体有自己的逻辑是一件事，角色的逻辑能够伸手动它是另一件事，两件加起来才是一个系统。

道具和液体自己说「说一句话」时，**气泡画在它自己头上**，粒子、液体也喷在它自己的位置。
同一份动作列表，从蜡烛的规则里跑出来烧的是蜡烛，不是宠物。

### 并行分支：一个侦测器，岔开若干执行器

「并行逻辑也有完整的侦测器和执行器，箭头是向下指过去的，就是岔开」。

    当：被点一下 ─┬─ 就：说「干嘛？」
                  ├─ 就：说「别戳我」
                  └─ 就：哭

- 一条**带分支的规则就是一个并行组**，它自己有完整的三个盒子：自己的「当」是组的侦测器，
  自己的「如果」是组的条件，自己的「就」是**第一支**执行器，`branches` 里每一项是另一支；
- **每一支都执行**，按写下的顺序 —— 全部响，不掷骰子；
- **分支有自己的「当」**：它等自己的事件，和组的那条**并行地**等（不是"组的当也成立"时
  才被看一眼 —— 第一版写反过，镜像当场抓到）。分支的冷却和「只发生一次」用**组自己的**：
  一个组是一件事，两个执行器各走各的节奏不是谁要的功能；
- **分支有自己的「如果」**：组说了"是"之后，这一支再问自己一句。问不过就只有**这一支**
  安静，别的支照旧；
- **「否则」不岔开**：条件不成立是另一条路，一个没响的侦测器上挂不了分支；
- 图上画成**岔开**：从侦测器那个盒子底下拉一条竖线下来，每一支一行横着接过去带箭头；
  分支行上的三个盒子（当 / 如果 / 就）点开改的都是**那一支自己的**；
- 存档：没有自己东西的分支还是一个扁平数组（它就是一个执行器）；带自己的当或如果的写成
  `{"on":…, "part":…, "if":[…], "then":[…]}`，两种都读。

（1.11.9 换掉的是原来那套**随机组** —— 同组每次只响一条、随机挑一个。那东西是一个**名字**，
没有地方挂自己的侦测器和执行器，而"并行"要的是每条支线都是一条自己的线。老文件里的组现在
会变成"两条都响"，这正是换掉它的意思。）

（镜像里钉了十八条：全响、顺序、没有分支时和以前一样、组的条件不成立时只有否则响、
带自己的当的分支不被组的当带动、它自己的事件来了才响、部位不对不响、条件不成立的那一支
不跑而别的支照旧、互斥的两支只响成立的那一支、带自己的当的分支如果不过时**不消耗组的
冷却**、以及文件格式的两半 —— 解析读 `"if"`、落盘写 `"if"`、有如果的分支不写成裸数组。）

### 还没碰到它：靠近 / 走开

「被道具碰到」只在**已经碰到**之后才存在，所以"躲开锤子"以前根本写不出来 —— 规则跑起来
的时候锤子已经砸上了。现在多了两个事件：

| 事件 | 什么时候 | 值 |
|---|---|---|
| **有东西靠近** | 某个道具**第一次**进到身边（两个表面之间 90px 以内） | 还剩多少空当 |
| **有东西走开** | 那个道具又出了这个范围 | 离开时的空当 |

- 量的是**同一个胶囊**：最近的那根骨头、减去两个半径 —— 和碰撞用同一套几何，所以「靠近」
  和「碰到」不会对"在不在同一个地方"给出两个答案；
- 事件**带着是哪个道具**（所以规则可以点名锤子，而不是"任何东西靠近都躲"），`部位`是离它
  **最近的那根骨头** —— 写前缀（`hand`）就是"离手近"。它也是**走开**时说的那根骨头，
  所以"往哪边走的"是量出来的，不是猜的；
- **是一个变化，不是一个状态**：站在旁边不动只报一次。要"一直待在旁边"就写「每隔一会儿」
  加一个条件 —— 一个每帧都响的侦测器会让没有冷却的规则一秒响六十次；
- **回来要出得更远一点**（90 × 1.6 = 144px）才能再算一次靠近：停在边界上的道具，身体还在
  呼吸，不能一进一出地抖；
- **关掉碰撞的骨头不算靠近**（和碰到那边同一条约定），**道具从世界里消失不算走开**
  （子弹过期、蜡烛烧完 —— 它没去任何地方，只是不在了）。

**阈值暂时是固定的 90px**，大约一只手的长度（`hand_L` 从手腕到指尖是 100px）：
引擎里还没有"比较事件里的数值"这种条件（`value` 现在只写进日志），一条能说"比 40 更近"的
规则需要规则自己带一个阈值字段 —— 那是另一件有名字的事，不是一个偷偷加上的旋钮。

### 规则可以点名「是谁」

事件里一直带着**是哪个道具**（被道具碰到）或**哪种粒子**（粒子的落地），日志里从 1.10.2 起
也写出来了——"被道具碰到"单独一行是整份日志里唯一答不出"这条规则想问什么"的那种行，
锤子的规则和球的规则读起来一模一样。

缺的那一半是**规则能不能点名**。现在能了：一条规则的「关于谁」可以是任何东西、某一件道具、
或某一种粒子。

    当：被道具碰到 ─▶ 关于谁：锤子 ─▶ 就：说「哎哟」

**两个名字都不写就是"任何东西"**（老规则一个字节都没变），点名的规则只在事件真的来自它时触发。
界面上这一行只出现在**真能带着主语**的三种事件上：被道具碰到、被打到、落地——别的时候给
一个永远匹配得上的筛子是噪音。

（镜像里钉了四条：空 = 任何道具都能触发、点名之后只认那一个、粒子的落地同样、别的粒子不会误触发。
把筛子从引擎里拿掉，第二条立刻红。）

### 有三种问题，答案在世界里

如果里的条件一开始只有"角色身上的数字"和"它自己声明的开关"。但有三类问题不在这两处：

| 条件 | 问的是 | 参数 |
|---|---|---|
| **部位** | 「手**比**肩膀**高**」——两节在屏幕上的相对位置 | 哪一节、比哪一节、更高 / 更靠左、至少差多少像素 |
| **绳子** | 「这一节**有没有被绳子连着**」 | 哪一节（留空 = 身上任何一处都算）、连着 / 没连着 |
| **状态**（别人家的） | 「**角色**穿着衣服吗」「**手**在出汗吗」——不归这台引擎管的开关 | 哪个开关（带「·哪一节」的是部件自己的）、开着 / 关着 |

答案是**测试场给的**：引擎自己不知道骨头在哪、不知道谁被绳子拴着、也不知道别的引擎里
那些开关现在是什么样，所以它拿着一个 `Facts`（`RuleEngine.Facts`）去问世界 —— 而**比较
留在引擎里**（哪个方向、多少像素余量、开还是关）。这样"手比肩膀高 30 像素"是一条规则，
而一份没有世界的引擎（本地镜像、编辑器）照样能回答"它会怎么说"。

**没有世界可问时，这三种条件读作不成立** —— 和"未知种类的条件"同一条规矩：新版本写的
规则不能让老版本整个文件停摆。写一个**没人声明过的**开关也一样读作关着，但那一下**会**
在日志里留一行（见下一节）。

两个细节值得写下来：

- **屏幕坐标 y 向下**，所以"更高"是 y **更小**。这种符号在静止姿势里看不出来，换一个姿势
  就全反 —— 镜像里钉了六条（高/放下、余量 10px 不够 30px 够、靠左比的是 x、有一节不在场上、
  没有世界可问）；
- **前缀照样管用**：条件里写 `hand`，左右两只手被连着都算 —— 和规则里"部位"的其它地方一样。

### 规则也能改画画的顺序：改变部位深度

「就」里多了一个动作：**改变部位深度**（哪一节 + 拉到最前面 / 压到最后面）。

图层深度本来是文件里的一行（`layers` 的 z），规则改不了它，**也不该改** —— 那是用户画的
顺序。所以这是**运行时的覆盖**：只影响这一次会话怎么画，收回测试场、换骨骼套、重新加载都
回到文件里的顺序。"抬手时袖子该在胸前面、手放下时该在后面"就是它。

### 条件是一个一个加上去的模块

**「如果」不是一格，是一串。** 每个条件是一个模块；条件之间那个 **而且 / 或者**
也是模块 —— 它有自己的小方块，点一下就翻过来：

    当：每隔一会儿 ─▶ 如果：痛苦 ≥ 60 ─▶(而且)─▶ 如果：状态 穿着 开着
                  ─▶(或者)─▶ 如果：生命 ≤ 20 ─▶ ＋加一个条件
                  ─▶ 就：说「……」 ─▶ ＋加一个动作

- **「当……就」**：一个条件都不加，就是"总是"。图上那个方块写着「总是」。
- **「当……如果……而且……就」**：加两个条件，中间那个连接词是「而且」。
- **「当……如果……就……否则」**：点最右边的「＋加一个否则」。
- **每个方块都能改、能删；没有的模块用「＋」点出来。**

读法是**从左往右，而且比或者紧**：上面那条读作
(痛苦 ≥ 60 而且 穿着) 或者 (生命 ≤ 20)。规则在**任何一组**成立时触发 ——
这跟任何人写 a and b or c 时的预期是一样的。

以前这里只有一个「如果」格子，**所以"如果……而且……"根本写不出来** ——
不是难写，是没有地方写。

### 执行器之间能插计时器（1.16.0）

一条规则是一串**顺序**执行。「先做 A，等两秒，再做 B」曾经写不出来 —— 不是引擎不行（一个
在中间的**等一会儿**一直是对的：它把剩下的动作记下来，到点了接着跑），而是**编辑器只有一种
写法**：行尾那个「＋动作」只会往最后追加，于是计时器只能落在最后一个执行器后面，而那里它
什么也等不到。

现在每个**空档**里都有一个「＋ / 计时器」的小盒子 —— 第一个执行器之前一个，每两个执行器
之间一个，**就**、**否则**、以及每个**并行分支**自己的那一串都有：

```
当 被点一下 → 如果 总是 → ＋计时器 → 就 说「一」 → ＋计时器 → 就 说「二」 → ＋动作
                            ↑ 点它，问几秒
```

点它就问「等多久（秒）」，然后**插**在那个位置（后面的往后挪，不是把谁改掉）。加在中间之后
图上会多出一个**就 等一会儿**的盒子，和别的执行器一样能点开改秒数、能删。

它和「就 → 等一会儿」是**同一个模块**，同一组数字（0–30 秒，默认 0.5）—— 两个门进的是
同一件事，只是其中一个知道你想把它放在哪儿。

**还没做**：在空档里插**别的**动作（比如"先 A、再说一句话、再 B"里的那句话）。空档盒子现在
只插计时器：每个动作都有自己的参数（哪一节、哪个道具、哪种液体），插进去还得分清楚它属于
哪张表，那是编辑器的一次重构，不是加一个盒子。要别的顺序，现在是「在行尾加好、再删掉前面
那个」—— 不好用，记在路线图里。

### 「就」后面可以跟一个事件模块

动作里有一个 **发一个信号**。信号是规则自己的事件：一条规则「就」发出它，
另一条规则的「当」接住它（事件列表里的 **收到信号**，名字填在"信号"那一栏）。

于是「被打到 → 等一下 → 说一句话 → 打开状态」可以写成几条各自很短、互相叫名字的规则，
而不是一串必须从头读到尾才知道在干什么的动作。**不写信号名就接住所有信号**，
写前缀就接住同一族。

信号是**排队**发的，不是立刻递归：「当 X 就 发 X」一行就能写出来，
但跑起来是无限递归 —— 排队加上每帧 32 个的上限，把它变成一个"发着发着就没人听了"的信号，
而不是一个崩溃。

**「如果」可以有另一半：「否则」。** 条件不成立时做什么，是另一串动作。
没有「否则」的规则保持老行为：条件不成立就整个跳过，**连冷却都不消耗** ——
所以它可以条件一成立就立刻触发。有「否则」的规则两条路都会走，
冷却管的是**走过的那条**，不然"疼就哼一声、不疼就安静"会每半秒哼一次。

**动作里还有一个「跳到规则」。** 信号是规则之间互相叫名字，但那是**排队**的——
要过一个事件循环才到。跳到规则是**立刻**的：控制权当场交给第 N 条规则，同一帧里继续跑。

三点是刻意的：

- **当和部位不检查。** 跳过去的目标不必是被同一个事件触发的，不然跳转就只是把规则写了两遍，
  而不是够得着它——跳到一条「当 是 每隔一会儿」的规则，从「被点一下」那里跳过去，是通的。
- **目标自己的一切照算。** 它的「如果」决定走「就」还是「否则」，它的冷却和「一次」照常消耗。
  被跳过去不等于复活：已经用过「一次」的规则，跳过去也不会再开火。
- **跳转是这条规则的最后一件事。** 写在它后面的动作**不跑**——和「等一会儿」一样是提前返回，
  区别是「等一会儿」把剩下的动作排队延后，跳转把它们丢掉。日志里会写清楚丢了几个，
  因为一条悄悄半路停下的动作串，数一数之前是看不出来的。

**跳转不可能转圈**，因为整条链被规则条数兜住：**一次事件里每条规则最多开火一次**。
于是 A → B → A 在第二个 A 停下，没有"最多跳几次"这个数要调，也没有会忘记设的那一个。

（这道闸门标在规则**开火**时，不是被**考虑**时。一条被看过又跳过的规则——条件不成立、
冷却没走完——还没轮到它，它在同一个事件里稍后完全可能成立，因为跳过它的那条规则刚动过一个数值。
`tools/logic_check.py` 里有一条测试专门盯着这件事。）

**事件和动作的完整清单，就是代码里的 `EventType` 和 `ActionKind`**，编辑器那两栏直接列它们。
这里不再抄一遍——上一版抄了，抄成了"九种事件、十种动作"，而实际是**十种和十九种**。

**部位可以写前缀**：写 `hand` 会同时匹配 `hand_L` 和 `hand_R`。

**引擎里没有「数值变了」这个事件**，这是故意的：任何对数值的反应都能写成
「每隔一会儿 + 条件」，晚半秒但**不会自己触发自己**。规则改自己正在看的那个数，
正是那种写的人永远解释不清的 bug。

默认那套里有一对**用到了顺序和否则**的例子：**点一下**的那两条规则，
第一条把「穿着」翻过来，第二条**读第一条刚设好的状态**说「好看吗？」或者「干嘛？」——
规则按写的顺序跑，这件事在默认文件里就有。其余默认规则（改了就覆盖，可以「恢复默认」找回来）：被甩出去 → 喊 + 痛苦 20；
落地 → 痛苦 12 + 灰；被打到 → 痛苦 10 + 火花 + 喊；痛苦 ≥ 80 → 一直喊疼；
生命 ≤ 0 → 说「……」+ 松开动作 + 喷血（**只发生一次**）。

## 关于道具

**道具管理**里做道具，**测试场**顶部「道具」按钮放一个到桌上。五种用法：

| 类型 | 怎么用 |
|---|---|
| **持续使用** | 拖到角色身上按住，一直触发（刷子、食物） |
| **装置** | 放在桌上不动，角色碰到才触发（地雷、图钉） |
| **投掷** | 拖起来甩出去，砸到哪算哪 |
| **射击** | 拖出方向松手打出一发；道具留在原地，是个发射器 |
| **钉子** | 点一下钉住：点空白处钉在桌上，点部位就把那一节钉在那儿；再点一下拔掉 |
| **绳子** | 先画一小段绳子，再点两个点：点空白 = 锚在桌上，点部位 = 系在那根骨头上 |

**绳子是有物理的**（1.11.7 重做）：Verlet 链条 —— 重力把每个点往下拉，相邻点按 rest 距离
互相拉回来，两端钉在锚上，地板和边界收尾。**先积完分、再解连杆、最后钉两端**：锚点是世界的
事实（骨头动了、桩就在那儿），绳子不能跟它讲条件，只能挂着。位置就是状态，所以"速度"是
这一帧和上一帧的差 —— 会摆，不需要额外存任何东西。

拉不拉得动身体，量的是**两个锚点之间的距离和绳子自己的长度**，不是某一节连杆被拉长了多少：
一堆堆在地上的绳子，个别连杆看着紧，其实一点都没在拉，按连杆算会得到一根有脾气的绳子。
系上去的时候绳子比两点距离长 18% + 20px —— 正好一样长的绳子是一条直线，永远垂不下去。

- **绳子长度**：0 = 自动（两点距离 ×1.18 + 20px）；写了数就是写死的长度 —— 一根三米的绳
  拴在两米宽的地方，垂在地上；
- **弹性系数**：同一个拉伸量能拽出多大力。1× 默认，小于 1 是软绳（拉得动但没劲），
  大于 1 是蹦极绳；
- **画出来的是你画的那一小段**，沿着链条一节贴一节、转到那一节的方向、拉伸到那一节的长度。
  所以要画的是一小段而不是整根：画整根的绳子只有一种长度能用。**没画过图案也是一根绳子**
  （默认画成带绞纹的粗线）—— 一个必须先画点什么才能用的功能，第一次用的时候看起来就是坏的；
- 旧的**锚点**和**绳段**都删了，存档里读到这两个 kind **读出来是绳子**，不是锤子：
  文件说的是"绳子"，改的是绳子是什么，不是那个道具是干什么用的。

**拖尾**长在**道具**上（`props/<道具>/trail.png`），只有「持续使用」类道具能画：拖着它走过
的地方留下一笔，2.6 秒淡完，最多 220 个（太多先掉最老的）。**按距离留印子，不按帧**：每 26
世界像素一个印子 —— 按帧留的实现，同一段拖动在快的手机上密、在慢的机上稀，而没有任何地方
会报错。印子跟着走的方向转（绕自己的中心转，不是绕角，否则一个正方形的印子会甩出去整整一个
边长），画在**最底下**，宠物踩在自己的拖尾上面。

**粒子画在宠物上面**（1.15.0 改的）。粒子原来只有一层，画在角色**之前**——所以火花、汗、血
画出来就立刻被宠物和道具盖住，"喷血"看起来像没喷。现在 `Particles.draw` 是两次：

| 谁 | 画在哪 | 为什么 |
|---|---|---|
| `drawStains` 印子 | 在**一切之前** | 落在地上那点印子算地面的一部分，宠物踩在它上面 |
| `drawLive` 活粒子 | 在宠物、道具、钉子、等待提示**之后** | 这一层才是"喷在身上的东西" |

气泡和平衡读数还留在粒子上面：一个是台词，一个是调试读数，都不该被一粒汗盖住。
`tools/wiring_check.py` 钉住这个顺序（改一行就会红），因为顺序正是那种"改一行就悄悄变回去"的东西。

**画板**（`ui/PaintBoardView.kt`）是上面三样共用的那块 128×128：手指画线，一笔一撤销
（24 步），橡皮是 `PorterDuff.CLEAR` 而不是涂背景色 —— 画布要叠在世界上面，一个不透明的
方块就是把方块画在桌子上。**空画板 = 没有图案**：存一张全透明的图等于把这一笔变成一个什么
都不留下的东西，所以清空再保存会删掉文件，回到默认（粒子回到圆点，绳子回到默认那条）。

道具**不经过规则引擎去推角色**——推力是物理，有没有人写规则都会发生。
规则拿到的是一个事件：「被道具碰到 · 力度 640 · 打在 hand_L 上」，
**怎么算账是角色自己的逻辑说了算**。所以锤子和枕头可以是同一个道具，只是规则不同。

道具**之间**也会碰：两个撞上就分开，重叠**对半分**，谁也不比谁重。
道具的"重量"按设计不在 `PropSpec` 里（就是上一条的理由：锤子和枕头是同一个道具），
所以规格能支撑的分法只有对半——从 `force` 里读一个质量出来，等于凭空发明一个
编辑器从没写过、规则也够不着的数。液体里两滴水重叠时用的也是同一个分法。

唯一不让路的是**被手指按着的那个**：手指拥有它的位置，所以另一个吃下全部的分离量。
按住锤子能把飞过来的东西敲下来，靠的就是这一条；两个都被按着，就谁也不动。

只有**正在靠近**的一对才会反弹。两个道具靠在一起并不算靠近，每帧都把它们弹开就会抖——
这和地面那一遍把同一根静止的骨头转两次，是同一个错误。

道具之间的碰撞**不产生事件**。事件的主语是「谁被什么碰到了」，得是角色或它的某个部位；
两个道具相撞没有这样一个主语。要让"子弹打中炸弹"发生点什么，需要的是**一种新的事件**，
而不是把 `Hit` 掰弯去凑。

道具图不用对位：它不挂在骨头上，图片本身就是那个东西。
**没图的时候画一个绿圈，那就是它的碰撞范围**——调手感的时候比图还准。

## 关于液体

**液体不是网格，是一群互相推开的液滴。**

没有格子、没有压力求解。让它读起来像液体的只有一件事：**重力把它们堆起来，而拥挤把堆摊成水洼**。
其余每一行代码都是为了防止这件事出错：

| 做法 | 不加会怎样 |
|---|---|
| 修正量**累加后一次应用**（Jacobi），不是边找邻居边推 | 结果取决于网格先返回哪个邻居 —— 水洼会抖 |
| 修正量**每帧封顶** | 一次喷出一百滴，两两都重叠，一百个修正加起来是**手榴弹** |
| 速度**从落点反推**，不是保留推力 | 重力每帧给地上的液滴加 40px/s，地面只把位置还回去；不管速度的话，一洼静止的水每一滴都报告自己在以 300px/s 移动 |
| 略远时**互相吸引**（黏性） | 只会推不会拉，水洼会一直摊到撞墙为止 —— 那不是液体，是一袋弹珠 |

**黏度**不是流体属性，就是"拉回去有多用力"：0 像水（流开、摊薄），1 像史莱姆（抱团、整体移动）。

液体本身可以在**逻辑管理 → 液体**里自己加：名字 + **九个色板挑一个** + 黏度 + **液滴大小** + **透明度**。
色板不是取色器 —— 九个色块是个决定，一个色轮是个爱好。白色在里面：牛奶、云、白化的血都不是灰色。

**液滴大小**（0.25×–4×，默认 1×）不是把图画大一点：半径就是地面、墙和身体把这一滴托住的距离，
而且人群要的间距跟着一起变（`crowdScale` = 场上最大那滴的半径 ÷ 基准半径）。三个数字都是量出来的：

| 大小 | 静止后的中位间距 | 一滴落地时离地多高 |
|---|---|---|
| 0.25× | 3.75 px | — |
| 1× | 15.0 px | 15 px |
| 2× | 30.0 px | 30 px |
| 4× | 55.5 px | — |

间距不跟着变的话，两个方向都会难看：大了会互相穿模、糊成一坨，小了会摊成一层**分开的珠子**
而不是一滩东西——间距才是让它们并成一个身体的机制，半号也一样。间距是**整滩共用一个**（取场上最大
的那滴），所以同一场上两种大小的时候，小滴会坐得比它自己想要的松一点；这是明说的近似，换来的是
一个网格而不是每个尺寸类一个网格。

**透明度**（10%–100%）乘进画一滴的**两次**绘制里（120 的光晕和 215 的主体），不是只淡主体——
清亮的芯裹着一圈实心边，那是肥皂泡。它照在**每一滴**身上：改一改现有的液体，场上已经躺着的那滩
不会跟着变，下一把才是新的。**0 不允许**（下限 0.05，界面 10%）：一滴在场上、规则找得到、宠物
踩得到，而没人看得见它——这比"没到全透明"更像一个惊喜。

规则里的动作叫**喷液体**（一次四十滴，落地就见分晓），还有**流液体**：每秒多少滴、流多少秒，
位置每一帧重新取自主体自己身上——所以一条长在手上的「流液体 血」，手走到哪儿血就跟到哪儿，
像一道伤口而不是一次喷溅。粒子那边对着的是**喷粒子**和**持续喷粒子**。

**流液体有两种形状**，量出来的差别在"还是流的时候"有多宽：

| | 一柱（`柱状`，默认） | 一团（`乱撒`） |
|---|---|---|
| 落点宽度（20 滴/秒，第一滴着地那一刻） | **18 px** | **502 px** |

柱状给每一滴**同一个方向**（向下）、只抖 ±3°，而且沿着发射点撒而不是撒在一个 12px 的球里，
所以它们一起走、落地是一条线，重力再把它弯成一道弧——那才是"倒水"的样子。乱撒就是喷液体
那种全圆随机，摊在时间上。**这两种不能靠"慢一点喷"互相代替**：四十滴同时生在一个点上会
互相挤爆（`_separate` 那一套），所以形状这件事由方向决定，不由速度决定。

每种液体还有一个**性质**开关：

- **和角色碰撞**（默认）：水滴绕着身体流、堆在脚上。
- **穿过角色**：角色对它不存在，水从身上穿过去（**地面和墙照样拦得住它**——这个开关说的是宠物，
  不是世界）。

（镜像里两边都钉住了：同一次喷、同一根腿，只差这个开关，落点差 490px vs 6px。）

默认那套里，**生命归零时会喷 40 滴血**。

**逻辑管理栏下面现在有一栏「液体」。** 每种液体一个方块，**点一下就往场上喷一把** ——
在这之前，液体是唯一一个除了"写一条规则然后等它触发"以外没有入口的系统，
而这个要求对一个只想看看自己的史莱姆长什么样的人来说太奇怪了。
方块右边写着场上有几滴，长按回到液体编辑。规则照旧能喷。

## 关于动画（1.17.0）

「让它动起来」有两件看起来不同的事，而这一版把它们做成了**同一个模型**：

| | 你说的是 | 用的是帧的哪一半 |
|---|---|---|
| **演算动画** | 「先把手摆到 A，再摆到 B，中间自己走」 | **姿势**（每根骨头的角度，两帧之间插值） |
| **绘制动画** | 「我画了 8 张，按顺序放」 | **开关**（每帧亮起一套图） |
| **半演算** | 「画了 8 张，但帧之间再调调骨骼」 | **两样都要** |

一帧就是三样东西：

```json
{ "angles": { "hand_L": -30.0, "hand_R": 12.0 }, "state": "挥手3", "seconds": 0.4 }
```

- `angles`：这一帧的姿势。**两帧之间由求解器自己走过去** —— 每一帧都把"这一刻的角度"交给
  布娃娃当**目标**（不是直接摆上去），所以半路上被拽了一下、被打了一拳，它接得回来。
  这就是"演算"两个字的全部意思：动画给的是**意图**，物理仍然是主语；
- `state`：这一帧**亮哪些开关**。它不是一张图，而是一个名字（可以好几个，用 `+` 连起来：
  `"挥手3+出汗"`）—— 给某根骨头加过「挥手3」这套图（部位 → ＋加一张状态「挥手3」的图，
  老功能），这一帧就把那根骨头换成那张画。**逐帧绘制因此不需要任何新机制**，而"半演算"也是
  免费的：图换了，骨骼照样按 `angles` 动。分隔符 `+` 进不了状态 id（`RigEdit.sanitise` 把它
  换成 `_`），所以"两个开关"和"一个名字里带加号的开关"不会分不出来；
- `seconds`：这一帧**走多久**（不是停多久）。

**速度**是整套的倍率（0.25×–4×，默认 1×），不是"把每帧的秒数改一改"：用户调的是"这段太快
了"，调速度不该改坏已经摆好的帧。**循环**可以把最后一帧接回第一帧（走路的循环因此是闭合的
—— 最后一段是接着走的，不是一下跳回去）；不循环的走完就**停在最后一帧上**，姿势和图都留着。

**入口在哪**：**侧栏 → 动画管理**（1.21.0 起独立成页，1.22.0 起右边就是角色本人 —— 摆帧、
换图、播放都在这一页里）。另外两个入口是"让它现在演一遍"：**测试场**顶上那一排里的
**「动作 3 · 动画 1」** 按钮（原来只写「动作 (3)」，一个只做了动画的桌宠上面写着「动作 (0)」
——**入口在它里面，而它看起来是空的**，所以两处都改成把动画数上了）点开就是**动作列表**，
上半截是动作、下半截是**动画**；以及规则里「就 → 播放动画」、长按侧栏的召唤按钮 →「播放动画…」。

**怎么做一个动画**（1.22.0 起在**动画管理**这一页里闭环，右边就是角色本人）：

1. 侧栏 → **动画管理** → ＋ 新动画 → 起个名字、调速度和循环；
2. 右边直接拖关节把宠物摆成第一帧的样子（想换图就点上面那排开关；斜着画的身体用「转 90°」
   或双指旋转把视角转正；「骨骼」可以只留角色本身）；
3. 按 **「＋ 帧」** —— 抓的是**它现在真的摆成什么样**（每根骨头当前的角度）和**现在开着的
   那几套图**，插在选中的这一帧**后面**；
4. 改下一帧：摆姿势 → 「＋ 帧」；想改已经有的那一帧就点横带上那一格，摆好之后按
   **「存入这一帧」**（写的是整只的姿势，不是"只写动过的"）；
5. 每帧的秒数用 **「帧 −0.1s / ＋0.1s」** 调；**▶ 播放**就在这一页（从选中的那一帧开始演，
   播到哪一格横带上就亮哪一格）；碰一下画布会停下来 —— 停下来才能改。

测试场那张动作表里的路也还在（在测试场上摆好 → 「＋ 用现在的姿势加一帧」）：那一条适合
"边玩边抓"，这一页适合"一段一段做出来"，两边写的是同一份 `animations.json`。

**停止和走完不是一回事**：按「⏹ 停止」图回到默认那一套（姿势留着 —— 停下来的地方就是你看的
那个样子）；**不循环**的动画**走完**时不清图，停在最后一帧上。一个画了 8 帧的动画播完最后一下
就变回默认图，是"播完了"看起来像"坏了"。

**三个入口**：测试场那张动作列表（手动播）、规则里的**播放动画**（自己播）、长按侧栏的召唤
按钮 → **播放动画…**（桌面那一只播）。三个都按**名字**找，名字不认识就什么都不做，而且说一句
（日志 / 弹一句）—— 和 1.15.2 的「摆动作」同一条规矩。

**文件在哪**：`animations.json`，和 `poses.json` 一个地方（**按骨骼套**一份）—— 帧里写的是
骨头名字，换一套身体那些名字就不存在了。测试场和桌面上那一只是**两个实例**，所以动画表也是
`load` / `swapRig` 的**参数**（没有默认值，忘了就编译不过），和动作表一样。

**还没做**：在应用里**画**帧（现在的帧图是导入进来的，和部位图同一条路 —— 手机上的画图 App
画好、导进来）。内置一块全画布的画板是另一件事（现在的画板是 128×128，给粒子/拖尾/绳子用的），
记在路线图里。

## 关于状态

**状态是开关，不是数字。** 「穿著」「受伤」这类事实，用数字表达要解释"1 是穿着还是 2 是"，
用开关不用。逻辑管理里自己加，一个角色一套。

它连着两个地方：

- **图层**：在「图层与深度」里给每个部位选一个状态，那个部位就**只在状态打开时才画出来**。
  给衣服的每个部位都选「穿着」，穿衣服和不穿衣服就是同一副骨架的两套图 —— 
  不需要第二只角色。没选状态的部位永远画。
- **规则**：「如果」里可以测状态开着还是关着，「就」里有打开 / 关闭 / 切换三种。

删掉一个状态，引用它的规则读到「关」，引用它的部位**照常画** ——
名字没了就把图永久藏起来，那是找不回来的 bug。

### 全局状态和局部状态

状态分两级，**由谁声明就是谁的**：

- **角色自己的状态**（全局）：在主体是「角色」时加的状态。写着 `穿着`、`受伤` 那种。
- **部件的局部状态**：把主体切到「部件·手」，在同一个状态面板里加的状态就是**手的**。
  手可以有自己的「出汗」，和角色自己的状态**互不相干** —— 名字一样也是两把开关。

**它在哪里做**（这是这一版补的：机制从 1.11 就在，**门没写出来**）：**逻辑管理 → 状态**
——那个弹窗里的是**当前主体自己的**那一份。要么先把上面那排 chip 切成「部件 · 手」，要么在
弹窗里点最后那一行：

- 在**角色**上：「**给某一节加它自己的状态…**」→ 挑一节（每一节后面写着自己已经有几个）→
  主体跟着切过去，弹窗在那边重开；
- 在**某一节**上：「**回到角色自己的状态（全局）…**」→ 切回角色。

标题也说明了在看哪一份（「状态 · 角色（全局）」/「状态 · 手指（这一节自己的）」），
而**部件那排 chip 上就写着每一节自己有几个状态**（`部件·手 ·2`）—— 两级状态的分工因此是
看得见的，不是要记住的。问「怎么让每个部位处于不同状态」这件事本身就是一条 bug 报告：
功能在，入口没写出来。

规则里的「状态」**只写名字**。哪一级的名字都能写 —— 引擎先在自己**声明过**的那些里找，
找不到就问世界（见「有三种问题，答案在世界里」）：

| 一条长在手上的规则…… | 问的是 |
|---|---|
| 「如果 状态 **出汗**」（手声明过 `出汗`） | **手自己的**那个出汗 |
| 「如果 状态 **穿着**」（手没声明过） | **角色的**穿着 |
| 「如果 状态 **hand_L:出汗**」 | 手自己的那个（同一把开关的另一种写法） |
| 「如果 状态 **hand_R:出汗**」 | **另一只手**的出汗 |

这条规矩是 1.15.1 补上的。在那之前，一条长在手上的规则**只能看到手自己的状态** ——
面板上那张表里根本没有角色的「穿着」，所以「手在出汗的时候解掉衣服」这句话**写不出来**。
「就 → 改变状态」现在也走同一张表：能问的就能改，改的也是**真的那一把**（以前
`states[名字] = 开` 是照写不误的，于是手上的规则"打开穿着"打开的是一个只活在那台引擎
内存里的开关 —— 图层看不到、别的规则也看不到，而规则看起来是成功的）。

**唯一够不着的**是**重名**：如果手自己也声明了一个叫 `穿着` 的状态，那么在手这里
「穿着」指的是**手自己**那把（引擎先看自己声明的，这一条不能反 —— 不然一节手上的开关
在没有世界的时候就没法用了）。面板会**不列出**那个够不着的全局开关，并在下面写一句
说明；要两个都能用，把其中一个改个名。

图画在哪一级也是有据可查的：一张状态图的**图层标记**，全局的就是状态名，
部件自己的写成 `hand_L:sweat`（关着时画则是 `!hand_L:sweat`）。
渲染器只有一张开关表，就用这个标记当键 —— 于是 `visible()` 一行都不用改，
而**名字撞了也不会画错**。

图画在哪一级也是有据可查的：一张状态图的**图层标记**，全局的就是状态名，
部件自己的写成 `hand_L:sweat`（关着时画则是 `!hand_L:sweat`）。
渲染器只有一张开关表，就用这个标记当键 —— 于是 `visible()` 一行都不用改，
而**名字撞了也不会画错**。

测试场上面那排开关**两级都会列出来**（局部的那个写着「出汗·手」），点一下就是翻转它 ——
包括"某个部件只有一个状态、还没写过规则"的情况：那个状态的主人（部件的引擎）照样建起来。

### 状态还能换图，不只是藏图

**一条骨骼可以有多张图**，而"哪张图"是**一个文件夹**，不是一个按钮：
「桌宠管理 → 打开一只 → 部位」里，**点任何一个部位**就进它的文件夹，
里面是它所有的图，一行一张，**每行左边是那张图本身**，
右边写着它什么时候画：

    总是画                    → parts/upperarm_L.png
    状态「机械臂」关着时画      → parts/upperarm_L.png（图层上标着"不画机械臂"）
    状态「机械臂」打开时画      → parts/upperarm_L__mech.png

点一行**就是换那一张**（同一个文件，新图），右边是删除，底下是
**＋加一张图** / **＋加一张状态「机械臂」的图** —— 后者会自动建好图层，
和以前那个 **状态版本** 按钮做的事一样，只是现在**看得见自己在干什么**。

（这两个文件名的写法就是**加载契约**：加载器必须同时收下 `parts/<骨骼>.png` 和
`parts/<骨骼>__<状态>.png`。少收后面那种的后果是"文件在硬盘上、文件夹里列着、
图层指着它，而宠物身上没有"——这个 bug 真出过，就是"上传图片时看不见"，
见 `tools/parts_check.py` 里"什么名字能进库"那一节。）

在这之前，图是看不见的：导入一张，之后唯一的证据是宠物看起来不一样了。

删掉一张状态图，**同时会把图层删掉、并且把原来那张恢复成"总是画"** ——
不然那条"不画机械臂"的标记会留着，于是机械臂关掉时那条胳膊会凭空消失，
看起来像 app 坏了，而不是像图被删了。

于是"装上机械臂"就是：同一条 `upperarm_L`，两个文件，一个状态。

状态那栏现在可以选三种：**总是画** / **状态打开时画** / **状态关着时画**。
第三种的写法前面加个 `!` —— 这就是"替换"和"叠加"的区别，
不写的话状态一打开两张图会同时出现。

默认那套里有一对现成的例子：**点一下角色切换「穿着」，扔它的时候如果穿着就会喊「别弄脏衣服！」**。

### 状态多了以后，图层深度怎么改

一只桌宠的状态一多，**图层与深度**那一页就变成「二十行里找三行」—— 而要找的三行，往往还是
同一件衣服的三个部位，位置却分散在整张表里，▲▼ 一次只走一格，走的那一格还可能是别的状态的。

所以那一页顶上多了一行**过滤**：**全部 · 总是画的 · 每个状态一个方块（带层数）**。

- 选了哪一组，就只显示哪一组的行（一个状态的两半都算它的：`mech` 和 `!mech` 是同一组的
  正反面）；**顺序还是那一个顺序**，过滤只决定你看得见哪几行 —— 不是给每个状态各存一份顺序
  （那是两套顺序，迟早对不上）；
- 过滤时 **▲▼ 是在这一组内部换位**：它把这一行和「下一个你看得见的行」对调，别的状态的行
  原地不动。这正是「改某个状态的深度」的意思，也是不加过滤时做不到的那件事；
- 每一行右边那个方块仍然是这一层挂在哪个状态上（点它改）。

### 用不上的图层：三种「画了等于没画」

一个没人用的图层是**安静**的：不报错、不画、这一页里那一行还长得跟别的行一样。三种情况：

| 情况 | 症状 | 这一页怎么处理 |
|---|---|---|
| 它等的**状态已经不存在**（状态被删了，或者包是别人给的） | 永远没人打开它 | 行上标 ⚠，点开可以**改成别的状态**、或者**把那个状态重新建出来**（在哪一级建：标签带骨头就是在那个部件上建） |
| 它要的**图不在硬盘上** | 同上 | 点开直接送到**那根骨头的部位图**页面去导入，或者把这一层删掉 |
| **图画好了，可是表里没有它的行**（`hand_L__mech.png` 这种变体最容易） | 这一页里连找都找不到它 | 打开这一页时自动补一行，状态从文件名读出来（`addVariant` 就是这么命名的），存一次就正式进去了 |

顶上的过滤里有一个 **「用不上 N」**：点它就只剩这些行 —— 一个没人看得见的图层，是没人会去找的
图层，所以它得自己站出来。

### 状态在哪里打开、关掉、看到效果

状态做了三件事，之前只有第 1 件是看得见的，所以「加完状态然后呢」是个真问题：

1. **控制画哪张图**（图层，和上面说的状态版本）
2. **规则能读它**（「如果 状态 X 开着」），也能翻它（打开 / 关闭 / 切换）
3. **可以手动拨** —— 这是这一轮加的

所以现在：

- **测试场上面多了一排开关**：`● 穿着` / `○ 机械臂`。点一下就翻，
  立刻能看到另一张图长什么样。**没有这个东西就写不出关于机械臂的规则** ——
  你没见过它装上去的样子。
- **逻辑管理 → 状态**里每一条现在写着它被用在哪（`用在 2 张图 · 3 条规则`），
  点进去是能做的事：**现在打开/关上**、改名字／初值、
  **看哪些部位有它的图**（点进去就是那个部位的文件夹）、
  **用它做一条规则**（直接生成一条「当 被点一下 如果 状态 X 开着 就 说……」）、删除。
