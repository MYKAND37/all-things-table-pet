# 验证

> 本地 18 个检查各自钉着什么，以及每一版的验证记录。
>
> 这一篇原来在 README 里，2026-09-24 拆出来。README 是门面，这里是细节。
>
> **一条命令跑完全部**：`python3 tools/check_all.py`（21 个检查 / 约 80 秒）。它把结果分成
> 绿的、**欠账的**（已知是红的那三笔）、环境缺东西跳过的、以及真红的 —— 欠账不判失败，但会
> 单独列出来，因为一笔不肯写在明面上的债是最糟的那种。下面每一节的断言，就是它跑的那些。

## 关于验证（这一层也一样）

**规则引擎里没有一行 Android**：它只把"世界要执行的动作"还给调用方，
自己不知道气泡、骨头、粒子是什么。所以整个逻辑层能在本地测——

```bash
python3 tools/ragdoll.py          # 落地、倒吊、铰链限位、松开手的速度
python3 tools/drag_check.py       # 拎着脚踝倒吊、两根手指劈叉、甩出去的速度、拖起来会不会抖
python3 tools/carry_check.py      # 提脚整具身体翻过来（抬起多少、抓哪一段、什么帧率）
python3 tools/english_check.py    # 中英两份资源：键对得上、占位符没丢、还剩多少没翻
python3 tools/anim_check.py       # 动画：两帧之间插值、速度倍率、循环、图在哪一帧换
python3 tools/logic_check.py      # 冷却、只一次、而且/或者、信号、延时、规则顺序、别人的开关
python3 tools/rig_edit_check.py   # 加/删/换父级、部位属性的角度范围真的被求解器遵守
python3 tools/rig_prop_check.py   # 碰撞推出、接触节流、落地、投掷速度、道具对道具、名字→位置（骨头还是节点）
python3 tools/fluid_check.py      # 水洼会摊平会停、液滴认得自己那种液体、液滴大小真的改了间距
python3 tools/particle_check.py   # 粒子：受不受重力、落在地上留不留印子、颜色和大小是哪种粒子的
python3 tools/parts_check.py      # 图层、状态、画哪张图
python3 tools/store_check.py      # character.json 四处读-改-写：骨架、状态图、深度、改名
python3 tools/settings_check.py   # settings.json：缺键、越界、写坏了都不崩
python3 tools/camera_check.py     # 镜头：默认缩放看得见宠物、放大后丢了它要能找回来、喷的液体落在窗口里
python3 tools/mirror_check.py     # Kotlin 和 Python 两份实现的常数是不是同一个数（漂了就红色）
python3 tools/kotlin_check.py     # Kotlin 源码：NaN 陷阱、枚举重名、括号、资源引用
python3 tools/wiring_check.py     # 布局里的控件有没有人接线、函数有没有人调用
```

**后四个不是物理，是"物理测试永远看不见的那一类"**：

- `store_check.py` 镜像 `CharacterStore` 里**四处会改写 `character.json` 的地方**。
  四处都是**读-改-写用户自己的文件**：物理错了看得见，文件悄悄少了一样东西看不见。
  它已经抓出两个真 bug（保存骨架会删掉状态图、改名会把状态图落下）。
- `camera_check.py` 镜像的是**视口**：默认缩放该看得见宠物，双指放大**丢了**宠物之后
  要能自己找回来，喷出来的液体会不会落在窗口看的地方。**"角色不显示"这个报障出现过两次**，
  两次都是镜头算错但看起来像应用坏了——一次是宠物被放在地面之上掉下去，
  一次是房间变深之后宠物站在最底下、一放大就滑出窗口（跟着走的逻辑**只有横向**）。
  它顶上还会把 Kotlin 那边的两个常数读回来核对：镜像漂了比没有镜像更糟。
- `wiring_check.py` 抓的是"写完了没接线"：布局里有没有哪个**控件**一行 Kotlin 都没提到
  （点了没反应，而且没有任何地方说为什么），以及哪些函数**定义了没人调用**。
  前者是失败，后者只是一份阅读清单——见谁都喊的检查器会被无视。
- `kotlin_check.py` 抓的是 Kotlin API 的坑。最典型的一个：
  `optDouble("roomAir")?.toFloat() ?: 兜底` —— org.json 单参数版在键不存在时返回
  **NaN 而不是 null**，`?:` 永远不触发，于是地面、骨骼坐标、视图变换全变 NaN，
  **宠物画在"不是数字"的地方 = 什么都没画**。这个 bug 出过一次，
  两条检查都带自测，而且都**拿真 bug 反过来验过**（把错改回去，它报错）。

其中 `logic_check.py` 会**直接读 `LogicSpec.kt` 里那套默认规则**，
把事件名、动作名、数值名和 Kotlin 枚举逐个对照——默认规则写错一个字母，
本地就红，不用等装到手机上才发现"点了没反应"。

## 关于验证

物理有两份实现：Kotlin 引擎，和 `tools/ragdoll.py` 这份参考实现（带测试）。
**两份都必须存在**：Kotlin 只能在手机上跑，而手机不是用来调试数值的地方。

参考实现里完整记录了**两条走错的路**，都看起来很合理：

| 做法 | 为什么错 |
|---|---|
| 根节点用 Verlet 积分 | 拴点会瞬移根节点，而 Verlet 把位移当速度，下一步再加一遍 → **一秒内平方到 NaN** |
| 用"力"拴住被抓的点 | 平衡态是**退化**的：力只取决于手离手指多远，而"差一个弹簧长度"在任何身体位置都成立。所有参数都得到**逐字节相同**的错误姿势 |

最后可行的是：**先用 IK 让被抓的链条去够手指，够不到的部分才平移根节点**。


这台机器**编译不了 APK**（没有 JDK / Android SDK），所以：

- **数学**由 `tools/skeleton_tool.py` 在本地验证——它是 Kotlin 引擎的参考实现，
  含往返测试（随机合法姿势 → 取末端 → IK 反解 → 比对）和真实拖拽测试。
- **编译**由 GitHub Actions 验证。

```bash
python3 tools/skeleton_tool.py \
  --spec app/src/main/assets/characters/female_base/character.json \
  --verify --out docs/template_female_base.png
```

改动骨骼数学时**务必先跑这个**——它抓到过两个真实的符号错误，那两个错误在静止姿势下
完全看不出来，只有拖拽才会暴露。

动作列表的缩略图也一样：拟合外框取的是**骨架自己的外框**，不是画布——
用画布的话，一个蹲下的动作会缩成一个小点。`tools/pose_preview_check.py`
把几个姿势画成一张对比图（`docs/pose_preview_check.png`），改缩略图逻辑时对着看：

```bash
python3 tools/pose_preview_check.py
```

**这一版新加的两处验证**（两件新功能各有一条本地断言链）：

- **分支自己的如果**：`tools/logic_check.py` 的镜像里，规则的如果和分支的如果走**同一个**
  `holds_conditions`，测试钉住"不成立的那一支不跑而别的支照旧"、"带自己的当的分支如果不过时
  不消耗组的冷却"；另外三条是**文件格式的两半**（解析读 `"if"`、落盘写 `"if"`、有如果的分支
  不写成裸数组）—— Kotlin 的 `toJson` 在这台机器上跑不起来，而这个项目踩过一次"只加了读、
  忘了写"，所以那两半在源码里点名核对。
- **靠近 / 走开**：`tools/rig_prop_check.py` 镜像了 `nearMisses`（和碰撞同一套胶囊）和
  `NearWatch`（两个变化 + 带回差），十四条断言：量出来的空当就是"圆心距减两个半径"、
  说出最近的是哪根骨头、进到阈值以内只报一次、出到 90×1.6 之外才报走开、回来能再报一次、
  在阈值附近来回抖**只算一次**、关掉碰撞的骨头不算靠近、道具从世界上消失不算走开。
  两条阈值常数是**从 `PropWorld.kt` 里读出来**跟镜像比的，不是手抄的。

## 叠加图 / 碰撞范围 / 动画管理这一版的验证

**叠加还是替换**：`tools/parts_check.py` 五句 —— 这是这一版最值得量的地方，因为两种关系
**层的结构是同一对**，区别只在一处标记：替换时状态开着只画新那张（老的让位）、关着只画老的；
**叠加时两张都画、新的在上面**、关着只剩老的；以及新层紧贴它那张图（量的是层序：手臂的
叠加层画在胸口**之前**，不是压在最上面）。`tools/wiring_check.py` 七句盯接线（两种关系都能选、
替换写 `!tag` 而叠加一个字不动、`baseZ + 1`、一键反悔、切换只改那一个标记、没有图就不给改成
替换）。

**碰撞范围可见**：`tools/wiring_check.py` 六句 —— 要害是**画出来的就是撞上的那个**：半径只有
一处判断（`CharacterSpec.colliderRadiusOf`，求解器与编辑器都调它）、形状跟着求解器（胶囊是圆头
粗线、圆在中点）、`collides = false` 的骨头不画（画一个不存在的碰撞体会让人以为开关没生效）、
正在调的那一节亮着画而关掉弹窗就撤掉、能一键看全部、半径写在图旁边（自动算的会说明是自动）。

**独立的动画管理页**：`tools/wiring_check.py` 四句 —— 侧栏多了一项而且有自己的一页、
按 `MenuItem` 的规矩进 `menuItems`（rail 检查盯着顺序）、页面自己建、**编辑器不再绑定某一个
容器**（改完叫回调，谁开的重绘谁）。

## 动画工作台这一版的验证

**一帧能同时开好几套图**：`tools/anim_check.py` 八句 —— 空串拆出空表（"不开图"和"没写过"是
同一个值）、`+` 拆开、多余的加号和空格不产生空名字、拼回去去重保序、拆了再拼是原样、以及
**分隔符进不了状态 id**（那句直接读 `RigEdit.kt` 的字符表，不靠记性）。

**编辑器看到的那一帧 = 播放器演到那一刻**：这是这一版最值得量的一条，因为右边演的东西如果
和引擎算的不一样，用户会摆出一个"引擎演不出来"的姿势 —— 摆好、存下、一播就变样，是最难查的
那种错。所以 `anim_check.py` 拿五种动画（两帧循环 / 三帧不循环 / 2 倍速 / 一帧 / 含 0 秒帧）
逐帧比 `framePose(a, i)` 与 `sample(a, startSeconds(a, i))`：**帧号一样、每一根骨头的角度也
一样**（时间用二进制精确的 0.5 秒，边界相等是精确的）。另外单独钉住那条最容易错的规矩：
**下一帧才写的骨头，在这一帧里就已经是下一帧的值**（不是 0），以及帧起点时间会夹住。

**接线**：`tools/wiring_check.py` 二十句，钉的是"用户能不能用上"而不是"我写没写"：右边真的是
第二个角色视图（不是又一个列表）、左边有关键帧横带和「＋ 帧」、选中一帧摆的是 `Anim.framePose`、
拖关节会报"改过了"、骨架也能在这页改、**改骨骼写回的是正在看的那一只而不是 `opened`**
（这条最阴：写成 `opened` 在"打开 A、放上场 B"时会安静地写错一只）、图开关名单来自声明过的
状态、「底图」给了一条"什么都不开"的路回去、旋转/缩放/平移三件事都在、旋转只做一次（画布层）、
摆正视角会把三样一起收回来、这一页也能播、关键帧加/存/删/改时长各有一个函数、加帧插在**这一帧
后面**、存一帧写的是整只的姿势、时长两个方向各 0.1 秒且夹在界面那把尺子里、底下那条每个 chip
都挂上了自己那一件事、离开这一页会把图解掉、以及**「停」和「碰一下」是两件事**（前者回到你在
编的那一帧，后者只是停下时钟 —— 用户碰一下就被复位回帧里的角度，等于把他刚拖的那一下吃掉）。

**本地那八条看不见的两类错**：`kotlin_check.py` 加了第九条 —— **View 子类不许声明平台自己的
名字**（`setRotation` / `setAlpha` / `setScaleX` / `invalidate` 那一类，`override` 的除外）。
它是被真错误逼出来的：这一版给"转画布"起名 `setRotation`（= 转整个控件），CI 报
`hides member of supertype 'View' and needs 'override'`。加完用同一个错误反过来验过 —— 写回去
立刻红，改回来立刻绿。另一条（`s == null` 推不出 `anim != null`）**故意没加检查**：判据要一张
流图，写歪了就是误报，理由记在 `docs/JOURNAL.md` 第七节。

**旋转是视图的**：`SkeletonView` 里 `vx/vy`、`toCanvas`、`anchorAt` 共用同一个支点（视图中心）
和同一对 cos/sin 缓存，所以四件事（缩放 / 旋转 / 平移 / 拖关节）互不知情；旋转为 0 时
cos=1、sin=0，那两行就退化成原来的两句乘法 —— 这一版没有给"没转过"的情况加任何代价。

## 免责声明确认门这一版的验证

`tools/wiring_check.py` 八句 —— 一条门要成立，四件事都要在：**关不掉**（`setCancelable(false)`，
返回键与外点都不行）、**不同意真的退出**（`finishAffinity`）、**同意之前没有副作用**（门在
`store.ensureSeeded()` 之前 —— 这条断言比的是两个位置的大小，所以顺序被人挪了会红）、
**对话框被系统收走而人还没选也算没同意**、正文能滚（不然一段法律文本会把按钮顶出屏幕）、
设置里能重读并显示同意过第几版。

`tools/settings_check.py` 六句盯"记住的是什么"：缺键 = 没同意过、同意过当前版就不再问、
**签过旧版不算同意这一版**、手改成 999 不等于同意了未来的版本、负数夹回 0、来回一趟不丢键。

## 应用背景图（主题）这一版的验证

`tools/settings_check.py` 十条 —— 名字是这一版唯一一条安全规矩（`settings.json` 能手改，而
那个名字会被拼成一条路径）：正常文件名收下、带路径/反斜杠/上级目录的一律拒掉、空名字就是空、
超长的拒掉、缺键 → 没有背景图 + 默认压暗 0.35、压暗越界夹住、值不是数字时不崩、
**文件里手改出来的危险名字读成"没有背景图"**、写出去的时候也过一遍安检、来回一趟不丢键。

`tools/wiring_check.py` 十二句盯接线：布局里那一层（盖在极光之上、面板之下）、挑图那条路
接得上、背景图这条排在别的图前面（它不属于任何角色）、图存在应用自己的目录里、**存之前先
缩小**（先读尺寸再定采样率）、写 `.part` 再改名、换背景不留旧图、没有图就回到自带背景、
文件名一处判断、坏图降级、设置里三个入口、改完立刻生效。

## 每一版的验证记录

按版本写的那 16 段（哪一版加了哪条断言、为什么）搬去了 [`docs/JOURNAL.md`](JOURNAL.md) —— 那是**历史**，这一篇是**参考**：
每个检查各自钉着什么、怎么跑、以及那三笔欠账的来龙去脉。
