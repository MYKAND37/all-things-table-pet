- [x] 应用外壳：侧栏菜单 + 磨砂内容区
- [x] **通用骨骼系统**：正向运动学 + 两段式 IK（拖拽，保持肘部侧）
- [x] **女性素体骨架**：19 根骨骼，按参考图实测（6.12 头身）
- [x] **绘画模板 + 命名规范**（A + C 方案）
- [x] **部件装配**：读 `parts/` 里每个骨骼一张整画布 PNG，挂到骨骼上
- [x] **布娃娃物理**：每个关节独立受力矩，可抓任意部位、整体下垂、可调刚度
- [x] **可自定义碰撞体**：每个骨骼在 character.json 里带 collider（capsule / circle + 半径）
- [x] 菜单分工：**测试场**跑角色，**桌宠管理**编辑角色
- [x] **部位深度**：图层顺序可编辑，换序规则可编辑且真正生效
- [x] **自己搭骨架**：加骨骼（在画布上点两下画出来）、**改父级**、删骨骼、清空重来
- [x] **部位状态**：自己定义开关（穿着 / 受伤…），部位可以只在某个状态打开时才画出来
- [x] **骨骼编辑器**：双指缩放、拖空白处平移、右边一栏点名字放大到那根骨骼
- [x] **整只桌宠可以删**（连同它的图、规则和动作）
- [x] **动作预设**：摆好姿势存成动作（`poses.json`，属于用户不属于角色包）
- [x] **测试场动作列表**：一个按钮打开，每条动作带**骨架缩略图**，可改名 / 删除
- [x] **事件系统**：角色做了什么、被什么碰到，都变成带时间戳的事件
- [x] **数值系统**：H / P 或任何你自己起的名字，由角色包自己定义
- [x] **规则引擎**：当 → 如果 → 就，用户自己搭
- [x] **可视化规则编辑器**：节点图。方框 + 连线 + 单指平移 + 双指缩放，点方块改
- [x] **道具六类**：持续使用 / 装置 / 投掷 / 射击 / **钉子** / **绳子**，带碰撞和推力
- [x] **粒子**：血、汗、火花、灰尘，落地的会留印子
- [x] **液体**：会流、会积成水洼、会绕着身体流；液体本身也可以自己加（颜色 + 黏度 + 液滴大小 + 透明度）
- [x] **部位破坏**：规则可以把某个部位打没（骨头还在，图不画了）
- [x] **道具之间的碰撞**：道具不再互相穿过；被手指按着的那个不让路（`PropWorld.separate`）
- [x] **部件也是主体**：每个部件（`part:hand_L`）自己就是一个主体，规则长在部件上
- [x] **全局状态 / 局部状态**：手有自己的「出汗」，角色有自己的「穿着」，同名也不互相污染
- [x] **每种东西一个文件夹**：道具、液体、部件的规则各归各家，不再挤在一个文件里
- [x] **部位替换**：换一条胳膊是「同一条骨骼 + 两个文件 + 一个状态」，不需要新机制。
      碰撞体跟着**骨骼**走，不跟着图走——换成机械臂，粗细还是原来那条
- [x] **否则**：「当……如果……就……否则」。没有否则的规则保持老行为（条件不成立就整个跳过、连冷却都不消耗）
- [x] **跳到规则**：控制权可以**当场**交给另一条规则。当/部位不检查，目标自己的如果/冷却/一次照算；
      一次事件里每条规则最多开火一次，所以跳转不可能转圈
- [x] **钉子与连绳**：点哪钉哪，点两点连绳；点部位就是把那一节钉住
- [x] **绳子有物理**：画一小段图案，点两个点，生成一条会垂会拉的 Verlet 链条（长度与弹性可调）
- [x] **骨骼节点**：一根骨头上叫得出名字的点（指尖、肩膀）。判定 / 抓取 / 系绳 / 钉钉 / 独立隐藏 / 装道具全认它
- [x] **画板**：粒子图案、拖尾、绳子图案都由用户自己画（128×128，一笔一撤销）
- [x] **拖尾**：持续使用类道具拖过的地方留下一笔；按**距离**留印子，不按帧
- [x] **变身**：规则能把角色**整套**换成另一个（骨架 + 图画 + 它自己的逻辑）
- [x] **多套骨骼**：一只桌宠可以有几副身体，各自的骨架、部位图和动作；规则里用「换骨骼套」切，
      换的是**样子**不是**这一只**（数值、状态、规则、粒子、液体全都留着）
- [x] **调骨骼时有参考图**：拼起来的整只（可以把某个**状态**打开，画在它后面的图就出来了），
      或者从手机里放一张图在画布下面照着描
- [x] **新建 / 复制桌宠**：从出厂素体新建一只，或者把一只整个复制一份（图、骨骼套、规则、
      粒子、液体、动作全都一起）
- [x] **桌宠包**：一只桌宠导出成**一个文件**（`.atppet`），导入回来是一只新桌宠；
      导入**永远不覆盖**，重名自动加号
- [x] **「保存骨骼」不再让图层平方**（1.14.1）：一根骨头有几层就写几层；被旧版本写坏的
      文件，存一次就折叠回正常
- [x] **重置骨骼**：调骨骼那一页的回头路 —— 丢掉没保存的改动 / 骨架恢复成出厂素体 /

- [x] **场上放哪一只**：测试场顶上那一排的**第一个**就是它（每只一个方块，当前那只亮着、
      还写着它正在用的身体）；桌宠管理的每张卡上也有「放到场上」
- [x] **侦测器能问世界**：「手比肩膀高」（两节比位置，带像素余量）、「被绳子连着」（哪一节、
      连着还是没连着）—— 引擎问，测试场答
- [x] **改变部位深度**：规则能把一节**拉到最前面 / 压到最后面**。动的是一次会话里怎么画，
      不写文件
- [x] **状态图可以叠加**（1.21.0）：一根骨头的状态图不再只有"替换"——现在能选**叠加**
      （绷带、伤口、汗、配件：两张都画，上面那张透明的地方透出下面那张），而且已经做好的图
      能一键在两种关系之间反悔。新层也改成贴着它那张图（`baseZ + 1`），不再压在所有东西上面
- [x] **调骨骼碰撞时看得见范围**（1.21.0）：属性弹窗打开时，那一节的碰撞体（胶囊/圆）在画布上
      亮着画，旁边写着半径；还能一键看全部（对位用）。半径和形状**和求解器共用同一个函数**，
      所以画出来的就是道具真正撞上的那个
- [x] **独立的动画管理**（1.21.0）：侧栏新的一页 —— 一只桌宠的动画都在那里（新建 / 改帧 /
      速度 / 循环 / 试播），编辑器和测试场那张表共用，播放仍然只在测试场看得见
- [x] **动画工作台：右边就是角色**（1.22.0）：动画管理不再只有一列列表 —— 左边是这一段和它的
      关键帧（＋ 帧 / 存入这一帧 / 时长 ±0.1s / 删帧），右边是**这只桌宠本人**，直接拖关节摆
      姿势。选中一帧摆的就是**播放时那一刻的样子**（`Anim.framePose` = 采样在帧起点的结果，
      不是"帧里写了什么"——两者在"下一帧才写的骨头"上不一样）；改完按「存入这一帧」写回，
      写的是整只的姿势
- [x] **一帧可以同时开好几套图**（1.22.0）：帧里的开关从"一个名字"变成"一串"（`+` 连接），
      所以"这一帧左手出汗 + 换机械臂"能一次说清。分隔符进不了状态 id（`RigEdit.sanitise` 把
      `+` 换成 `_`），歧义在造名字那一步就被掐掉；测试场那边也拆开写进画图表
- [x] **视角能动**（1.22.0）：双指**转**（原来只有缩放）、单指拖动平移、「转 90°」和「摆正视角」
      两个按钮；转的是**视图**不是角色（骨架/图/参考图一起转，摆出来的角度一点没变）——
      斜着画的身体，手是顺着画走的。旋转绕视图中心，和缩放、平移共用同一个反变换
- [x] **骨骼这一层能关**（1.22.0）：动画预览要的是"它看起来什么样"，所以「骨骼」一按只剩下
      角色本人（和桌面上那只看到的是同一张图）；「改骨骼 / 存骨骼」让它在这页里也能把骨架对
      到画上 —— 写回的是**正在看的这一只**（`summoned ?: opened`），不是"打开的那一只"
- [x] **动画在这一页也能播**（1.22.0）：从**选中的那一帧**开始演，播到哪一帧横带上就亮哪一格，
      图在帧边界换；碰一下画布就停下来（停下来才能改），「停止」回到你在编的那一帧
- [x] **关键帧时间轴编辑器**（1.23.0）：动画页下半屏是一条时间轴 —— 标尺 + **可拖的播放头**，
      一行一根骨头，菱形就是关键帧，**横向拖改时间、纵向拖改值**；左边点名字选中那一节，
      「＋关键帧」把**这一刻、这一节的当前值**记下来，图那一行显示每帧多久、画的哪套图。
      和 Blockbench 一样：编辑的关键帧只是通道上的点，帧（图）仍然是时间轴的刻度
- [x] **每根骨头三条通道**（1.23.0）：旋转 / 位置 X、Y / 缩放，各打各的关键帧，互不影响。
      **旋转**照旧是交给求解器的目标（物理仍是主语）；**位置与缩放只改画面** —— 一节骨头
      "平移"到别处在物理上没有意义（等于瞬移一节骨头、碰撞体重叠、绳子长度全乱），所以它们
      画在求解器算完的姿势之上，`Ragdoll.kt` 里一个字都没有
- [x] **关键帧之间自动插值**（1.23.0）：默认**平滑**（smoothstep，两头慢中间快 —— 放在
      有物理的宠物身上才像"它在动"），每段可以选匀速或**阶跃**（逐帧动画的老规矩）；
      缓动挂在"段"的起点上，因为走进一个关键帧和走出它是两段
- [x] **「转成时间轴」逐点无损**（1.23.0）：把现在这几帧烘成每根骨头的通道，`timeline_check`
      拿 60 段随机动画 × 41 个时刻逐点比过（最大差 0.000000）。要精确就得照着帧模型真正的
      三条规矩来（两侧都写了是斜坡、只写一侧是保持、两侧都没写等于回站姿）—— 第一版漏了
      第三条，烘完差了 168 度
- [x] **帧与通道是同一个时间轴的两半**（1.23.0）：插一帧、删一帧、改一帧的时长，后面的
      关键帧跟着挪；「存入这一帧」同时给有通道的骨头在那一刻打一个关键帧 —— 不这么做，
      "存了这一帧、播出来却是通道的老值"会让人以为存没生效
- [x] **姿态锚点**（1.24.0）：时间轴多了一行「姿」—— 一帧一个**小方块**，位置是它开始的那一刻
      （下面「图」那一行画的是**时长**，块有多宽 = 这一帧走多久；两件事都看得见）。方块实心
      = 这一帧存了一整套姿势，右上角一个小点 = 这一帧**绑了规则**
- [x] **＋锚点落在播放头那一刻**（1.24.0）：播放头在帧开头 → 插在它后面（连按几下就是一串
      锚点）；播放头在一帧**中间** → 把那一帧在播放头处**断开**，新的锚点拿走后半段的时长
      —— 总时长一点没变，所以那种情况下一个关键帧都不用挪
- [x] **锚点可以绑一条规则，播到就响**（1.24.0）：引擎多了一个入口 `RuleEngine.runRule(第几条)`，
      触发只免掉「当」（播放头走到那一刻，触发已经发生了），**如果 / 冷却 / 只一次一个字都不
      放宽** —— 走的是同一个 `fire()`，所以"按 id 跑"和"事件触发"不可能长出两套语义。
      一遍响一次（`Timeline.passIndex`）：循环的动画每绕一圈再响一次，停在同一格不会每帧都响。
      绑的是**第几条**（和「跳到规则」同一个身份，不另造一套 id；代价也一样：改了规则顺序
      绑的号会跟着变，界面上写明了）。只在**测试场和桌面**上播的时候才响 —— 编辑这一页没有
      世界可跑，这一条写在界面上
- [x] **点小方块 = 跳播放头 + 载入那一套姿势**（1.24.0）：和点「图」那一块是同一个动作，
      但状态栏说的是锚点的话（第几秒、几节骨头、哪套图、绑的是哪条规则）
- [x] **「转 90°」闪退修掉了**（1.22.1）：真因不是那个按钮，是**画布旋转那一段绘制漏了
      `canvas.save()`** —— 旋转会漏给父控件，而配对的 `restore()` 会去弹别人的存档，
      Android 在 restore 弹空时直接抛（`Underflow in restore`）。双指旋转走的是同一段
      代码，所以两指一转同样会闪。补上 save 之后，按用户要求把那个按钮摘掉了（旋转留给
      双指手势）；`kotlin_check` 第十条从此盯着「restore 不许比 save 多」和「有画布变换的
      函数里必须有 save」
- [x] **免责声明确认门**（1.20.1）：第一次打开先把免责声明摆出来 —— 同意才继续，不同意就
      退出（返回键也关不掉）；**同意之前应用什么都不做**（连出厂角色都不铺）；记住的是
      **版本号**，文案改了会再问一次；设置里能重新阅读
- [x] **应用背景图（主题）**（1.20.0）：全局设置里挑一张手机里的图当应用背景。图会被
      **缩小到长边 1600** 再存进应用自己的目录（不碰外部存储、不需要权限），面板半透明地透出
      它；「浓淡」四档压暗保证字看得清；去掉就回到自带背景。名字只收纯文件名（`settings.json`
      能手改，而它会被拼成路径 —— 这是这一版唯一一条**安全**规矩，`settings_check.py` 十条断言）
- [x] **英文（功能词那一半）**（1.19.0）：508 条短标签 + 引擎词汇（当/如果/就、14 事件、
      28 动作、6 道具类型）+ 19 根骨头 + 四档刚度住进 `values-en/`，跟系统语言走；引擎只留 id，
      给人看的字搬进资源（`ui/Labels.kt`）；`tools/english_check.py` 把"还剩多少"变成一个数字
- [x] **两级状态看得见，也走得过去**（1.18.0）：状态弹窗的标题写明是**谁的**状态、说明分

      几个状态。机制没动（它一直是对的），动的是"你现在看的这一份是谁的"
- [x] **动画的入口看得见**（1.17.1）：测试场那个按钮和列表标题都数上动画（原来只数动作，
      一个只做了动画的桌宠写着「动作 (0)」，入口等于藏起来了）；场上没有桌宠时会说一句
- [x] **动画**（1.17.0）：一帧 = 可选姿势 + 可选开关 + 秒数，所以**演算动画**（两帧之间
      插值，物理仍是主语）、**绘制动画**（每帧一套图）和**半演算**是同一个模型；整套一个

- [x] **执行器之间能插计时器**（1.16.0）：**就 / 否则 / 每个并行分支**的每个空档（含第一个

- [x] **桌面穿透真的点得穿了**（1.16.0）：Android 12 起，从不透明的悬浮窗穿过去的触摸会被

- [x] **部件也能测全局的状态**（1.15.1）：引擎留住自己文件里声明的开关，别的名字问世界 ——

- [x] **零重力**：重力那一排最前面一档是 0
- [x] **悬浮桌宠是全屏的**：整块屏幕都是它的地盘，另有一条「可摸 / 穿透」的小控制条

## 关于英文（1.19.0）

**范围是"应用自己的功能"，不是整个应用。** 这个应用是给人**自己打包**用的 —— 角色美术、规则、
出厂角色里那几句话都是用户的东西，所以：

| 翻了 | 没翻（有意） |
|---|---|
| **控件**：按钮、标题、选择器、开关（508 条短标签） | **长提示语** 125 条：解释某个功能为什么这样的那种段落 |
| **引擎词汇**：当 / 如果 / 就、14 种事件、28 种动作、6 种道具类型 | **出厂内容**：默认角色那几条规则（「别弄脏衣服！」）、液体和粒子的名字 |
| **骨头名**（胯/腰/胸…）、四档刚度、单位与数字 | **界面里拼在行里的短句** 87+42+41+5+4 = 179 处（「未导入」「 · 播放中」）—— 它们要先一条条搬进资源，是下一批 |
| **调试读数**（引擎日志、`GameEvent.describe`）也是有意不翻的 | |

英文住在 `res/values-en/strings.xml`，跟系统语言走（手机是英文就显示英文，其余回落中文）。
**功能词那一半是翻完了的**：14 种事件、28 种动作、19 根骨头、四档刚度、全部控件文案 —— 一个
英文用户打开它，每一排按钮、每一个选择器、规则编辑器里的每一个词都是英文。

**引擎里的中文为什么还在**：那些字（`EventType.label`、`ActionKind.label`、骨头表）原来写在
引擎的枚举里，而引擎是故意不依赖 Android 的 —— 那是它能在本地被完整镜像测试的原因，也让
它里面的字**永远不可能有第二种语言**。所以这一版分成两半：引擎只留 id，给人看的字住进资源，
两边靠 id 对上（`ui/Labels.kt`）。引擎那份中文留着当兜底，因为日志和 `describe` 还在用它。

**"还剩多少没翻"是一个数字，不是一种感觉**：`tools/english_check.py` 每跑一次都打印
「508/633 条有英文」和还差多少条；`kotlin_check.py` 打印界面里还剩多少处硬写的中文。两个
数字都在往 0 走，而它们红不红取决于**键对不对得上、占位符丢没丢** —— 那两件事才是会炸的。
