# 骨架与角色

> 搭骨架、节点、属性、多套骨骼、桌宠包、动作预设。
>
> 这一篇原来在 README 里，2026-09-24 拆出来。README 是门面，这里是细节。

## 关于一个部位的属性

「骨骼列表」里每根骨骼多了一个 **属性**：

- **刚度 ×**：这个关节自己的弹簧，**乘在全局刚度上**。0 = 完全松垮（不管测试场那个滑杆），
  1 = 跟别的关节一样，2 = 硬一倍。全局那个"松垮/僵硬"还在，没删——两个一起用才是"整只软、
  但这条胳膊硬"。（这个字段其实一直写在文件里，只是**从来没有人读**：求解器只认全局那个。
  1.10.0 起它真的接上了，默认值也从那个没人读的 0.35 改成了 1.0。
  **1.11.13 补的是第三处**：`saveRig` 从来没把它写回去 —— 编辑器有、求解器读、保存漏了，
  症状正是"这个滑杆没用"，而且一声不响。现在不是 1.0 才写进 `physics.stiffness`，
  回到 1.0 就把键拿掉（"不在"本来就等于 1.0，不该让十九根骨骼第一次保存就全长出 physics 对象）。）
- **旋转范围**（最小 / 最大角度，度）。这是手感来的地方：膝盖能弯多少、
  肩膀能转到哪儿，全都写在这两个数里，而它们原本是照着参考图量完就再也没看过的。
  一个能转 170 度的肩和一个能转 90 度的肩是两种动物，而想知道自己要哪一种，
  唯一的办法是拽着胳膊看它停在哪。
- **碰撞体**：沿骨骼的胶囊，或者中点的圆，加上半径。
  地板、道具、液体看见的就是这个形状 ——
  "为什么它浮在地面上方"和"为什么它陷进桌子里"都是从这里来的。
- **质量不在这里**，因为质量是按碰撞体的面积算出来的：粗的肢体就是重的肢体，
  另外再给一个重量等于同一件事给两个答案。
- **两个开关**（默认都开着）：
  - **参与碰撞** 关掉 → **地板、道具和液体都感觉不到它**。它照样跟着动、照样有重量、
    照样参与摆动，只是世界当它不存在。发带不该把桌子推走，就用这个。
  - **能被拖动** 关掉 → **手指直接穿过去**。为规则而存在的骨骼（"让手流汗"挂的那个点）用它。
  两个是分开的：不能碰的东西仍然可以抓，能碰的东西也可以规定"不许抓"。

**范围不用敲数字了（1.9.2）。** 「摆姿势」那一档本来就能拖关节，所以摆出你想要的角度之后，
工具栏上多出来的两个按钮把它记下来：

    摆姿势 ──拖关节，把胳膊/膝盖甩到你希望它停下的地方──▶「设为最小」或「设为最大」

「设为最小」只动最小那一头，最大那头留在文件里；如果这么一设反而让范围倒过来
（新的最小比原来的最大还大），两个数会互换——这和属性框里"把范围敲反了"是同一条规则，
两边现在共用 `RigEdit.limits`，所以不会各说各话。

**选中一根骨骼，画布上会把它的范围画出来**：关节处一个半透明的扇形，两条边就是能转到
哪儿的两头，骨头本身画在扇形里面——所以"能转到哪"和"现在在哪"是同一眼看到的。
扇形是以**静止方向**为中心的（`minAngle`/`maxAngle` 本来就是相对静止姿态的偏移），
所以摆姿势的时候扇形不动、骨头在里面动，这正是要看的东西。

默认那套骨架里，**胯是 ±360°**（整个自由转动），所以整只宠物可以翻过来倒立；别的关节各自带着
一个量过的范围（膝盖 -150~0、手 ±70、头 ±50……）。

改完点保存会直接写回 `character.json`，回测试场就能感觉到。
（这两个开关**每次都写**，不是只在新骨骼上写 —— 不写的开关就是"下次保存时自己翻回去"的开关，
而那是 `tools/store_check.py` 专门盯的一类 bug。物理那半边有 `tools/ragdoll.py` 的第 4b 组：
关掉一只脚的碰撞，那只脚穿过地面线 49px，而**其余仍然实心的部位照旧站在地面上**。）

## 关于自己搭骨架

**改骨骼**模式下，底部多了 **＋加骨骼** 和 **骨骼列表**：

- **加骨骼**：输入名字（默认 `bone_1`），点一个父级，然后**在画布上点两下** ——
  第一下是关节，第二下是末端。骨骼是画里的东西，唯一诚实的说法方式就是指着画说。
- **骨骼列表**：每根骨骼一行，**按层级缩进**，每行带「改父级」和「删除」。
  列表里还有「清空（只留根）」，这是从零搭一副骨架的起点。
- **双指缩放、拖空白处平移**，右边一栏是骨骼列表，**点名字就放大到那根骨骼** ——
  十九根骨骼里找一只手，在手机上戳图是猜谜，点名字不是。
- **改父级**：**骨骼不会移动**。头尾存的是画布坐标，父子相对关系是烘焙时才推出来的，
  所以换父级换的是"跟着谁动"，不是"在哪里"。
- 骨骼名同时是**文件名**：`parts/<名字>.png`。所以名字里的空格和
  `/ \ : * ? " < > |` 会被换成下划线 —— 名字是骨架和画之间的约定。

三条规矩，编辑器当场拦下来，不会等到烘焙时才炸：

| 规矩 | 为什么 |
|---|---|
| **只有一根根骨骼** | 出现第二根时 `buildSkeleton` 只认最后一根，另一棵树会**整棵消失** |
| **不能接到自己的下级上** | 成环。列表里那些自己的下级是**灰的**，点了会告诉你原因 |
| **根骨骼不能删** | 它的子骨骼会没有归属（要重来用「清空」） |

### 「保存骨骼」为什么会让宠物越来越卡（1.14.1 修）

**每按一次「保存骨骼」，图层就会平方一次。** 一根骨头有两层（比如它有一个状态图），存一次
变四层，再存变十六层 —— 你报的「保存两次就开始掉帧」就是它：文件里堆着几百层，渲染器每帧
老老实实画几百遍。

原因在一处接口误解上：编辑器的 `rigLayers()` 交出来的是**每层一个骨头名**（一根骨头有两层
就出现两次），而 `saveRig` 拿到那张表之后的意思是「现在把这个骨头的层写出来」—— 每出现一次
就把那个骨头的**所有**层再写一遍。修法是两层：

- **顺序先按骨头去重**（`distinct()`）：不管调用方给什么，一根骨头的层只写一次；
- **一模一样的重复层折叠成一层**（同一根骨头、同一张图、同一个状态）：这是**修老文件**的
  那一半 —— 已经存坏的文件里堆着 2/4/16 份重复，存一次就收回一层。它们画的是同一个东西，
  留第一层就是它们全部的意思。

**你的宠物现在可能是坏的：打开骨架页按一次「保存骨骼」就修好了**（保存会折叠重复层，
图层表回到正常条数，帧率跟着回来）。

（镜像 `tools/store_check.py` 里有这个 bug 的回归测试：一根骨头两层的骨架存三次，
层数必须一直是 20，而且两次保存出来的文件必须完全一样。**这个测试是用真 bug 反过来验过的**：
把去重那一行拿掉，它立刻报 `[22, 26, 34]` —— 一路涨。）

**删除只在「保存骨骼」时才落盘。** 在那之前"删除"只是一个意图，
中途走掉不保存，你的图还在。

### 调骨骼时看什么：参考图

改骨骼的时候，画布上**本来就该看得见这只桌宠的样子**（拼起来的那一整只画在骨架下面）。它不
见了有两个原因，一个是 bug，一个是缺功能：

- **bug：被状态挡住的图在这儿一直没画过。** 一层图只有它的状态开着才画（`LayerSpec.visible`），
  而这一页从来没有人给它状态表 —— 于是画在「穿着」「机械」后面的图在测试场里看得见，
  在调骨骼的这一页看不见。现在骨架页底栏的 **参考图** 里有这一只的每一个状态（它自己的，
  加上每个部件自己的），点一下打开就好；
- **缺功能：还没导入的图，任何开关都变不出来。** 所以**从手机里选一张图**也能放进来：
  它存在这一套骨骼里（`rigs/<套名>/reference.png`，默认那套是 `characters/<桌宠>/reference.png`），
  画在**最下面**，骨架和拼起来的那只都在它上面。**按比例放得下**（不变形：导出的图是
  1024×2048 的话正好铺满画布），浓淡三档（淡 / 中 / 浓），随时可以去掉。

参考图**不放在 `parts/` 里**：那是"每根骨头一张图"的地方，一张 `reference.png` 摆在那儿
既会被当成某根骨头的画，也会在测试场上被一起画出来。

（`tools/wiring_check.py` 盯着这两半：编辑器必须把状态表交给渲染器，上传的图必须真的
`drawBitmap`。两句话都是"功能看起来在、其实没接上"那种错的机器版本。）

### 骨骼节点：一根骨头上叫得出名字的点

部位是一整根骨头，所以「指尖」「肩膀」这种地方以前没法说 —— 规则能写「手」，不能写「手上
那个点」。**节点**就是那个点：没有长度、没有关节、自己什么都不用解算，它只是一个**名字**。
入口是骨架页底栏的 **＋加节点**（和 ＋加骨骼 并排）：点它，然后**在画布上点骨头上的位置**
—— 落点会投影到**最近的骨骼**上（点在细骨头旁边也算点到它，和这个应用里手指的其他地方
一样宽容），偏移量就是那个落点沿骨头的位置。

- **判定**：道具碰到节点走和骨头**完全同一套**接触（同一个重叠、同一个回弹、同一个 0.25 秒
  节流、同一个冲量），只是事件里的名字是节点而不是骨头 —— 规则问的是"谁被碰到了"，而
  「指尖」比「整只手」是更好的答案。冲量照旧落在骨头上，因为推的是身体；
- **被点一下**：手指按在节点上时，抓的是**节点的偏移**而不是手指投影到的地方；
- **系绳 / 钉钉**：绳子的一端、钉子的落点本来就是一个"骨头上的偏移"，节点只是给它起了名字；
- **隐藏 / 显示**：规则里两种名字都收，节点走自己的一套（它没有图画）；
- **装道具**：节点可以带一个道具，道具每帧跟着那个点走，而且永远是 planted —— 世界不动它、
  手指拿不走、身体感觉不到它（一把每帧推自己手的剑是拿不住的），但它照样把别的道具推开，
  所以挥起来是有用的。隐藏节点就是把东西摘下来。

节点位置存的是**沿骨头的距离**：骨头以后被改长改短，末端节点跟着走，而不是留在半空。
三条约束（`RigEdit.nodeProblem`，编辑器、保存、镜像共用一份）：节点名不能和骨骼重名
（两者都是规则里的名字）、半径不能是 0、挂的骨头必须存在。删骨骼会连同它的节点一起删，
骨头改名时节点跟着改。

**每一次改动立刻写盘**，这一条是踩出来的：节点以前只改在编辑器内存里，而保存按钮在**另一页**，
所以加完看着成功、列表里也有，但沙盒读的是硬盘上的文件 —— 节点根本不存在。用户在哪儿改，
就在哪儿算数，和逻辑面板一个规矩。

#### 节点也是主语（1.15.1 修）

面板把**骨头和节点列在同一张部位表**里（写着「骨骼节点 · 指尖」），所以一条规则的主语可以是
一个节点。但"名字 → 位置"那条路以前走的是 `Skeleton.find`，而**它只认骨头**：节点名在那儿
得到 null，然后每个调用方掉进自己的兜底 —— 而兜底都是"宠物附近"或者"整只宠物"。1.15.1 把它
收成两个入口（`Skeleton.place` 给位置、`Skeleton.boneFor` 给"哪一节"），凡是把名字变成地方
或骨头的地方都走它们：

| 你写的 | 以前 | 现在 |
|---|---|---|
| 一条长在**指尖**上的规则「喷火花 / 喷液体」（含持续喷、流液体） | 落在**宠物家位上方 400px** 的空中 | 落在那个点上 |
| 「被点一下 · 指尖」触发的喷溅 | 同上 | 落在指尖 |
| 说话气泡跟着一个节点主语 | 气泡在宠物头上 | 在节点上 |
| 「推一下 · 指尖」 | 推的是**整只宠物**（`?: sk.root`） | 推它长在的那一节 |
| 「断开 · 指尖」 | 什么都不发生 | 把手拆下来 |
| 如果「**指尖**比肩膀高」 | 永远不成立（问世界得到 null） | 照常比较 |

节点是"一个点"，所以「断开」这种要**一块**的动作按它长在的那一节算；而「隐藏 / 显示」本来
就分两套（节点没有图画），没有变。

## 关于变身

「就」里有一个动作叫**变身**：**整套**换成另一个角色 —— 骨架、图画、道具和那个角色自己的
逻辑，一起换。这是「换骨骼」必然的样子：没有图画的骨头是看不见的，所以换骨骼一定连图画
一起换。

- 由**宿主动手**：角色是文件夹、图画和几个文件，只有 Activity 知道它们在哪儿，测试场只说
  "变成这个"。目标写在动作的 `text` 里，是一个角色的 id；
- 找不到那个角色、或者文件读不出来，就**不换**（找不到时弹一句，文件坏了时退回原来那个）：
  变身成一个空测试场，比这条规则什么都不做更糟；
- **变成自己不算变身**：那只是把世界清空一次，看起来像惩罚；
- 两个保护，都不是类型错、编译器一句话都不会说：**速度上限 0.5 秒**（"A 出现时变 B、
  B 出现时变 A"是两行就能写出来的东西，没有上限它就是每帧重新装载一次），以及**延到下一帧
  做**（动作表在帧中间跑，在中间换掉整个世界，会让这一帧剩下的部分跑在一个已经被换掉的
  世界上面，所以动作只记账，帧首才动手）；
- 已知行为：变身会把桌子也重新摆一次（道具、液体、粒子都清掉，新角色从家位开始）——
  换的是整套，包括地面高度，所以这是有意为之而不是漏了。

## 关于多套骨骼：一只桌宠，几副身体

同一只桌宠可以有几套骨骼 —— 一套「平常的样子」，一套「机械形态」，各自有自己的骨架、自己的
部位图、自己的动作。桌宠管理里点进一只，**名字下面那一行**就是它的骨骼套：默认那套 + 每一套
一个方块，最后是「＋」。

```
characters/<桌宠>/
  character.json  parts/  poses.json     ← 默认那一套（就是包裹本身，老文件零迁移）
  rigs/<套名>/
    character.json  parts/  poses.json   ← 另一副身体：骨架、图、动作都是它自己的
  logic.json  particles/  liquids/       ← 这一只的规则、粒子、液体（不跟着骨骼走）
```

- **换的是样子，不是这一只**。规则动作里有一个**「换骨骼套」**（选哪一套，空 = 默认那套）：
  切过去的时候**数值（H/P）、状态开关、规则、粒子、液体、桌子上的道具全都不动** ——
  「肚子痛到一半变成机械形态还是痛」就是这句话。这和**变身**是两件事：变身换的是**谁**
  （另一只桌宠，它自己的规则和数值，世界整个重新装载），换骨骼套换的是**长什么样**；
- **换完发一个事件**「换了骨骼套」，所以「变成机械形态 → 说一句话」是两条规则，而不是一段
  藏起来的代码；
- **它也有速度上限**（0.5 秒）和**延到帧首执行**：一套「换了这套 → 再换回去」的规则是两行
  就能写出来的东西，而没有上限它就是每帧重建一次身体；
- **身体换掉时松手的东西**：手里抓的、钉在身上的、系在骨头上的绳、被扯断掉在地上的那一块、
  正在喷粒子的发射点 —— 它们说的都是**旧骨架的骨头名字**，新骨架里没有这些名字。所以它们
  留在地上/消失，而不是挂到一个碰巧同名的骨头上（那看起来像隔空取物）。**藏起来的部位跟着
  人走**：那是一个开关，不是旧身体的几何；
- **桌子跟着骨骼套，只在屋子真的不一样时才动**：两套骨骼通常共用一间屋子（屋子是这只桌宠
  的），这时桌子、道具、水、火花一点都不动。新那套如果写了不同的地面/墙，世界会重建，**散着
  的道具会跟着搬过去，水不会**（它的每一滴都在旧屋子的坐标里）；
- 新建一套时可以选择「**复制当前这套**（骨架 + 部位图）」或者「**只复制骨架**」（图自己再画）；
  **长按**一套可以重命名或删掉它。**默认那一套不能删也不能改名** —— 它就是包裹本身，
  全世界的存档都在那儿；
- 动作（pose）**跟着骨骼套走**：一个动作是一堆骨头角度，骨头名字换了它就没有意义。默认那套
  的 `poses.json` 还在老地方，所以谁的动作都不会搬。

## 关于桌宠包：把一只桌宠带走

一只桌宠本来就是一个文件夹，所以「导出」不是一种新格式 —— 就是把那个文件夹写成**一个文件**：

- 桌宠管理 → 某一只那一行的 **导出** → 系统「另存为」 → `名字.atppet`（就是一个 zip）；
- 列表顶上的 **导入桌宠包…** → 选一个 `.atppet` → 它变成**一只新的桌宠**，用包里写的名字。

包里装的是**整个文件夹**：骨架、部位图、别的骨骼套、动作、规则、粒子、液体、参考图。
少装一样的包，装回去就是一只你不认识的宠物。

**导入永远不覆盖**：包里叫「小白」而你这里已经有一只「小白」，新的那只就叫「小白2」——
两个人给自己的宠物起同一个名字，不是弄丢一只的理由。

**一个来自外面的 zip 就是一个来自外面的文件**，读的那一侧按这个对待
（`data/PetPackage.kt`）：

| 规矩 | 为什么 |
|---|---|
| 条目名里有 `..`、以 `/` 开头、带盘符、带 NUL、超长 → **那一条丢掉** | zip 是一串路径，而恶意的那一串里一半的条目是「出去的路」 |
| 条目数 > 4000，或者解出来的总量 > 512MB → **整包拒掉** | zip 炸弹寄出去很小 |
| 没有 `pack.json`、格式号不对、`kind` 不对 → 拒掉 | 选错文件是最普通的错，答案要和「这不是包」一样 |
| 没有 `character.json` → 拒掉，并把解出来的东西删干净 | 列表里半只宠物，比一个没导进来的包更糟 |
| 包里的文件都套在一个文件夹里 → 认出来，把那一层剥掉 | 别人解压看一眼再压缩回去，是他的权利 |

（`tools/package_check.py` 是这一节的镜像：哪些路径会被拒、重名怎么办、套了一层还认不认。
它当场抓到过一个真 bug —— 第一版只剥**第一段**路径，于是「解压再压缩」过的包会被判成
「里面没有桌宠」。）

## 新建、复制、重置

- **＋新建桌宠**：列表顶上，从**出厂素体**复制一只（19 根骨骼那副，带占位图）；
- **复制**：某一行的按钮，把**整个文件夹**再写一份 —— 图、骨骼套、动作、规则、粒子、液体
  全都一起，所以「在原版上试一个想法」碰不到原版；
- **重置骨骼**（调骨骼那一页底栏）：改骨骼是**直接改骨架**的（拖动关节就是改坐标），而回头路
  原先只有「清空」和「删掉整只桌宠」—— 后者会连图、规则、粒子一起丢。现在一个入口三个答案：

| 选项 | 做什么 |
|---|---|
| **回到上次保存的样子** | 丢掉编辑器里还没保存的改动（拖过的关节、加过删过的骨骼）。文件是唯一的真相 |
| **骨架恢复成出厂素体** | 骨骼、层级、图层、IK、物理参数回到内置那副 19 根的素体；**这一套的部位图、动作、规则、粒子和别的骨骼套都不动**（同名的骨头照样认自己的图） |
| **清空重来（只留根）** | 骨骼列表里那件事，放到这里，好让「从头开始」只有一个地方 |

新建、复制、重置都不需要新机制：它们都是**文件夹操作**，所以没有新的存档格式、也没有新的
运行时概念 —— 校验的重点因此不在功能而在边界（重名、坏包、名字里的斜杠）。

### 场上放哪一只

「测试场」顶上那一排的**第一个**就是它：每只桌宠一个方块，当前那只亮着，名字后面写着它正在用的
**身体**（骨骼套）；最后一个「＋」直接去桌宠管理。桌宠管理里每只一张卡上也有 **放到场上**，
当前那只写「✓ 场上」。

两处走同一个函数（`summon`），因为"挑一只上场"只该有一件事发生：换骨架、图画、规则、粒子和
液体。**再点一次当前这只**不会把身体重置成默认那套 —— 它只是把测试场重新读一遍。

**挑宠物是用户的事**：复制一只、导入一个包、改完名字之后，刷新列表会**留住场上那一只**
（连同它正在穿的那套骨骼），而不是跳回列表里的第一只。原来就是跳的，症状是「我刚复制了一只，
桌上的宠物变成了别人」。

## 关于动作

动作（pose preset）存在角色目录**旁边**的 `poses.json` 里，不在 `character.json` 里——
角色包是"素材"，动作是"你的用法"，两者升级互不覆盖。测试场顶部那个 **动作** 按钮打开列表：

- 每条动作左边是**骨架缩略图**。名字三个月后就没意义了，形状不会。
  缩略图只读 spec 画骨架，**不加载部件图片**，所以列表是秒开的。
- 点一条＝角色做这个动作，然后**列表自动关掉**，好让你看。
- 改名 / 删除都在列表里。存动作在**桌宠管理 → 摆姿势 → 存为动作**。

选动作时角色会被**放回原位站好**：不然一只被扔到角落躺着的桌宠，
做的动作就是躺在地上摆造型，什么也看不见。

## 一个只有真机上才会出现的 bug

修好"提脚倒吊"那一版之后，测试场里**什么都没有了** —— 只剩 HUD 和状态条。

原因不在物理，在**读文件**：

    val air = phys?.optDouble("roomAir")?.toFloat() ?: derived()

org.json 的**单参数** `optDouble(name)` 在键不存在时返回的是 **NaN，而不是 null**，
而 NaN 不是 null —— 所以 `?:` 根本不会触发。于是 `air` 是 NaN，地面是 NaN，
每根骨骼的位置是 NaN，视图变换也是 NaN：**画在"不是数字"的坐标上，就等于没画**。
HUD 和状态条是屏幕坐标，不受影响，所以看起来是"别的都在，就是宠物不在"。

Python 那套镜像永远抓不到这个 —— 它们测的是算法，而这是 Kotlin API 的坑。
所以多了 `tools/kotlin_check.py`，三条检查里第一条就是它：

    .opt(Double|Int|Long)(k) ... ?:      ← 一个参数 + elvis，就是 NaN 陷阱

带自测（`--self-test`），而且**验证过它真的能抓到这个 bug**：把那一行改回去，它报错；
改回来，它过。另外两条是括号平衡（省一次五分钟的 CI 往返）和 R.* 引用是否存在。
