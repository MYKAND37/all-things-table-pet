# 部件作为主体，以及状态的两级

**这一篇是设计，不是现状。** 现状见 `README.md`；这一篇是下一步要写的东西，
先把决定写下来，免得写到一半又改主意。

## 要解决的三件事

1. **「让角色的手流汗」现在只能写在角色自己身上** —— 一条"每次判定都问是不是手"的规则。
   部件应该能自己当**主体**，规则长在部件上。
2. **状态现在全是角色的。** 手需要有自己的"出汗"，角色有自己的"穿着"，两者不该互相污染，
   也就是**全局状态**和**局部状态**。
3. **每种能装逻辑的东西该有自己的文件夹**，而不是道具和液体的规则挤在一个
   `props/object-logic.json` 里。

## 主体

| 主体 | 现在 | 说明 |
|---|---|---|
| `pet` | 有 | 角色自己 |
| `prop:<id>` | 有 | 一个道具 |
| `liquid:<id>` | 有 | 一种液体 |
| `part:<bone>` | **要加** | 一个部件 |

`Subjects.part(bone) = "part:" + bone`，反过来是 `Subjects.partId(subject)`。
部件主体只对**角色身上的骨骼**存在：部件不属于道具，道具也没有骨架。

### 事件怎么走

一个部件的引擎听到的是：

- `part` 等于自己那根骨骼的事件（沿用规则里那套前缀匹配，所以 `hand` 这条规则也收 `hand_L`）；
- `part` 为空的**整体事件**（被扔出去、落地、被点）—— 手也应该知道"整个人被扔了"。

角色引擎照旧听到**全部**，所以"手流汗"和角色自己的规则不会互相抢：
同一条事件同时喂给角色和每个部位的引擎，各自判断。这条和道具/液体现在的做法一致
（`stepObjects` 里那一套），所以引擎本身不用改，只是主体多了一种。

## 状态的两级

`StateSpec` 加一个字段：

```kotlin
data class StateSpec(
    val id: String,
    val name: String,
    val initial: Boolean = false,
    /** 空 = 全局状态（角色的）；非空 = 只属于这根骨骼的局部状态。 */
    val part: String = "",
)
```

**状态声明在角色自己的 `logic.json` 里**（和液体一样：液体也是角色声明的），
`part` 说的是"这一条属于谁"。于是：

- **一个引擎只装自己那一级的状态**：角色引擎装 `part == ""` 的，部件引擎装
  `part == 自己那根骨骼` 的。引擎内部**不用加前缀**——每个引擎的 map 里只有一级，
  名字撞不上。`stateOn("出汗")` 在角色引擎里问的是全局状态，在手的引擎里问的是手的。
- **写规则的人不用想命名空间**：条件/动作里的"状态"只写名字，在哪个引擎里就是哪一级。
- **渲染那边要合并**：渲染器只有一个 `states` map，所以要按**图层标记**来查：
  `LayerSpec.state` 里局部状态的标记写成 `"<骨骼>:<状态>"`（全局的还是光名字），
  合并时用同一个规则拼键。于是 `LayerSpec.visible()` **一行都不用改**（它只是查表），
  而文件里也看得出这条标记是哪一级的 —— 名字撞了也不会画错。
- **存回去要合并**：界面里只看得见当前那一级的状态，所以保存时是
  `别级的状态 + 当前这一级`，不能直接拿过滤后的列表覆盖（那会把另一级删掉）。
- **建状态图（`addVariant`）**要知道这个状态是哪一级的，才能写对图层标记：
  局部状态写 `"<骨骼>:<状态>"`，全局的照旧。

## 文件：每种东西一个文件夹

```
characters/<角色>/logic.json                  角色自己的规则（已有）
characters/<角色>/parts/<骨骼>/logic.json      部件的规则（新）
characters/<角色>/liquids/<液体>/logic.json    液体的规则（新）
props/<道具>/logic.json                       道具的规则（新，道具是所有角色共用的）
props/object-logic.json                       旧的：所有客体规则挤在一起（保留，只读）
```

液体和粒子是**角色声明**的东西（颜色、黏度、受不受重力是角色的决定），
所以它们**是什么**留在 `characters/<角色>/logic.json` 里，
**怎么动**放进自己那个文件夹。这样两种角色可以有各自的"血"。

### 搬迁：旧文件一条都不能丢

- 读：新位置没有、旧位置有 → **用旧的**。
- 写：**只写新位置**，旧文件**不删**（那是用户的数据，不是我们的缓存）。
- 新位置存在但是**空文件**：**不回退**到旧文件 —— "空 ≠ 没有"这条已经踩过一次
  （见 `CharacterStore.loadLogic` 的注释），搬家的代码最需要它。

## 界面

- **逻辑管理**最前面那排主体 chips 多出每个部件一项（`部件·手`）。
  部件的规则和角色的规则在同一个界面里写，只是主体不同 —— 不新开一屏。
- **状态面板**按主体过滤：选角色时列全局状态，选部件时列这个部件的局部状态，
  外加一个"新建局部状态"。现在的状态行已经会写"用在哪（几张图 · 几条规则）"，
  局部状态那行再加一句"属于 手"。
- **部位文件夹**（`桌宠管理 → 部位 → 某根骨骼`）里多一行"这个部位的规则"，
  点进去就是它的逻辑管理。

## 顺序（一次一步，每步都能单独发版）

1. `Subjects.part` + 事件路由 + 部件主体在界面里可选 —— **规则存在老地方**，只是主体多一种。
2. 局部状态（`StateSpec.part` + 引擎的键 + 状态面板的过滤）。
3. 文件夹搬迁（三个新位置 + 旧文件只读 + 测试）。
