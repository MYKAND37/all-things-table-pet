# 角色绘画规范 · female_base

这份文档就是 **A + C 方案**：模板对齐（A）加命名约定（C）。
你按模板画，按名字导出，系统自动装配，**不需要任何手动对齐**。

---

## 一、画布

| 项 | 值 |
|---|---|
| 画布尺寸 | **1024 × 2048**（宽 × 高） |
| 头高 | 276 px |
| 身高 | 1690 px（6.12 头身） |
| 头顶 y | 179 px |
| 中线 x | 512 px |

模板图：[template_female_base.png](template_female_base.png)

## 二、导出规则（三条，必须全遵守）

1. **每个部位单独一层**，画在模板之上。
2. **导出时必须是整张画布尺寸**（1024 × 2048），不要裁到内容边界。
   位置信息就藏在「整张画布」里——裁了就全错位。
3. **文件名 = 骨骼名**，例如画左上臂就存成 `upperarm_L.png`。

> **缺文件不会报错。** 某个部位还没画，那根骨骼就不画东西，骨架照常工作。
> 所以可以先画一部分、装上试效果，再慢慢补。

> 为什么坚持「整张画布」：这是让**位置自动对齐**的唯一办法。系统按骨骼名把图挂上去，
> 图本身已经在正确位置上，不需要任何标定步骤。导入时程序会自动裁掉透明边并记住偏移，
> 所以存储上不会浪费。

**按静止状态画就行**，不用考虑飘起来的样子。

## 五、图层顺序

从后往前（数字大的盖住小的）：

| z | 部位 |
|---:|---|
| 10 | `thigh_R` |
| 11 | `shin_R` |
| 12 | `foot_R` |
| 13 | `thigh_L` |
| 14 | `shin_L` |
| 15 | `foot_L` |
| 20 | `hip` |
| 22 | `spine` |
| 24 | `chest` |
| 32 | `upperarm_R` |
| 33 | `forearm_R` |
| 34 | `hand_R` |
| 40 | `neck` |
| 42 | `head` |
| 50 | `upperarm_L` |
| 51 | `forearm_L` |
| 52 | `hand_L` |

另外还有两条**动态换序**规则：手抬到胸口以上时，那条手臂会自动翻到头和头发的**后面**。
这样「把手放到脑后」会自然被头挡住，不需要额外处理。

## 六、画完之后放哪

```
characters/female_base/
  character.json      <- 已经有了，不用动
  parts/
    head.png
    upperarm_L.png
    forearm_L.png
    ...
```

放进 App 的 **测试场** 就能看到角色动起来——手指可以拖关节。
