# 行动历程

> 这一份记的是**这份代码是怎么变成现在这样的**：谁要什么、我做了什么、哪里想错了、哪里被
> CI 抓住。README 讲「它是什么」，[`docs/VERIFY.md`](VERIFY.md) 讲「怎么验证」，
> 这一份讲「过程」。
>
> **为什么值得单独记**：这个项目换过手 —— 三个接入 DeepSeek 的智能体在不同时期各做了一段
> （名单、型号与分工在 [README 的「致谢」](../README.md)）：第一代 `DSH` 跑在
> **DeepSeek V4 Flash EXP** 上、**能看图**；第二代 `atp` 和我这一任 `ATP` 跑在
> **DeepSeek v4.1 Flash** 上、**看不到图**。
>
> 而我这一任是从一份**断续的摘要**开始的：上一任死于对话日志错误，我能看到的只有它的提交
> 信息、注释和那份摘要。
> 代码能读出结果，读不出**当时的取舍**；而取舍才是接手的人真正需要的东西。
>
> 所以这一份是给下一个我（或者你）看的 —— 尤其如果你也是被一份摘要叫醒的。

## 怎么用

- 每做完一件事，在「时间线」里追加一行：**要什么 / 做了什么 / 犯的错**；
- 「犯过的错」按**类型**记 —— 它不是忏悔录，是一份"下一次最容易踩的坑"清单；
- 「每一版的断言记录」是从 `docs/VERIFY.md` 搬来的（原来在 README 里）：它属于历史，不该
  占着参考文档的位置。

## 工作方式（交接时最该先读的六条）

1. **先量再断言**。任何一句"它更快/更准/更大"都要有一个数字在后面；量错了就写出量错的过程
   （「液滴大小」那一版我量的是水洼宽度，六条断言全红，换测量方式才是对的 —— 那一段还在
   验证记录里）。
2. **一条功能配一条断言；纯数学配一个镜像**（同一套算法用 Python 再写一遍，常数从 Kotlin
   源码里读）。镜像抓的是"两边不一样了"，不是"它对不对" —— 但它便宜、且真的抓得住。
3. **这台机器编译不了 Kotlin**（没有 JDK / Android SDK）：只有 CI 会编译。所以本地检查要
   尽量覆盖"只有编译器看得见"的那类错（名字、导入、常量前缀），因为一次 CI 往返五分钟。
4. **每次发布都归档 + 写 Release 说明**：APK 进 `~/exp/`，说明进 `~/exp/notes/`，GitHub
   Release 是给别人的，`~/exp` 是给自己的（同一个包、两份，不互为备份，是两条路）。
5. **欠账写在看得见的地方**：三条红的检查（求解器镜像）在 README、VERIFY.md 和
   `tools/check_all.py` 里都写着 —— 一笔不肯写在明面上的债是最糟的那种。
6. **「做出来但点不到」等于没做出来**。这一条我犯了四次（见下）：功能在、机制对、用户找不到。

还有一条不在规矩里、但在每一处细节里：**我看不到任何图片**（v4.1 Flash 不带视觉），而屏幕
上的东西是"看得见才算数"的。所以这个仓库里凡是"看起来怎么样"的问题，最后都变成三种东西：
**坐标与尺寸**（骨架怎么贴）、**统计量**（掉帧、抖动、间距）、或者**把眼睛借给**——你把看到的
说出来，我把它变成断言。这不是客套话，是这个仓库的工作方式里最实际的一条。

## 犯过的错（按类型）

### 一、"名字对不上" —— 三次 CI 红，全在这台机器上看不见

| 错 | 为什么本地没抓住 | 之后加的检查 |
|---|---|---|
| `ANIMATIONS_FILE` 少了 `CharacterFolder.` 前缀 | 只有编译器管跨类引用 | `kotlin_check`：CharacterFolder 的常数在类外必须带前缀 |
| `Labels` 写在 `ui/`、`MainActivity` 在 `dev.atp.pet`，忘了 import | 同上 | `kotlin_check`：跨包用的 object 必须 import |
| `PROP_KINDS` 写成 `PROPKINDS` | 生成脚本和手写引用是两套拼法 | `kotlin_check`：全大写名字**离本树某个名字只差一两个字母**就是打错了（判据宽松，因为 `Service.START_NOT_STICKY` 和 `0xFF171528` 必须不报） |

三条新检查**都用真错误反过来验过**（把错改回去，看它红不红）—— 这是这个仓库的规矩，也是
唯一能证明"检查真的在干活"的办法。

### 一·五、检查本身写错了三次（1.21.0）

为"加了枚举值忘了 when 分支"写的检查，前后错了三轮，每一轮都是**误报**——而误报比不检查更糟
（它会让人开始无视红色）：

1. 判据是"正文里点到了这个枚举的两个以上项"→ 把 `when (section)`（另一个枚举，共用
   PARTICLES / LIQUIDS 两个名字）报进来；
2. 数花括号时不剥字符串和注释 → 正文提前截断，于是**在完全正确的代码上**报"少写了一个分支"；
3. 判据改成"几乎点全了"→ 又漏掉了真错误（`when (pane)` 的正文里有一个 arm 自带 if/else，
   我把那个 `else` 当成了 when 的 else 分支）。

最后成立的写法：**只看"变量类型是枚举"的 when**（`pane: Pane`）—— 那才是编译器那条规矩适用的
地方，也不会被"只是提了几句枚举值"的 when 骗到。教训写在这里，因为它是这个仓库最贵的一课：
**一个检查的判据错了，比没有检查更坏。**

### 二、我自己写错的断言

- 「动画走完一圈回到开头」：我以为 t=2.1 应该回到 -30 度。其实 2.1 已经走进第一帧 10%，
  **-21 才是对的** —— 错的是断言不是代码。教训：断言挂了先怀疑断言。

### 三、"做出来但点不到"（四次）

动画（入口在「动作」按钮里，而它写着「动作 (0)」）、节点当主语（面板列表里有，但位置解析
只认骨头）、部件测全局状态（引擎支持了，面板不列）、两级状态（1.11 就有，弹窗不说是谁的）。
四次都**不是机制问题**，是"你现在看的东西没有说自己是谁"。所以现在的做法是：每个新功能都
要有一条**入口断言**（`wiring_check` 里那张 ENTRIES 表）。

### 四、验证"检查"本身时的方法错

我用 `io.open(p,'w').write(io.open(p).read()…)` 去改被测文件 —— Python 先求值
`io.open(p,'w')`，**那一刻文件已经空了**，读到的自然是空串。于是那两次"验证"其实是把一个
空文件交给了检查器，看起来"检查没报错"。重做（先读、再写）之后才是真验证。
教训：验证一个检查时，**先确认被测的东西真的被改了**。

### 五、断言 grep 到了注释

「规则里的摆动作不再直接拿 map」这条断言，命中了我**自己解释旧写法**的那行注释。改成只看
代码行（跳过 `//` 与 `*` 开头）之后才是有意义的断言。

### 六、断言钉在实现细节上，实现一动就红（1.22.0）

动画工作台把动画页重写了一多半，于是 `wiring_check` 里四条断言变红 —— 而它们红得**没有信息**：
程序是对的，红的是"那句源码文本已经不在了"：

| 断言当时钉的东西 | 为什么它必然要红 |
|---|---|
| `askAnimation(folder, anim) { buildAnimList() }` | 编辑器多了一个 `withFrames` 参数，调用点当然变了 |
| `"existing: AnimationSpec?, after: () -> Unit"` | 同上，签名本来就该变 |
| `"val seconds: Float = 0.4f"` | 那个 0.4 被提成了一个常数（因为它现在有两处用） |
| `"if (animState.isNotEmpty()) out[animState] = true"` | 一帧能开好几个开关了，这一行必须拆开写 |

四条里没有一条在保护"功能还在不在"。改法不是把新文本抄回去，而是**把断言提到性质那一层**：
"编辑器不再绑定某一个容器（改完叫回调）"改成看 `after()` 有没有被调用；"默认帧时长"改成
**只允许有一个来源**（Kotlin 的常数，Python 镜像从源码里读它）；"当前帧的开关只进画图那张表"
改成看它有没有**拆开**写进去。教训：一条断言如果钉的是某一句源码长什么样，它测的是我上次
怎么写的，不是这东西还能不能用。

（同一个版本里还有一条**差一点写错**的：工作台演的是 `summoned ?: opened`，而骨骼页那个
`saveBones()` 写的是 `opened`。差一点就复用它了 —— "打开 A、放上场 B"的时候这两只不是一个，
写错一只是事后极难发现的那种（名字都对，就是写到了别人身上）。所以工作台的存骨骼自己一份、
folder 由调用方传进来，并且加了一条断言：**那段代码里不许出现 `opened`**。）

### 七、两个只有编译器看得见的错（1.22.0）

这一版 CI 红了一次，两条错，都是**本地那八条检查看不见的类型错**——而那正是这台机器上唯一
测不了的东西。

1. `SkeletonView.kt`：我给"把画布转多少度"起名 `setRotation` —— **那是 `View` 自己的方法**
   （转整个控件）。Kotlin 不肯编译：
   `Cannot weaken access privilege 'public' for 'setRotation' in 'View'` /
   `'setRotation' hides member of supertype 'View' and needs 'override'`。改成
   `applyViewRotation`。这一条**已经补进 `kotlin_check.py`**（第九条检查）：View 子类不许声明
   `setRotation` / `setAlpha` / `setScaleX` / `invalidate` 这类平台名字（`override` 的除外），
   并且照例用真错误反过来验过 —— 把 `setRotation` 写回去，它立刻红。
2. `MainActivity.kt:6022`：写成 `if (s == null || folder == null) return` 之后继续用 `anim`
   （`AnimationSpec?`）。编译器说了三次"only safe calls on a nullable receiver"：
   **`s == null` 推不出 `anim != null`**，那个 `s` 是 `if (anim == null) null else Anim.sample(...)`
   算出来的，这个跳跃编译器不做。改成三个变量各自判。

第 2 条**没有加检查**，理由写在这里：它的判据是"某个变量在这个条件下是不是非空"，那要一张
流图，写歪了就是误报 —— 而误报比不检查更坏（第六节）。这一条只能靠"写的时候想一下"，所以它
留在这份日志里，而不是留在检查里。

### 八、崩在用户手上的那个按钮（1.22.1）

用户报：「在动画编辑里面点转 90 度会立即闪退」。

真因不在那个按钮里，在**画布旋转那一段绘制**：我写了

```kotlin
if (turned) canvas.rotate(viewRotation, pivotX, pivotY)   // 没有 save
...
if (turned) canvas.restore()
```

两件事同时发生：旋转会**漏给父控件**（整个界面跟着转），而那个 restore 会去弹**别人的**存档
—— Android 在 restore 弹空的时候直接抛（`Underflow in restore - more restores than saves`）。
用户看到的"点一下按钮应用就没了"就是这个。**双指旋转走的是同一段代码**，所以"把按钮删掉"这个
要求如果只照字面做，两指一转还是会闪 —— 我先补上 `canvas.save()`，再按用户说的把按钮摘掉。

教训有两条，第二条更贵：

1. 那个按钮**我一次都没点过**。功能和手势在同一条路上，我验了手势（写在断言里），没验按钮。
   "同一段代码"既是好消息（修一处就够）也是坏消息（任一个入口没走，就等于没验）。
2. **为它写的检查，第一版是错的**：判据写成"这个文件里有 `canvas.save()` 就跳过"—— 而
   `SkeletonView` 里别处确实有一个 save（画角色那一块），于是它**放过了真 bug**。我照例把真
   错误写回去验，才看见它没反应。改成两条能数的判据：整个文件 `restore` 不许比 `save` 多；
   任何一个函数里有画布变换，这个函数里就至少要有一次 `save`。为了让第二条在"提前 return"的
   写法下也成立（提前返回会让配对数出不了口），`onDraw` 里那个 `if (!showSkeleton) return`
   改成了 `if (showSkeleton) { ... }`：**能数得清**本身就是一种更好的写法。

### 九、镜像测试第一次就抓到了我自己写错的东西（1.23.0）

时间轴那一版的中心是"帧"和"通道"必须是同一个东西的两半，于是写了一条断言：**把帧烘成通道之后
再采样，必须和原来逐点相同**。第一次跑：**最大差 168 度**。

一查，错的是我对帧模型的理解，不是断言：帧模型里**两根相邻的帧都没写到的骨头等于回站姿
（0 度）**，而不是"沿用上一个值"。我一直按后者写烘培（也一直这么以为 —— `Anim.blend` 那句
"没写到的一侧保持另一侧的值"只在**一对**帧之内成立，跨过这一对就掉回 0）。要精确，就得照着
真正那三条规矩来，连缓动都得跟着选（斜坡用匀速、保持用阶跃）。改完 0.000000。

这是这个仓库第一次"先有断言、后有实现"地抓到一个语义错误，而且抓的是**我自己以为已经理解**
的那部分。教训：把"两种表示是等价的"写成一个能跑的数字，比在文档里写一句"转换是无损的"值钱
得多。

### 十、一个键的读法不在检查的认识范围里（1.24.0）

姿态锚点绑规则，存的是「第几条」（`optInt`）。写完 `store_check` 立刻红：「动画：写出去的和读回来
的是同一批键」。代码是对的 —— 红的是**检查的判据**：它抽「读回来的键」用的正则里列了
`optString|optDouble|optBoolean|optJSONObject|optJSONArray`，**没有 `optInt`**。于是一个用
`optInt` 读的键看起来像「写出去没读回来」。

判据补上 `optInt` 之后才是真的断言。同一个毛病在 `frame_read` 那条上也有一份，一起补了。
教训和第六节是同一个：**判据漏了一种情况，检查就会在正确的代码上红** —— 这一次它红得很快，
是因为它比的是两边的**集合**（差一个立刻看得出来），不是因为有人去读日志。

### 十一、"搬了父子关系，忘了它自己藏着"（1.24.1）

用户报：「怎么按钮都不见了，我咋存帧咧」。

1.23.1 为了修平板横屏的遮挡，把底栏和状态行从根布局（浮在内容上面那一层）搬进动画页的纵向
流里。搬的时候我只搬了**父子关系**，还顺手给结构断言加了一句"谁是谁的孩子"—— 然后就把
`visibility="gone"` 忘了：底栏原来在根布局里是 `gone`，由 `show()` 打开它；改成一整页开关
（`animPane`）之后，再没有人打开它。**整页显示着，底栏永远藏着。**

这一课的要点不是"忘了删一个属性"，而是**我加的那条断言只问了我想得到的那一半**。我看到
"位置错了"（遮挡）就去验位置，而"看不见"有两个原因：不在正确的地方，或者自己在躲着。所以
那句断言现在是两问：父子对不对，**以及它自己藏没藏起来** —— 照例把真错误写回去验过（加回
`gone` 立刻红）。另外把布局里 16 个写着 `gone` 的控件对着代码全过了一遍，没有第二个。

### 十二、"转两遍"和"看漏一半"（1.25.0）

这一版修的四条 + 两条新要求，全是用户报的，而其中两条的根是同一个毛病：**我把一件事在两个地方各做了一次**。

1. **视角旋转把骨头转了两遍**。骨头是拿 `vx/vy` 画的（我在里面乘了 cos/sin），图是拿
   `canvas.rotate` + 自己的变换画的 —— 两个变换各转一次，于是转 90° 时骨头走了 180°、图走了
   90°，用户看到"骨骼和图片错位"。修法不是"再调一调"，而是**把旋转整个拿掉**（视角定死）：
   只剩缩放和平移，两边共用同一套数，从结构上不可能错位。**能共享的东西重复做一次，就是 bug。**
2. **"编辑之后回到帧起点"把姿势换掉了**。我写 `loadAnimationStudio` 时想的是"选中哪一帧就摆
   哪一帧"，于是每次落盘后的重建都摆回**帧起点**；而用户是在**播放头**那一刻摆的姿势 ——
   加个关键帧，姿势就自己变成另一个样子（"莫名其妙变一个动作"）。修法：工作台记住**播放头**，
   所有"编辑完再显示"都回到那一刻（`showStudioMoment`）。
3. **帧模型只看相邻两帧**，于是"隔着一帧没写到的骨头"会啪一下回站姿（80 度的瞬移）。这是我
   自己写在注释里的**本意**（"只写要动的那几节，不该让没写的骨头弹回站姿"），老实现只在相邻
   两帧里做到了它。改成"每根骨头各自在**提到过它的帧**之间插值"之后，它和通道模型也变成了
   同一件事，烘培因此不用再拿阶跃去凑。

教训：**注释里写下的意图，要用一条能跑的断言去量**（这次量的是"最大一步变化多少度"）。
"我注释里说不会弹回 0"和"它真的不弹回 0"之间，隔着一个 实现细节。
