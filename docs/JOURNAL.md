# 行动历程

> 这一份记的是**这份代码是怎么变成现在这样的**：谁要什么、我做了什么、哪里想错了、哪里被
> CI 抓住。README 讲「它是什么」，[`docs/VERIFY.md`](VERIFY.md) 讲「怎么验证」，
> 这一份讲「过程」。

> （名单、型号与分工在 [README 的「致谢」](../README.md) —— 09-24 起是两个实例并行，
> 谁做了哪一版只能按功能认）：第一代 `DSH` 跑在
> **DeepSeek V4 Flash EXP** 上、**能看图**；第二代 `atp` 和我这一任 `ATP` 跑在
> **DeepSeek v4.1 Flash** 上、**看不到图**。
>
> 而我这一任是从一份**断续的摘要**开始的：上一任死于对话日志错误，我能看到的只有它的提交
> 信息、注释和那份摘要。
> 代码能读出结果，读不出**当时的取舍**；而取舍才是接手的人真正需要的东西。
>
> 所以这一份是给下一个我（或者你）看的 —— 尤其如果你也是被一份摘要叫醒的。

## 怎么用

- 每做完一件事，在「时间线」里追加一行：**要什么 / 做了什么 / 犯的错**；
- 「犯过的错」按**类型**记 —— 它不是忏悔录，是一份"下一次最容易踩的坑"清单；
- 「每一版的断言记录」是从 `docs/VERIFY.md` 搬来的（原来在 README 里）：它属于历史，不该
  占着参考文档的位置。

## 工作方式（交接时最该先读的六条）

1. **先量再断言**。任何一句"它更快/更准/更大"都要有一个数字在后面；量错了就写出量错的过程
   （「液滴大小」那一版我量的是水洼宽度，六条断言全红，换测量方式才是对的 —— 那一段还在
   验证记录里）。
2. **一条功能配一条断言；纯数学配一个镜像**（同一套算法用 Python 再写一遍，常数从 Kotlin
   源码里读）。镜像抓的是"两边不一样了"，不是"它对不对" —— 但它便宜、且真的抓得住。
3. **这台机器编译不了 Kotlin**（没有 JDK / Android SDK）：只有 CI 会编译。所以本地检查要
   尽量覆盖"只有编译器看得见"的那类错（名字、导入、常量前缀），因为一次 CI 往返五分钟。
4. **每次发布都归档 + 写 Release 说明**：APK 进 `~/exp/`，说明进 `~/exp/notes/`，GitHub
   Release 是给别人的，`~/exp` 是给自己的（同一个包、两份，不互为备份，是两条路）。
5. **欠账写在看得见的地方**：三条红的检查（求解器镜像）在 README、VERIFY.md 和
   `tools/check_all.py` 里都写着 —— 一笔不肯写在明面上的债是最糟的那种。
6. **「做出来但点不到」等于没做出来**。这一条我犯了四次（见下）：功能在、机制对、用户找不到。

还有一条不在规矩里、但在每一处细节里：**我看不到任何图片**（v4.1 Flash 不带视觉），而屏幕
上的东西是"看得见才算数"的。所以这个仓库里凡是"看起来怎么样"的问题，最后都变成三种东西：
**坐标与尺寸**（骨架怎么贴）、**统计量**（掉帧、抖动、间距）、或者**把眼睛借给**——你把看到的
说出来，我把它变成断言。这不是客套话，是这个仓库的工作方式里最实际的一条。

## 犯过的错（按类型）

### 一、"名字对不上" —— 三次 CI 红，全在这台机器上看不见

| 错 | 为什么本地没抓住 | 之后加的检查 |
|---|---|---|
| `ANIMATIONS_FILE` 少了 `CharacterFolder.` 前缀 | 只有编译器管跨类引用 | `kotlin_check`：CharacterFolder 的常数在类外必须带前缀 |
| `Labels` 写在 `ui/`、`MainActivity` 在 `dev.atp.pet`，忘了 import | 同上 | `kotlin_check`：跨包用的 object 必须 import |
| `PROP_KINDS` 写成 `PROPKINDS` | 生成脚本和手写引用是两套拼法 | `kotlin_check`：全大写名字**离本树某个名字只差一两个字母**就是打错了（判据宽松，因为 `Service.START_NOT_STICKY` 和 `0xFF171528` 必须不报） |

三条新检查**都用真错误反过来验过**（把错改回去，看它红不红）—— 这是这个仓库的规矩，也是
唯一能证明"检查真的在干活"的办法。

### 一·五、检查本身写错了三次（1.21.0）

为"加了枚举值忘了 when 分支"写的检查，前后错了三轮，每一轮都是**误报**——而误报比不检查更糟
（它会让人开始无视红色）：

1. 判据是"正文里点到了这个枚举的两个以上项"→ 把 `when (section)`（另一个枚举，共用
   PARTICLES / LIQUIDS 两个名字）报进来；
2. 数花括号时不剥字符串和注释 → 正文提前截断，于是**在完全正确的代码上**报"少写了一个分支"；
3. 判据改成"几乎点全了"→ 又漏掉了真错误（`when (pane)` 的正文里有一个 arm 自带 if/else，
   我把那个 `else` 当成了 when 的 else 分支）。

最后成立的写法：**只看"变量类型是枚举"的 when**（`pane: Pane`）—— 那才是编译器那条规矩适用的
地方，也不会被"只是提了几句枚举值"的 when 骗到。教训写在这里，因为它是这个仓库最贵的一课：
**一个检查的判据错了，比没有检查更坏。**

### 二、我自己写错的断言

- 「动画走完一圈回到开头」：我以为 t=2.1 应该回到 -30 度。其实 2.1 已经走进第一帧 10%，
  **-21 才是对的** —— 错的是断言不是代码。教训：断言挂了先怀疑断言。

### 三、"做出来但点不到"（四次）

动画（入口在「动作」按钮里，而它写着「动作 (0)」）、节点当主语（面板列表里有，但位置解析
只认骨头）、部件测全局状态（引擎支持了，面板不列）、两级状态（1.11 就有，弹窗不说是谁的）。
四次都**不是机制问题**，是"你现在看的东西没有说自己是谁"。所以现在的做法是：每个新功能都
要有一条**入口断言**（`wiring_check` 里那张 ENTRIES 表）。

### 四、验证"检查"本身时的方法错

我用 `io.open(p,'w').write(io.open(p).read()…)` 去改被测文件 —— Python 先求值
`io.open(p,'w')`，**那一刻文件已经空了**，读到的自然是空串。于是那两次"验证"其实是把一个
空文件交给了检查器，看起来"检查没报错"。重做（先读、再写）之后才是真验证。
教训：验证一个检查时，**先确认被测的东西真的被改了**。

### 五、断言 grep 到了注释

「规则里的摆动作不再直接拿 map」这条断言，命中了我**自己解释旧写法**的那行注释。改成只看
代码行（跳过 `//` 与 `*` 开头）之后才是有意义的断言。

### 六、断言钉在实现细节上，实现一动就红（1.22.0）

动画工作台把动画页重写了一多半，于是 `wiring_check` 里四条断言变红 —— 而它们红得**没有信息**：
程序是对的，红的是"那句源码文本已经不在了"：

| 断言当时钉的东西 | 为什么它必然要红 |
|---|---|
| `askAnimation(folder, anim) { buildAnimList() }` | 编辑器多了一个 `withFrames` 参数，调用点当然变了 |
| `"existing: AnimationSpec?, after: () -> Unit"` | 同上，签名本来就该变 |
| `"val seconds: Float = 0.4f"` | 那个 0.4 被提成了一个常数（因为它现在有两处用） |
| `"if (animState.isNotEmpty()) out[animState] = true"` | 一帧能开好几个开关了，这一行必须拆开写 |

四条里没有一条在保护"功能还在不在"。改法不是把新文本抄回去，而是**把断言提到性质那一层**：
"编辑器不再绑定某一个容器（改完叫回调）"改成看 `after()` 有没有被调用；"默认帧时长"改成
**只允许有一个来源**（Kotlin 的常数，Python 镜像从源码里读它）；"当前帧的开关只进画图那张表"
改成看它有没有**拆开**写进去。教训：一条断言如果钉的是某一句源码长什么样，它测的是我上次
怎么写的，不是这东西还能不能用。

（同一个版本里还有一条**差一点写错**的：工作台演的是 `summoned ?: opened`，而骨骼页那个
`saveBones()` 写的是 `opened`。差一点就复用它了 —— "打开 A、放上场 B"的时候这两只不是一个，
写错一只是事后极难发现的那种（名字都对，就是写到了别人身上）。所以工作台的存骨骼自己一份、
folder 由调用方传进来，并且加了一条断言：**那段代码里不许出现 `opened`**。）

### 七、两个只有编译器看得见的错（1.22.0）

这一版 CI 红了一次，两条错，都是**本地那八条检查看不见的类型错**——而那正是这台机器上唯一
测不了的东西。

1. `SkeletonView.kt`：我给"把画布转多少度"起名 `setRotation` —— **那是 `View` 自己的方法**
   （转整个控件）。Kotlin 不肯编译：
   `Cannot weaken access privilege 'public' for 'setRotation' in 'View'` /
   `'setRotation' hides member of supertype 'View' and needs 'override'`。改成
   `applyViewRotation`。这一条**已经补进 `kotlin_check.py`**（第九条检查）：View 子类不许声明
   `setRotation` / `setAlpha` / `setScaleX` / `invalidate` 这类平台名字（`override` 的除外），
   并且照例用真错误反过来验过 —— 把 `setRotation` 写回去，它立刻红。
2. `MainActivity.kt:6022`：写成 `if (s == null || folder == null) return` 之后继续用 `anim`
   （`AnimationSpec?`）。编译器说了三次"only safe calls on a nullable receiver"：
   **`s == null` 推不出 `anim != null`**，那个 `s` 是 `if (anim == null) null else Anim.sample(...)`
   算出来的，这个跳跃编译器不做。改成三个变量各自判。

第 2 条**没有加检查**，理由写在这里：它的判据是"某个变量在这个条件下是不是非空"，那要一张
流图，写歪了就是误报 —— 而误报比不检查更坏（第六节）。这一条只能靠"写的时候想一下"，所以它
留在这份日志里，而不是留在检查里。

### 八、崩在用户手上的那个按钮（1.22.1）

用户报：「在动画编辑里面点转 90 度会立即闪退」。

真因不在那个按钮里，在**画布旋转那一段绘制**：我写了

```kotlin
if (turned) canvas.rotate(viewRotation, pivotX, pivotY)   // 没有 save
...
if (turned) canvas.restore()
```

两件事同时发生：旋转会**漏给父控件**（整个界面跟着转），而那个 restore 会去弹**别人的**存档
—— Android 在 restore 弹空的时候直接抛（`Underflow in restore - more restores than saves`）。
用户看到的"点一下按钮应用就没了"就是这个。**双指旋转走的是同一段代码**，所以"把按钮删掉"这个
要求如果只照字面做，两指一转还是会闪 —— 我先补上 `canvas.save()`，再按用户说的把按钮摘掉。

教训有两条，第二条更贵：

1. 那个按钮**我一次都没点过**。功能和手势在同一条路上，我验了手势（写在断言里），没验按钮。
   "同一段代码"既是好消息（修一处就够）也是坏消息（任一个入口没走，就等于没验）。
2. **为它写的检查，第一版是错的**：判据写成"这个文件里有 `canvas.save()` 就跳过"—— 而
   `SkeletonView` 里别处确实有一个 save（画角色那一块），于是它**放过了真 bug**。我照例把真
   错误写回去验，才看见它没反应。改成两条能数的判据：整个文件 `restore` 不许比 `save` 多；
   任何一个函数里有画布变换，这个函数里就至少要有一次 `save`。为了让第二条在"提前 return"的
   写法下也成立（提前返回会让配对数出不了口），`onDraw` 里那个 `if (!showSkeleton) return`
   改成了 `if (showSkeleton) { ... }`：**能数得清**本身就是一种更好的写法。

### 九、镜像测试第一次就抓到了我自己写错的东西（1.23.0）

时间轴那一版的中心是"帧"和"通道"必须是同一个东西的两半，于是写了一条断言：**把帧烘成通道之后
再采样，必须和原来逐点相同**。第一次跑：**最大差 168 度**。

一查，错的是我对帧模型的理解，不是断言：帧模型里**两根相邻的帧都没写到的骨头等于回站姿
（0 度）**，而不是"沿用上一个值"。我一直按后者写烘培（也一直这么以为 —— `Anim.blend` 那句
"没写到的一侧保持另一侧的值"只在**一对**帧之内成立，跨过这一对就掉回 0）。要精确，就得照着
真正那三条规矩来，连缓动都得跟着选（斜坡用匀速、保持用阶跃）。改完 0.000000。

这是这个仓库第一次"先有断言、后有实现"地抓到一个语义错误，而且抓的是**我自己以为已经理解**
的那部分。教训：把"两种表示是等价的"写成一个能跑的数字，比在文档里写一句"转换是无损的"值钱
得多。

### 十、一个键的读法不在检查的认识范围里（1.24.0）

姿态锚点绑规则，存的是「第几条」（`optInt`）。写完 `store_check` 立刻红：「动画：写出去的和读回来
的是同一批键」。代码是对的 —— 红的是**检查的判据**：它抽「读回来的键」用的正则里列了
`optString|optDouble|optBoolean|optJSONObject|optJSONArray`，**没有 `optInt`**。于是一个用
`optInt` 读的键看起来像「写出去没读回来」。

判据补上 `optInt` 之后才是真的断言。同一个毛病在 `frame_read` 那条上也有一份，一起补了。
教训和第六节是同一个：**判据漏了一种情况，检查就会在正确的代码上红** —— 这一次它红得很快，
是因为它比的是两边的**集合**（差一个立刻看得出来），不是因为有人去读日志。

### 十一、"搬了父子关系，忘了它自己藏着"（1.24.1）

用户报：「怎么按钮都不见了，我咋存帧咧」。

1.23.1 为了修平板横屏的遮挡，把底栏和状态行从根布局（浮在内容上面那一层）搬进动画页的纵向
流里。搬的时候我只搬了**父子关系**，还顺手给结构断言加了一句"谁是谁的孩子"—— 然后就把
`visibility="gone"` 忘了：底栏原来在根布局里是 `gone`，由 `show()` 打开它；改成一整页开关
（`animPane`）之后，再没有人打开它。**整页显示着，底栏永远藏着。**

这一课的要点不是"忘了删一个属性"，而是**我加的那条断言只问了我想得到的那一半**。我看到
"位置错了"（遮挡）就去验位置，而"看不见"有两个原因：不在正确的地方，或者自己在躲着。所以
那句断言现在是两问：父子对不对，**以及它自己藏没藏起来** —— 照例把真错误写回去验过（加回
`gone` 立刻红）。另外把布局里 16 个写着 `gone` 的控件对着代码全过了一遍，没有第二个。

### 十二、"转两遍"和"看漏一半"（1.25.0）

这一版修的四条 + 两条新要求，全是用户报的，而其中两条的根是同一个毛病：**我把一件事在两个地方各做了一次**。

1. **视角旋转把骨头转了两遍**。骨头是拿 `vx/vy` 画的（我在里面乘了 cos/sin），图是拿
   `canvas.rotate` + 自己的变换画的 —— 两个变换各转一次，于是转 90° 时骨头走了 180°、图走了
   90°，用户看到"骨骼和图片错位"。修法不是"再调一调"，而是**把旋转整个拿掉**（视角定死）：
   只剩缩放和平移，两边共用同一套数，从结构上不可能错位。**能共享的东西重复做一次，就是 bug。**
2. **"编辑之后回到帧起点"把姿势换掉了**。我写 `loadAnimationStudio` 时想的是"选中哪一帧就摆
   哪一帧"，于是每次落盘后的重建都摆回**帧起点**；而用户是在**播放头**那一刻摆的姿势 ——
   加个关键帧，姿势就自己变成另一个样子（"莫名其妙变一个动作"）。修法：工作台记住**播放头**，
   所有"编辑完再显示"都回到那一刻（`showStudioMoment`）。
3. **帧模型只看相邻两帧**，于是"隔着一帧没写到的骨头"会啪一下回站姿（80 度的瞬移）。这是我
   自己写在注释里的**本意**（"只写要动的那几节，不该让没写的骨头弹回站姿"），老实现只在相邻
   两帧里做到了它。改成"每根骨头各自在**提到过它的帧**之间插值"之后，它和通道模型也变成了
   同一件事，烘培因此不用再拿阶跃去凑。

教训：**注释里写下的意图，要用一条能跑的断言去量**（这次量的是"最大一步变化多少度"）。
"我注释里说不会弹回 0"和"它真的不弹回 0"之间，隔着一个 实现细节。

### 十三、"只有第一次生效"（1.26.0）

用户报：「导入了三个部位状态结果它只显示第一个，不管开关与否」。

先用镜像把场景摆出来（三件替换图、逐个打开），一眼就看到根：**"平时那张"的让位标记只在它
还空着的时候才写**。第一次替换把它写成 `!甲`，从那以后它就不空了 —— 第二件、第三件替换
再也没让它让位。于是只有第一件是真的替换，后面几件都是"画在底图上"。

- 修法一：标记变成**追加**的一串（`!甲+!乙+!丙`，每一个都要满足）——`LayerSpec.state` 从
  "一个开关"变成"一串开关，与的关系"；
- 修法二：用户顺势要的**权重** —— 同一根骨头上只有最高那一档会画，所以三件同时开着时画哪件
  由用户说了算。叠加那一类和底图同档，照旧一起画。

同一天还补了两件事，都是"看得见 ≠ 能用"：
**节点能不能拖**（关掉照样挂道具、系绳子、有碰撞，只是手指拽不走）和
**液体/粒子画在角色前还是后**（各按各的老默认值，所以升级不换样子）。

### 十四、一个撇号让整轮构建失败（1.26.0）

CI 红在一句英文上：

    values-en/strings.xml:614: Failed to flatten XML for resource 'part_variant_prio_title'
    with error: Invalid unicode escape sequence in string

我写的是 `Where %1$s's drawing ranks` —— Android 资源里**裸的单引号**必须写成 `\'`（或者
把整句包在双引号里），否则 aapt2 直接拒绝。报错信息（"invalid unicode escape"）也没帮上忙，
是那一行的内容让我一眼看出来的。

`tools/english_check.py` 从此多一句：中文、英文两份资源里都不许有裸单引号，而且照例用真错误
反过来验过（写回去立刻红）。这已经是这台机器上第五类"只有工具链看得见、而本地检查能提前拦住"
的错 —— 每一个都值得一条本地断言。

### 十五、空白的名字（1.26.1）

用户报「自己添加的骨骼在逻辑里面没有显示名字」。

`Labels.bone` 写的是 `BONES[bone]?.let { context.getString(it) } ?: ""` —— **认不出就给空串**。
而它被逻辑页的主体名、部位那一行、深度页的层名、骨骼列表一起调着，于是用户自己加的骨骼到处
都是一片空白。讽刺的是同一个文件里 `pick()` 的注释写着"宁可显示中文，也不要显示空白" ——
**意图写在注释里，而代码走的是另一条路**，这一课在第十三节刚记过一次。

修法就一个字：`?: bone`（认不出就用它自己的名字）。骨骼编辑器里还抄过一份"前缀 → 中文"的表，
认不出也是空串，一起删掉、改用同一处 —— 同一个东西有两份实现，就是两个会各自出错的地方。

### 十六、单位错了 57 倍，而我修了两轮都没往那儿看（1.27.0）

用户第一次报「关键帧功能有 bug」，我修了四条：加"存关键帧"按钮、编辑后回到播放头、
菱形只在时间轴上拖、命中只看横向。用户第二次报「你也没修好啊：点加关键帧会突然旋转，
两个关键帧之间也没有动画衔接」。

真因只有一行：写进通道的角度用了 **`currentDegrees`**，而帧里的角度、求解器的目标、
关节的限位全都是 **`Bone.rotation` 的弧度**。一个 20° 的姿势 = 0.349 弧度，我写进去的是
`20` —— 大 57 倍。后果正好是用户描述的两件事：

* 预览里 `applyPose` 直接设 `rotation = 20`（= 1146°）→ 骨头猛地一转；
* 测试场里那个目标远超关节限位（±1.5 弧度左右）→ 骨头被顶死在限位上，两帧之间看起来
  **没有过渡**。

为什么两轮都没看见：我一直在修**交互**（按钮、光标、命中），而没问过一句"写进去的这个数，
和旁边那一半的单位一样吗"。整个链路只有两处调用 `currentDegrees`，另一处（关节范围弹窗）
是**对的** —— 因为 `BoneSpec` 的角度范围确实是度数。所以这不是"少写了一次转换"，而是
**同一个词在两个地方指两个单位**，而代码里没有任何东西逼你说清楚。

现在有两条本地断言盯着它：镜像里"摆姿势 → 打关键帧 → 采样必须一模一样"（四个真实量级的
弧度值），静态的"关键帧的值只能来自 `currentAngles`、而 `currentDegrees` 只许出现在给人看的
那一处"。照例把真错误写回去验过。

## 每一版的断言记录

从 `docs/VERIFY.md` 搬来（原来在 README 的「关于验证」里）。每一段说的是：**这一版加了什么，
它被哪一条断言钉着，以及为什么是那一条** —— 这是"当时的取舍"，代码里读不出来。

**图层平方这一版的验证**：`tools/store_check.py` 五句 —— 一根骨头两层的骨架**存三次层数
不变**（`[20, 20, 20]`）、两次保存完全一样、被写过 8 次的层折叠回 1 层、折叠不伤别的骨头、
以及从 Kotlin 源码里确认那两处修复还在（`.distinct()` 与 `layerSeen`）。把去重拿掉，前三条
立刻变红 —— 这是拿真 bug 反过来验过的测试，不是照着实现抄的。

**侦测器问世界这一版的验证**：`tools/logic_check.py` 十二条 —— 手比肩膀高成立 / 放下不成立
（y 越小越靠上）、余量 10px 不够 30px 够、靠左比的是 x、有一节不在场上、没有世界可问时
不成立；绳子：连着 / 前缀 / 没连着 / 「没连着」这条 / 留空算全身。`tools/wiring_check.py`
四句：引擎有 `Facts` 接口、测试场把它交给**每一个**引擎、`tied` 问的是绳子不是钉子、
深度是运行时覆盖（`setDepth` + 回到文件顺序的 `clearDepth`）。

**用不上的图层这一版的验证**：`tools/wiring_check.py` 四句 —— 能判断「这一层永远画不出来」、
有一个过滤器能找到它们、点它有得改（换状态 / 重建状态 / 导入图 / 删掉）、以及**画好但没排进
表的图会被列出来**（最安静的那一种：行根本不存在）。

**图层深度过滤这一版的验证**：`tools/wiring_check.py` 三句 —— 深度页有状态过滤、▲▼ 按
**看得见的行**换位（不是按整张表走一格）、以及落盘的仍然只有 `depthLayers` 那一份列表
（过滤是视图，不是第二份顺序）。

**「哪一只在场上」这一版的验证**：`tools/wiring_check.py` 三句 —— 刷新列表时留住场上那一只
（不是跳回第一只）、挑一只上场只有一个入口（`summon`）、测试场顶上**先给的是"哪一只"**而不是
松垮/僵硬（它原来排在状态方块后面，方块还会随宠物变多 —— "没有地方可以选"就是这么来的）。

**桌宠包这一版的验证**：`tools/package_check.py` 镜像 `PetPackage` —— 常量从 Kotlin 读
（`512L * 1024 * 1024` 这种写法也读出它**算出来是多少**），然后钉四条：`..` / 绝对路径 /
盘符 / NUL / 超长名字一条都不写出去；重名走 `freeId`（导入永不覆盖）；格式号、`kind`、
`character.json` 任一不对就整包拒掉；解压再压缩过的包（套了一层文件夹）照样认得出来。
`tools/wiring_check.py` 盯「重置骨骼」的承诺：只写这一套的 spec、**不碰部位图、不删任何东西**。

**参考图这一版的验证**：`tools/wiring_check.py` 里两句 —— 编辑器把状态表交给渲染器
（那正是"被状态挡住的图永远不画"的机器版本）、上传的图会被画出来；入口表里也多了
「调骨骼时的参考图」。`tools/store_check.py` 那句钉的是参考图的位置：跟着骨骼套走、
而且**不在 `parts/` 里**。

**多套骨骼这一版的验证**：`tools/store_check.py` 里那一节钉住三条路径规则 —— **默认套还在
老地方**（零迁移，全世界存档都在那儿）、命名套各占 `rigs/<名字>/` 一层、动作跟着骨骼套走；
另外两条是"文件格式的两半"式的：规则/粒子/液体**不**跟着骨骼套走，以及落盘的临时文件必须
和它要换掉的文件在**同一个目录**（换套之后 `.tmp` 留在桌宠根目录，是个只在换套时才出现的
bug）。`tools/wiring_check.py` 钉住换骨骼套的两个机制（记账 + 速度上限）和"swapRig 里没有
新的 RuleEngine、没有清粒子" —— 那三句就是"换的是样子不是这一只"的机器版本。
`tools/logic_check.py` 里 `setRig` 原样穿过引擎、`rigSwap` 是声明过的事件。

**液滴大小 / 透明度 / 粒子在最上层这一版的验证**：`tools/fluid_check.py` 量的是**静止后的
中位间距**，不是水洼的宽度 —— 宽度是那个"看起来该量的数"，而它没用：喷出来的水会一直摊到撞墙，
所以什么大小量出来都是 2800–3000px，唯一在变的只有它对墙的压力（这一版第一稿就是这么写的，
六条断言全红，然后换掉的）。间距才是机制：0.5× / 1× / 2× 量到 **7.5 / 15.0 / 30.0 px**，
两端（0.25× 与 4×）各一句，再加上"一滴落地时离地多高 = 它自己的半径"和"场上最大那滴决定
整滩的间距"（后者是把那条明说的近似**当成决定**钉住，免得它哪天变成惊喜）。三个 clamp
（`MIN_SIZE` / `MAX_SIZE` / `MIN_OPACITY`）是**从 Kotlin 源码里读出来**再比的 —— clamp 漂了
从两边都看不出来。`tools/logic_check.py` 按块抄下每个液体 / 粒子字段的**写入键**和**读取键**
再比对：只做一半（写进文件了、读的时候键名拼错一个字母）不会报错，症状只有"我改了它，喷出来
还是老样子"。`tools/wiring_check.py` 钉住界面这一半：两行 stepper、白色在色板里（数出来是九个）、
保存时进了 spec、**四次喷**（按钮 + 规则 + 发射器）都带上了这两个数、透明度乘进两次绘制，
以及粒子的两层顺序（活粒子在宠物和道具之后、印子在一切之前、气泡还在最上面）。

**节点在地点上 / 部件问全局这一版的验证**：`tools/rig_prop_check.py` 把「名字 → 位置」
这条规矩**镜像**了一遍（`node_point` 沿骨头当前的头→尖取点、两头夹住；`place` 先骨头再节点），
七句断言：骨头名给骨头、节点名给**节点那个点**、而它和所在骨头的距离正好 160px（这就是那个
bug 的量级）、谁都不是就没有这个地方、空名字也不是、骨头改长了节点跟着走（存的是距离不是
坐标）、落在骨头外面夹在尖端。`tools/logic_check.py` 镜像引擎那一半，十二句：手上的规则问
角色的开关成立、读它**不在本地留副本**、`hand_L:出汗` 这种带标签的写法指的是那一节自己的、
关掉的就不成立、自己声明的名字**不绕世界一圈**（数世界被问了几次）、手上改全局状态改的是
**真的那个**、再点一次关掉、没人声明过的开关本地不凭空造而且**记下来**、没有世界时读作
关着、反过来角色问一节自己的开关也成立。`tools/wiring_check.py` 盯 Android 那两半：
`Skeleton.place` / `boneFor` 存在、节点真的被列成主语、主语 / 事件里的 part / 「如果」问世界
三处都走 `place`、要骨头的地方走 `boneFor`；以及开关那条路的五句（Facts 上那一对读写、
引擎"先自己后世界"、不凭空造开关而且在日志里说出来、测试场按标签找主人、面板一张表给
「如果」和「就」共用、重名够不着的会写一句说明）。

**桌面上摆动作这一版的验证**：`tools/wiring_check.py` 十三句，盯的都是"哪个实例拿到了
动作表"这类接线（算法本身只有一次查表，没有可镜像的东西，这一点写在检查里）：动作是 `load`
的参数而且**没有默认值**、`load`/`swapRig` 都把它装进这一只的动作表、两个实例都交、按名字
摆动作查不到就不动而**且告诉调用方**、规则里的「摆动作」走 `playPose`（不是直接拿 map ——
那句断言只看**代码**，因为注释里正解释着旧写法）、世界也能往日志里写一句、
长按菜单有「摆动作」并发出命令、服务收得到而且名字没有时会说、存/改名/删动作之后名单会
刷新、召唤时连骨骼套一起记下来、桌面那一只开出来就是那套身体（不在就退回默认）、换套之后
记性跟着走；入口表里多了一行「桌面上的摆动作」。

**插计时器 / 桌面穿透这一版的验证**：`tools/logic_check.py` 三条行为断言钉住引擎那一半
（计时器**插在第一个执行器前面**：此刻什么都不做、1 秒时还没到、2 秒后才发生；中间那个
「等一会儿」原来就有三条），`tools/wiring_check.py` 十二句钉住编辑器那一半 —— 空档盒子在
三类表（就 / 否则 / 分支）里都放了、点它问秒数并插「等一会儿」、**插入不是替换**
（`list.add(at, …)` 而不是 `list[i] = …`）、以及穿透那半：alpha 压到 0.8 以下、
两个窗口都压、`FLAG_NOT_TOUCHABLE` 照设（alpha 不是替代品，是另一半）、更新失败会重挂
窗口、切不过去会说而且状态不假装、初始状态从同一个地方落地。

**动画这一版的验证**：采样是纯数学，所以它有一个**真镜像**：`tools/anim_check.py`
二十七句，常数（`MIN_FRAME` / `MIN_SPEED` / `MAX_SPEED`）从 Kotlin 源码里读出来再比 ——
两帧之间插值（-30 → 60 度，中途 15）、第二帧一开始就是目标角度、循环时最后一帧**插值回**
第一帧（闭合）而刚好一圈回到开头、不循环时时间夹在末尾、2 倍速一半时间到中点、0.5 倍速要
等两倍、倍率上下限、挂钟时长 = 动画时长 ÷ 速度、图**只在帧边界**换、半演算两者同时成立、
"一帧里没写到的骨头保持另一侧的值"（不然第二帧一到腿会弹回站姿）、单帧动画、0 秒和负秒数
不会把时间轴弄坏。写这个镜像的时候还纠正了**我自己写错的断言**：我以为走完一圈（t=2.1）应该
回到 -30 度，其实 t=2.1 已经走进第一帧 10%，-21 才是对的 —— 错的是断言不是代码，这件事写在

十四句盯接线（动画是 `load` / `swapRig` 的参数、两个实例都交、每帧按时间采样并把姿势当**目标**

**走完回第一帧这一版的验证**（1.30.0）：这一版只加了一个开关，但里面有两处取舍值得记下来，
因为它们是"以后想改回另一种做法"时最容易被推翻的两处。

第一处：**回家那一段是加在总时长里的一段，而不是往帧表里补一帧。** 理由是帧表是用户摆过的
东西，播放器不该往里偷偷塞内容（塞进去就会出现在时间轴上、会被烤进通道、会被用户存成"我摆过的
第 6 帧"）。所以它住在 `Anim.returnSeconds/totalSeconds` 里，两个宿主（测试场、动画页）问的是
**同一个总长** —— 原来两处各自写 `anim.duration`，这一版一起改成一个函数。`tools/wiring_check.py`
五句盯的就是这个：`returnHome` 的读写、两个宿主都改用 `totalSeconds`、通道在回家那一段也插值。
`tools/anim_check.py` 八句里最要紧的一句是"整条路上每 0.05 秒最多走 4.5 度"：截图看不出平滑，
只有连续采样能看出"哪一步是跳的"。

第二处：**通道（`tracks`）和帧用的是同一条回家规则。** 不这么做就会出现"姿势回去了、骨头还在
最后一帧的位置上"——因为一根骨骼可以在帧里有姿势、同时又有一条只打了两个关键帧的通道，两者
各有各的末尾。顺带修掉的是循环动画里通道的老毛病：原来末段是**停住**、绕回时跳回第一个值，
现在那一段走的是从最后一个值回第一个值的一整圈。`tools/timeline_check.py` 三句分的是这两半
（循环接回开头 / 不循环仍停在最后一帧）：它们必须**分别**断言，因为两种情况的正确行为正好相反。

**叠加这一版的验证**（1.31.0）：用户问的是"能不能两个动画一起播、动作能不能和动画叠"，选的
是**相加**。相加这一件事看着简单，但有一个必须先回答的问题：**加在什么上**。三个取舍值得记，
因为它们是"以后想换一种做法"时最容易被推翻的三处。

第一处：**编辑器里摆一帧存的是绝对角度，而相加要的是增量**，所以"摆的时候脚下踩的是什么"
必须跟着动画一起存 —— 就是那个 `AnimationSpec.base`（界面上的「基准」）。不存的话，播的时候
只能拿静息当零点：一段在坐姿上摆的挥手会演成"坐着的人手臂抬 60 度"，而这是**谁也说不清**的
结果。存**快照**而不是动作的名字，是因为名字是引用：用户以后改了那个动作，一段已经摆好的动画
会跟着变样，而存下来的东西不该因为别处改动而变（"现在这份基准是哪来的"因此是拿角度**比**
出来的，比出来的名字永远是真的）。

第二处：**"叠加"只有一个意思，四个通道一起换行为**（姿势相加、画面偏移相加、缩放相乘、
图开关并起来；关着就是整份接管）。不这么做的话，用户要按四次开关才能表达"这一段是加在别人
身上的"，而四个通道各有一套"谁赢"的规矩 —— 那是四套要分别解释、分别测的东西。`Timeline.overlay`
是它唯一的定义处，`tools/anim_check.py` 把四个通道一起量。

第三处：**一段"播一遍"的走到头 = 整场停**，姿势冻在那一刻。规矩定得这么粗是有意的：两段长度
不同时，"短的先停、长的接着演"要回答"那姿势现在归谁"，而那个答案在界面上讲不清。冻的方式是
把它 `applyPose` 成新的底座 —— 这样叠加的段撤掉时姿势不会跳（跳一下是用户最容易当成"坏了"的
那种症状）。

还有一处是**这一版唯一真正的技术风险**：动画每帧写的是**目标**，而叠加要减掉"脚下那一份"——
如果每帧写目标时顺手把底座也改了，第二帧就会在第一帧的结果上再加一次，姿势一帧一帧往关节
极限里爬（看起来像"求解器坏了"）。所以 `Ragdoll` 分成两个函数：`applyPose`（摆动作：底座 +
目标）和 `showPose`（动画每帧：只写目标）。`tools/wiring_check.py` 里那一条就是钉它的：
`showPose` 的函数体里出现 `poseBase` 就红 —— 反过来验过（塞一句进去，立刻红）。

**「按钮写着叠，就得真的叠」这一版的教训**（1.31.1）：1.31.0 的叠加做完，用户第一句反馈是
"没有叠加成功啊"。真因不在加法（那部分有十几条断言盯着），而在**入口和语义分了家**：
「＋ 叠」管的是"把这一段加进播放表"，而"加在别人身上"是那段动画自己的一个开关 —— 默认关。
两件事长得像一件事，用户按了写着"叠"的按钮，就以为语义已经切过去了。

这是这个仓库里第一次栽在**界面**上而不是机制上，所以值得记下三条：

1. **一个按钮的承诺要由那个按钮自己兑现**。它写着"叠"，那它就得让这件事发生（这里就是顺手
   把那段打开成叠加并且说一句"我改了你的动画"）—— 让用户再去别处找一个开关，等于这个按钮
   在骗人；
2. **语义开关必须在使用的那一刻看得见**。「正在演：发抖（叠加）· 脚下：坐」这一行是同一件事
   的另一半：用户按了「＋ 叠」之后，得能从屏幕上确认"它现在是叠加的、它踩在坐姿上"。
   没有这一行，"没叠上"和"叠上了但姿势难看"在用户眼里是同一种症状 —— 而这两种情况的修法
   完全不同（前者改入口，后者改语义）；
3. **界面要自己解释异常场面**。整份替换的动画压着一个动作时，列表当场写出"它会顶掉你按着的
   动作，按「＋ 叠」可以让它加在动作上"。这一条是拿用户的原话写的 —— 一个只有作者看得懂的
   功能，在用户那儿和没做出来是一样的。

**一个会答错的默认值**（1.31.2）：用户报"部位状态的开关能点亮，图不显示"。查下来不是画图那
一层，是**写文件**那一层：三处要回答"这个状态是这一节自己声明的，还是角色的全局状态"，三处
都调 `loadObjectLogic()` —— 而那个函数的 folder 参数自带 `= null`，`null` 会**静默跳过所有
部位文件**。于是三处一律答"不是"：图层写成全局的键 `出汗`，开关点亮的却是部位的键
`hand_L:出汗`，`LayerSpec.visible` 永远查不到。这个 bug 从 1.21.0 就在，只是要等到"给部位状态
配一张图"的人才会碰到，而那时症状（灯亮着、图不画）指向的是渲染，不是存储。

三条教训：

1. **默认参数是"看不见的调用"**。`folder: CharacterFolder? = null` 读起来像"可以不给"，实际
   意思是"给了才读部位文件" —— 一个会**答错**的默认值比一个必须写的参数危险得多。现在参数
   必须写，漏传是编译错误；另外加了一条机器断言（源码里不许出现不带这一只的查询）和一个 Python
   镜像（`parts_check` 里那句"查询时必须带上这一只"）。
2. **同一句话抄三遍，就是三个会忘的参数**。那三处是同一句判断，抄成三份之后，连"忘传 folder"
   都一起忘了三遍。判断现在只有一处（`variantTag`），断言盯的是"判断只有一份"。
3. **修代码不等于修好**。写坏的是**文件**：用户装上新版，那几张图还是不显示（他的 spec 里存着
   错的键）。所以这一版带了一个幂等的数据修复，判据只收错得毫无歧义的那一种（角色没声明、
   这一节声明了），而且修完会**说一句** —— 那几张图会突然出现在宠物身上，不解释就是"我的宠物
   怎么自己变了"。这条和 1.31.1 的教训是同一个：界面必须解释自己做了什么。

**「三样东西合成一个概念」这一版**（1.32.0）：用户要的是删掉并行分支、给每个「如果」加一个
向下的「否则」（可以是 else-if 链）、以及给「就」加按权重挑一支的「或者」。做完之后值得记的
是**它其实是一次减法**：

1. **删掉的功能腾出的位置比它占的多**。并行分支（1.11.9 加进来的）原来是"一个侦测器岔开若干
   执行器，全部响"，而"另开一条规则、当一样"就能做到同一件事 —— 用户的原话是「跟新建一条规则，
   只要当里面的内容不一样就没有区别」，这句话是对的。删掉它之后，图里"向下的行"这件事反而
   变成了通用的：**否则**挂在「如果」下面（"这些如果都不成立时"），**或者**挂在「就」下面
   （"这一支的备选"）—— 挂在哪一个方块下面是有意思的，不是排版细节；
2. **两个参数合成一个概念**。以前界面里到处传 `isElse: Boolean` + `branch: Int`（哪一支并行
   分支），每加一种地方就多一个参数、多一个会漏的地方。现在只有**一步**（`Step`：主行 / 第几级
   否则如果 / 否则）加上"这一步里的第几支就"。改完之后 `editTarget` / `putActions` /
   `putConditions` / `askTimer` / `insertAction` 全都不再需要第二个参数；
3. **"反方向"这件事不要另写一套**。「否则」= 整组条件不成立，而整组条件的真值早就有唯一的
   一处实现（`holds_conditions`：一组是**与**，组内**或者**连、组间**与**连）。所以"并且连着
   的一组取反 = 任一不成立""或者连着的一组取反 = 全都不成立"两句话都自动成立 —— 用户描述的
   那两种逻辑判断因此不需要任何新代码，只需要一条断言各钉一句。

**这一版的三条错判**：改完之后红的三条**全是我自己写的判据**（等权重的边界期望写反、
`1:3 == 2:6` 拿不同号的 roll 去比、把排版常数当成方块角色）。写错的判据比没有判据更糟：它会
让人去改**对的**代码。

**还有一条真空被反向验证抓出来**：我把 Kotlin 的加权挑选改成"永远第一支"，`logic_check` 一条
都没红 —— 因为那些边界断言量的是**Python 镜像**。补了一条"Kotlin 那句与镜像逐句一致"之后，
改坏 Kotlin 才会红。这个仓库里每一处"镜像 + 源码形状"的搭配都是同一个理由：镜像保证语义，
源码形状保证镜像没漂。

**一条不响的断言**（1.32.0 的第二个教训）：这一版我把改动推上去，CI 报了九处
`Unresolved reference: row` —— 我在两个新弹窗里调了一个不存在的助手。奇怪的是本地那条
「局部函数没有被别处调用」的规则（1.20.0 加的，专门为了这类错）**一声没响**。

查下来是它的归属追踪：它记"最近的函数"，而我把那些调用写在了一个**局部的 `fill()`** 里面，
于是归属变成了局部名 `fill`，规则按它自己那句"跟踪不可信就不说话"的保守分支沉默了。那条
保守分支当年是对的（花括号深度在字符串里数不准，宁可漏不可误报），可它恰好把这一版最常见的
写法（弹窗里的局部 `fill()`）整个遮住了。

修法只动一处：**归属取最近的成员函数**（缩进 4），局部函数的名字不参与判断；`object` /
`companion` 里那种没有外层函数的保持沉默。验证是反过来做的：把 `row()` 写回去，规则自己报出
`MainActivity.kt:10048 调了 row()，而它是 … 里的局部函数` —— 和 CI 报的同一行。

这件事值得记下来，因为它推翻了我一直默认的一件事：**断言写了就在看着**。一条有盲区的断言和
没有断言的区别，只在于它给人一个"这里有人管"的错觉。所以每加一条断言，最好都反过来验一次
（这一版我给三处新断言都做了反向验证，唯独没验这条老规则）。

**一个混用了一年的等式**（1.32.1）：用户报"给第 1 条规则加『就』，加到了第 2 条上；加完一条
规则之后所有方块都没反应"。查出来是一句话：**图报的是"第几行"，我一直当"第几条规则"用**。

之所以一年没出错，是因为以前**一条规则正好占一行** —— 那个等式一直成立，只是从来没人写下来过。
1.32.0 让一条规则可以有好几行（否则如果一级一行、或者一支一行），等式立刻不成立：错位是第一
个症状，"越界的规则号 + `getOrNull ?: return`"是第二个 —— 而第二个看起来像"所有方块都坏了"，
离真因（一个数被当成了另一个数）非常远。

修法不是"把索引改对"，而是**让两份名单不可能不同步**：建图的每一行都经过同一个
`logicPushRow(row, drop, rule, step)`，它同时往图的行和"行 → (规则, 步)"里加。剩下的就是点击
只许查那张名单。这条经验在这个仓库里是第二次出现（第一次是"状态图的标签只有一处判断"），
值得写成一句话：**两个必须同步的东西，不要靠"记得" —— 让它们只有一个入口。**

**接手另一个 agent 的半成品**（1.33.0）：这一版的功能（节点道具的位置能拖）不是我这个会话写的
—— 它在工作区里、没提交，我上一条提交用 `git add -A` 把它一起卷进来了，CI 随后因为它红了两处。
用户知道之后说"并过来完善"，所以这一版是**接手**：读懂、修掉两个问题、补齐收尾（版本号、
STATUS/VERIFY/JOURNAL、发布说明），再发。

三件事值得记：

1. **`git add -A` 在一个共享工作区里是危险的**。这个仓库现在有两个 agent 在改同一批文件
   （MainActivity.kt 最明显），`-A` 等于"把别人没写完的也提交了"。以后提交前先 `git status`
   看清楚，只 add 自己动的路径 —— 但同一个文件被两边改时这条也不完全够用，所以真正的解法是
   分开工作目录（那是用户要决定的事）；
2. **接手别人的代码时，先找"只有编译器看得见"的那类错**。它那两行「调位置 / 回中间」的闭包要
   `dialog.dismiss()`，却写在 `val dialog = …` 之前 —— Kotlin 里闭包只能捕获在它**前面**声明的
   局部变量。这类错本地检查看不见（那两行本身完全合理），只有 CI 会说话；
3. **顺带修了它一条手滑的断言**：拿 `LogicGraphView` 的正文去 `replace("graph","")` 再找
   `beginPropPlacement`，靠 `or` 兜住才不会误报。断言里"看着在查、其实查的是别的东西"比没有
   断言更危险 —— 它会让人以为这件事有人看着。

**一个按钮的判据长在文件里**（1.33.2）：用户报「部位图片叠加的功能不见了」。代码里那个
「改成叠加 / 改成替换」从 1.21.0 起**一个字都没改过**，所以它不是被删掉的 —— 是**判据不成立**：
那个按钮问的是"这一行落在哪一层上"（叠加还是替换，看的就是那一层的 `!状态` 标记），而用户那份

这一页没有"改这一张图挂哪个状态"这个动作，所以用户唯一的出路是删掉重加 —— 等于让他重画。
修法因此不是"改界面"，是**修文件**：文件名后半截（`hand_L__出汗.png`）就是它等的那个状态
（`addVariant` 一直是这么命名的），按它挂回去，挂成叠加（找回一个丢了的层，不该顺手把底图
关掉）。和 1.31.2 的 `repairPartStateTags` 同一个位置、同一个理由：**坏掉的是文件，而用户是在
界面上看见它的。**

顺带收了两处"抄一遍"：图层与深度那一页原来自己抄了一份同样的遍历（1.26.0 补的），而且只补在
**内存**里 —— 用户不按保存就没了，部位页上仍旧是一行"未使用"；"这个开关还在不在"的名单也在
两处各写了一遍。现在两条路各只有一个函数。

**一张快照回答不了一个会变的问题**（1.33.2）：用户报「桌宠在桌面上时有时候会掉出屏幕外，
希望能自动识别屏幕尺寸」。两处成因，都不在物理里：

1. 窗口尺寸写的是**服务起来那一刻** `resources.displayMetrics` 的宽高。屏幕转一下、系统栏
   收起/展开、分屏改变可用区域，窗口还是旧尺寸 —— 宠物于是站在"旧屏幕"的底边上，而那一条边
   已经在屏幕外面了。一张快照就是这个 bug 的形状；`MATCH_PARENT` 把这个问题交回给系统。
2. 桌面那一只的世界是**角色自己的画布**：出厂素体 `worldWidth` 6144，而一块屏幕只看得到其中
   三分之一，桌面模式又**不平移镜头**（手指在那边是点底下的 App 的）。被扔出去、被规则推走或
   被拖到边上的宠物可以停在两千多像素之外 —— 而"屏幕上什么都没有"和"它掉下去了"看起来是
   同一件事。往上扔也一样：屋子的天花板在 -1600，屏幕顶边在 -41。

修法是 `Ragdoll.cageTo(left, right, top)`：两堵墙和天花板搬到你正看着的那一块。**每帧给一次**
而不是建世界时算一次 —— 旋转、系统栏、双指缩放都会让这一块变，而它们都不该需要把宠物重建
一遍（重建会把它这一口气全丢了：数值、状态、正演到一半的动画）。**地板不在里面**，这是有意的：
地板已经是屏幕底边，而且道具和液体落的是同一块 —— 搬它会让那些东西落在半空。

这两条都值得记成一句话：**能被时间改掉的东西，不要写成一次性的**（世界多大、屏幕多大、
这张图归哪一层，都是会变的）。

**hitscan：把"子弹"从世界里删掉**（1.34.0）：用户要的是「第一人称视角的射击道具，点击道具
就像打开一个狙击镜」。这一句里藏着一个**减法**：既然**立刻结算**，就没有"飞出去的东西"——
`PropSpec.bullet()`、`SHOT_SPEED`、"拖出方向松手打一发"那一整条路全删了（hitscan 之后它们
一处调用点都没有）。剩下的是一件更小的事：**一枪 = 一条射线 + 一个瞬间**。

这一版几个判断都是从这一句来的：

* **射线不是点**。这是个 2D 侧视世界，准星的定义是一条**线**：落在线上的一切都在准星底下
  （所以 `SCOPE_REACH` 接近整间屋子 —— 短了会变成"看得见、打不着"）。这也正是 `rayHit` 返回
  **最近的**那一根的原因：挡在前面的先挨打。
* **宽容度按骨头问**。签名里那个参数是 `(Bone) -> Float`，不是一个 Float：手指和躯干不是一样
  粗，而调用方给的就是求解器用的那个碰撞半径 —— "打得中"和"撞得上"因此是同一个宽度。
  一个数只有一处出处的老规矩，这次长在了参数类型上。
* **印子存在骨头里**。命中点是一个世界坐标，而宠物一直在动：存世界坐标，抬手之间弹孔就飘到
  旁边去了。存进那一节骨头自己的坐标系，手一转它跟着转 —— 那才是"打在身上"。和 1.33.0 的
  节点道具偏移是同一件事，值得记成一句：**凡是贴在身上的东西，都要存在身上的坐标系里。**
* **镜头是借的，不是换的**。开镜用的是现成的 `viewScale` / `pan`（世界还是那个世界，只是窗口
  变小、对准了宠物），退出时三个数原样还回去。顺带因此免费得到两件事：镜筒里双指照样缩放，
  桌面那只（世界 = 屏幕）照样能开镜。
* **镜筒开着的时候镜头不许自己动**。`followPet` 那几个动作会把宠物慢慢挪到屏幕正中，而准星
  就在正中 —— 于是每一枪都不用瞄。开镜是你在瞄，不是镜头替你瞄。
* **"什么都没发生"要说出来**。打空是唯一一处"扣了扳机、世界一点变化都没有"的地方：不留
  事件、不留印子、也没有弹道线。所以它必须说一句 —— 和当年那条"点得太慢也要说"同一个规矩。

**这一版里"叠加不见了"那个 bug 的教训**（1.33.2，写在这里是因为它和上面同一天）：一个控件
看起来"被删了"，先别去界面里找 —— 那个按钮的**判据长在文件里**（这一行落在哪一层上）。判据
不成立时，按钮不是变灰，是**不存在**。

**镜像第一次跑起来就抓到了一个真 bug**（1.34.0）：这一版新写的 `tools/scope_check.py` 是
`Skeleton.rayHit` 的逐行镜像，第一遍跑出来 **11 条红、同一个根因** —— 那段几何里 `s` 的**分母
多了一个负号**：

    t = (p × e) / (u × e)        s = (p × u) / (u × e)        ← 共用同一个分母

符号一反，s 成了真值取负：一根横在正前方的骨头（真值 +0.5）算出 −0.5，被 `s < 0f` 丢掉 ——
**一枪打不中任何正对着的骨头**；反过来"头端往后"的位置会被当成命中。

它是上一任写的（1.34.0 第一步），写完就停在那儿了 —— 那段代码**一个调用点都没有**：没有界面、
没有测试、没有人调用。所以它一直没错过一次，因为它一次都没跑过。**这一版的镜像给了它第一个
证人**，而证人说的第一句话就是"这里错了"。

值得记下来的有两条：

1. **"没有调用点的代码"最需要镜像**。这个仓库的镜像一直是为了"两份会各自漂"（Kotlin 与 Python
   手写的同一件事），但这一次救回来的不是漂移，是**一段从没运行过的代码里的符号错**。纯函数 +
   逐行镜像，等于给它配了一个不花钱的编译器之外的第二个读者；
2. **红的是对的，就不要把它改绿**。写镜像的那个实例跑出 11 条红之后没有把判据按几何改对
   （那样会绿，但镜像已经漂了、而且这个 bug 从此看不见），而是照抄 Kotlin、把红留在那里、
   把推导写在注释里报上来 —— 这正是这个仓库对"欠账"的态度：**不肯写在明面上的债最糟**。
   修完两处（Kotlin 与镜像各一个字符）之后，第 0 节反过来钉住它：Kotlin 里不许再出现那个负号。

**「多个当」为什么不是把 `on` 改成数组**（1.35.0）：用户的原话是「一条规则可以加多个『当』
之间用或者链接」，还画了一张参考图（图上手写着「前面多个」）。实现本身只有一行判断
（`resolve()` 里"任意一个当发生都算听到"），真正要想清楚的是**文件格式**。

`on` 是这一条规则唯一的事件 id，把它改成数组读起来最自然 —— 可那样一来**老版本读到一个数组
会得到什么？** `optString` 在拿不到字符串时用默认值，也就是 `tick`：一条"被点一下"的规则会
变成"每隔一会儿"，一条安静的规则变成一条每两秒响一次的。所以选的是**多一个键**（`orOns`），
老版本读到只会**少认几个当**（规则变窄，仍然是它自己）。

同一个决定在这个仓库里是第三次了（「就」+「或者」、「如果」+「否则如果」，现在是「当」+
`orOns`），第三次才把它写成一句话：**给老读者留一条"读不懂就少做一点"的路，不要给它一条
"读错成另一件事"的路。**

另一条值得钉住的是语义：**冷却 / 一次 / 如果 / 部位 / 是哪个道具，全属于这一条规则，不属于
某一个当**。多个当是"几种叫醒方式"，不是"几条并行的规则"——后者正是 1.32.0 删掉的东西
（用户当时的原话是"跟新建一条规则，只要当里面的内容一样，就没有区别"）。镜像里专门有一条
断言钉着它：主当触发过一次、冷却还没过，换第二个当进来**不该**再响。

**镜像没漂，它只是忠实照抄了一个错误的决定**（1.35.0）：用户报「在桌面上打开无重力没效果」。
查下来是 `Settings.MIN_GRAVITY = 0.2f` 这一行 —— 而设置页那一排档位里**第一个就是 0**
（「零重力」）。于是 `gravityScale: 0` 存得下、**读回来被夹成 0.2**。为什么只有桌面那只中招、
测试场看着是好的：测试场用的是内存里那个刚点下的 0，**桌面上那一只会重新读一遍文件**
（`applyPetSettings` → `SettingsStore.load()`），读到的是被夹过的那一个。

真正值得记的是**为什么没有任何检查报警**：`tools/settings_check.py` 里有一条断言

    report("gravity below the floor", parse('{"gravityScale": 0}')["gravityScale"] == MIN_GRAVITY)

它**通过了** —— 因为镜像的 `MIN_GRAVITY` 也是 0.2，两边一模一样。这不是"漂了的镜像"（那是
另一种病），而是一种更安静的：**镜像忠实照抄了一个错误的决定，于是它一直在说"一切正常"。**
这个仓库对镜像的信任建立在一句话上（"两份手写的同一件事会各自漂"），而这一条补上的是它的
另一半：**镜像只能证明"两边一样"，证明不了"这个决定是对的"** —— 后者要么靠一个从**行为**
出发的断言（"点了零重力，读回来必须还是 0"），要么靠人的眼睛。

改法因此有两半：下限改成 0（一行），以及把断言从"夹到下限"改成"**这一档读回来还是 0**"
（它现在钉的是行为，不是那个常数）。外加一条"两边的下限是同一个数"——那个常数本身也值得
被钉一次，因为它曾经悄悄吃掉了一个用户能点的档位。

**"以前正好成立"是一个会过期的理由**（1.35.1）：用户报"不穿模"。1.33.2/1.34.0 那两版里，
桌面上那只的笼子只搬了**左右墙和天花板**，地板我特意留在角色自己那间屋子上 —— 当时的注释
写的理由是"地板正好就是屏幕底边，而且道具和液体落的是同一块，搬它会让那些东西落在半空"。

这句话本身没错，但它依赖一个**巧合**：`framePet` 在"房间比视口高"时会把 pan 对齐到地板，
于是地板确实等于屏幕底边。房间比视口**矮**的时候（横屏、平板），地板落在视口中间偏上 ——
宠物站在屏幕中间，东西落在它下面，看起来就是"没贴住、穿模"。

所以这一版的做法不是"把地板也搬过来"，而是**把那条线改成算出来的**：地板 = `panY + viewHeight()`，
而且**宠物、道具、液体拿同一组数**（`Ragdoll.cageTo` / `PropWorld.setBounds` / `Fluid.setBounds`
在同一次调用里拿到同一个 `bottom`）。判据因此从"搬没搬地板"换成了"三样是不是同一组数" ——
后者才是"脚踩的那条线 = 东西落的那条线"，也正是用户说的"不穿模"。

记成一句话：**注释里"因为现在正好……"这种理由，等于给未来埋了一个没有断言的假设。**
它可以留在那儿，但要么配一条断言，要么写成"如果哪天不成立了，就改成算出来的"。

**一条"只有一处判断"的断言，抓到的是第三处**（1.36.0）：用户要"部位图片可以使用 GIF 动图"。
改动本身不大（后缀名单、`AnimatedImageDrawable`、渲染那一处接上矩阵），值得记的是**断言怎么
找到真漏点的**：我写了一条"再没有第二处自己按 .png 判"（扫目录、部位页、变体名解析三处问的是
同一句话），跑起来就红了 —— 而它指的地方不是我这版写的，是 `CharacterStore` 里**改骨骼名**
那一段：它自己 `endsWith(".png")` 扫、自己 `removeSuffix(".png")` 拼新名字。后果是**GIF 的变体
在改名后成为孤儿**：文件还在老骨头名下，图层却跟着骨头改了名 —— 也就是 1.33.2 修过的"图在、
层找不到它"，换了个入口又来一次。

两件小事也记一下：

1. **那条断言第一次跑，红的是注释**。我写的解释性注释里就有 `endsWith(".png")` 这几个字，
   于是"代码里还剩几处"数出来是 1 —— 这个仓库在 1.32.1 前后就记过这一类（「断言 grep 到了
   注释」）。现在的做法是先把 `//` 和 `/** */` 都剥掉再数，这是**第二次**出现同一个坑，
   所以它从一个"注意"变成了一条规矩；
2. **回退是有名字的行为，不是"不支持"**。minSdk 是 26，`AnimatedImageDrawable` 要 28 ——
   所以 26/27 上显示**第一帧**（`BitmapFactory` 本来就会解出 GIF 的第一帧）。这不是"GIF 不
   支持"，是"这台机器上它是静的"；文档、发布说明和断言里写的都是这句话。

**一个写死的数字，用户看到的是"我的句子溢出来了"**（1.37.0）：用户要"人物多一个发图片的功能，
就像说话，说话的内容框能自动适配大小"。翻代码发现气泡一直是**写死的一个框**：

    val box = RectF(x - 200f, y - 82f, x + 200f, y - 4f)     // 400×78，永远
    canvas.drawText(text, x, y - 22f, textPaint)             // 一行，不折行

于是超过十来个字就**从框里溢出来**，两三个字又留一大块空白。这类"写死的数字"最麻烦的地方
不是它不好看，而是**它当时是对的**：出厂那几句话都短，谁也不会去量一个够用的框。

改法不是"把框调大一点"，而是把"框多大"变成**一道算术题**（`render/Bubble.kt`）：折行、封顶
（四行 + 省略号）、宽取最长那一行、图按比例缩、小图不放大、框挂在头顶且不探出画布。它写成
**纯函数**（文件里没有一行 `import android`，量字的宽度由调用方递进来），所以本地那个 Python
镜像可以喂一把假尺子，把每条规矩逐条钉住（`tools/bubble_check.py`，新增一个检查）。

同一版加的「发图片」就挂在这条路上：说话和发图是**同一个气泡**的两半（一边是文字、一边是图），
所以"自动适配大小"这件事一次做完，两种内容都受益。两个决定记一下：

1. **图的名字要问用户**。图存在 `characters/<这一只>/images/<名字>.png`，规则里按名字发 ——
   所以导入时**先问一个名字**，而不是拿 `IMG_20260930_001` 当 id：一个写不进规则的名字，
   等于这张图没法用；
2. **找不到那张图要说一声**（`没有「生气」这张图`）。一个错名字的规则从外面看就是"这个功能
   坏了"，而这正是这个仓库反复在修的那类"安静的死胡同" —— 和 1.33.2 那个"叠加不见了"同源。

**把布局写下来，才看见一个写死的 `0`**（1.38.0）：用户要的是"一条规则在添加分支时，他的分支
不会与其他规则并列在开头，而是直接向下后向右拐弯，多个分支就像打开括号一样……如果添加新分支，
下面又有其他规则，位置不够会自己挤开"。四句话，落在代码里是三件事：**缩进**（吊在别人下面的
行往右一格）、**块**（一条规则的行外面括一对括号）、**每次重算**（所以下面那些行自己让开）。

真正值得记的不是这三件事，而是**写镜像的时候被问住的那一句**："缩进几格"是从哪儿来的？答案
是挂点（`Drop`）—— 每一行只记"我挂在哪一行上"。于是紧接着就该问：**那挂点错了会怎样？**

以前的答案是"画错一条连接线"（没人看得出来）。这一版之后，挂点同时决定缩进和括号 ——
一条错挂点会把整串行缩进错、还会把它们括进**别人的块**里。所以我去看了挂点是哪儿来的，
然后就看见了：

    var fromRow = 0          // MainActivity：所有规则共用一份 graph，0 就是第一行

第一条规则正好也是第 0 行，所以这个写死的数一直没出错，**从 1.32.0 那条阶梯写出来到现在**。
第二条规则往后的「否则如果 / 否则」全都吊在第一條规则的当盒子底下 —— 镜像里把这一份"错的挂点"
也算了一遍：它把两条规则并成**一个块**，括号跨过中间的规则一直垂到第 3 行。这一条就这么反着
钉住（同时算对的和错的两份，错的那份必须表现为"并成一个块"）：一条只会变绿的断言证明不了
什么，它得能在错的代码上变红 —— 我把它改回 `0` 验过，红了。

另外两处是"看起来"的事，但它们各有各的理由：

1. **挂线不再从父方块正中间垂下去**：那条线会从中间穿过下面那些行（用户说的"向下后向右
   拐弯"正好是正确走法）—— 先在父方块底下横着挪到分支左边的一条竖道，顺着竖道往下，最后
   一支一支往右拐进去。分支缩进了一格，所以这条竖道正好落在它们左边；
2. **括号和那条竖道得看得出是两件事**（一个说"这是谁的分支"、一个说"从哪儿下来"）：所以
   括号贴着**挂点行的左边缘** 6dp，而不是"离分支半格" —— 后者会和竖道差 7dp，两根竖线并排
   看过去就是一根。

顺带给这个镜像加了一张 `--png` 预览：把样例图按镜像的布局画出来（方块 + 挂线 + 括号），
用眼睛看一遍骨架 —— 数字能证明结构对，证明不了"看着像不像那么回事"。
