# 操作与场地

> 手感、测试场这块地、部位怎么没、召唤到桌面。
>
> 这一篇原来在 README 里，2026-09-24 拆出来。README 是门面，这里是细节。

## 几点关于手感的说明

**物理回到了 0.18.0 的求解器，这是手感定的，不是数字定的（1.9.1）。**

从 1.0.0 到 1.9.0，为了治抖动一共加过五样东西：每帧限速（`MAX_IK_RATE`）、IK 增益
（`PIN_JOINT_GAIN`）、力臂保护（`LEVER_MIN`）、手指目标的低通（`PIN_TARGET_ALPHA`）、
以及"拎着/站着"两套地面模型（`carryFloor` / `hanging` + `CARRY_SINK`）。每一样都量过、
每一项都把 `tools/` 里的读数改好看了——其中 `LEVER_MIN` 那一版（1.8.0）确实把"抓关节时
整只宠物跟着一根 0.075px 的力臂转"修掉了。

**但把它们叠起来之后，宠物变成了"对手指有反应"而不是"挂在手指上"。** 所以做了一版
把求解器换回 0.18.0 的测试包（界面还是 1.9.0 的），拿手上比——结论很干脆：
**这一版真的更好，完全没有抖动。**

于是 1.9.1 的 `Ragdoll.kt` 逐行是 0.18.0 的求解器，只多了三样**不碰物理**的东西：
部位的 `collides` / `grabbable` 两个开关、`gravityScale` 重力倍率、以及调参面板要的
四段探针（只读 `rotation`）。

**两件要知道的事：**

1. ~~调参面板上的「IK 增益」和「IK 限速」是死的~~ —— **1.10.0 把它们删掉了。** 0.18.0 的求解器
   里没有这两个数，所以那两个滑杆只是"会动、数字会变、手感不变"；一个动不了任何东西的滑杆
   比没有滑杆更糟。面板现在只留它真能回答的东西：两个数字、四段探针、步进时间、CSV 导出。
   （跟着一起删的还有 CSV 里 `max_ik_rate` 和 `pin_joint_gain` 两列、手指目标那道低通——
   低通是给 1.9.0 的求解器准备的，0.18.0 直接用手给的坐标。）
2. **`tools/ragdoll.py`（Python 镜像）暂时不再描述这个文件**，`mirror_check` 会因此报错。
   这是**故意留着的红**：镜像说 0.18.0 的求解器变号率更差（15~31% vs 0~4%）、而拇指说
   它更稳，两个裁判打架时该被检查的是裁判。把镜像对齐到实际发货的这一套，是接下来的
   第一件事，而不是已经做过的事。

**被点一下，和"按了一会儿"是两件事。** 手指按下算「被抓」，抬手时如果又快又没怎么动，
再补一个「被点一下」。补的那一下有个窗口，原本是 **300ms**，而手机上一次**故意**的点
（不是飞快戳一下）常常要 200–400ms —— 于是有些点算数、有些不算，规则看起来"有时候灵
有时候不灵"。现在窗口是 **500ms**，也就是 Android 自己判定长按的那条线：过了这条线，
按就是按，不是点。而且**不算的时候测试场会写出来**（"点：按了 0.7 秒" / "手指挪了
34px"），因为这个事件是唯一一个不留痕迹的：规则没跑、日志里没有、什么都没发生。

**那条线的另一侧现在是一个事件：「被长按」。** 按住宠物不放，到 500ms 那一刻报一次
（`longPress`，带部位），再抬手不会补一个「被点一下」。所以手指落在宠物身上**有且只有
一种结果**：短的算点、长的算按 —— 而在这一版之前，按久了的下场是一句"你点得太慢"，
也就是说"按住不放"根本没有地方可以写。长按只认宠物，不认桌面：空画布按多久都只是平移
镜头。

**松垮的关节没有静摩擦。** 一个完全对称的松垮身体站在地上是**真平衡**，
会像雕像一样立着不动 —— 这是正确的物理，但不是一个"松垮"该有的样子。
所以加了两处刻意的非物理处理，都只在**松垮档 + 着地 + 几乎静止**时生效：

1. 极小的噪声（角度 2e-5 rad/步，根节点 0.6 px/s²），用来打破对称
2. 关节的**让位**：对自身偏角做正反馈。已经在偏的关节会继续偏，
   直到身体躺下（跨度小于站立时的 55% 就停止，否则永远停不下来）

角阻尼也从 1.4 降到 0.9 —— 1.4 让整个身体像在糖浆里动。

**抓住一个部位时，身体会真的吊下来。** 这件事一共错了四次，前三次是物理，第四次不是：

**第四次（真机上手仍然不倒吊的原因）：钉住的点根本不是你摸到的那一点。**
一根骨骼有个"关节"（头）和一个"末端"，而**大腿的关节就是胯**。
所以不管你是抓大腿中段还是抓膝盖，程序钉住的都是**胯** —— 等于拎着腰把它端起来，
头上再没有东西可以往下垂。现在钉的是**手指碰到的那一点**，沿着骨骼算一个偏移量。
这一条就是"拎着腿"和"拎着腰"的区别。

**还有一个：垮塌反馈在抓着的时候还在放。** 那是给"自己站在地上的软身体"用的，
和它自己的偏角成正反馈。抓着的时候它不该管事；而且那个式子对**根关节**来说，
等于"按身体当前朝向给一个几 rad/s² 的力矩" —— 那不是让位，是踹一脚。
现在抓着时不触发，根关节也永远不参与。

前三服是物理：

| 做法 | 为什么不行 |
|---|---|
| 在被抓的点上施加**力**（一般的 mouse joint） | 平衡态是退化的，身体会飘到天花板停住 |
| 只**平移根节点** | 精确，但手臂根本不用动，于是身体"站"在手指上方，而不是吊在下面 |
| 只做 CCD（每个关节朝手指转） | 能碰到手指，但它**不知道谁重**——髋关节和踝关节一视同仁，而转髋关节等于转动整具身体。于是拎起一只脚时它去转整个身体，然后每一帧再跟重力互相抵消 |

对的是**给根关节的旋转上一条短皮带**：根关节的旋转就是整具身体的朝向，重力对它有更强的发言权。
两个手指往外掰两条腿时需要它（髋自己的限位掰不开），但只能占很小的权重（`ROOT_PIN_GAIN = 0.15`）。
此外，**被一根手指拎着时，整具身体是绕那根手指的摆**——所以要在手指处补一个重力力矩，
否则身体只会把重心收到骨盆下面（蜷在手边），而不是收到手指下面。

根关节自己写的那对限位，是"地面"的替身，所以只在**没人抓它的时候**生效。
在空中自由落体时仍然保留——试过放开，结果每次落地都摊成一团。

**测试场现在把重心画出来了。** 吊着的身体，重心在手指下面；没吊起来的，重心在上面 ——
绿点 / 橙点，再加一条从手到重心的线。这件事看不见就没法调，所以它不该只活在代码里。

**第五次（这一轮的三个原因，是一个问题的三层。）**

1. **房间只有一层楼高。** 角色一千六百九十像素，地面在 1980 —— 从脚踝倒吊，
   手指底下得有整整一个身长，也就是说手要抬到接近天花板。手机上手指只有一块屏幕，
   抬不到那儿：头先碰到地板，然后地面干它该干的事，把脊椎拧开。**这就是"弯腰"。**
   现在房间在地面线上方多了**一个身长**的空气，角色站在**真正的地面**上
   （不是画布自己那条地平线）。骨骼坐标一个都没动：骨架仍然在画布坐标里来回存，
   不会每存一次往下漂一点。

2. **钉住的解法把身体留在了地上。** 链条解算总能靠弯点什么碰到手指 ——
   抓住脚踝往上提，它转的是胯：脚抬起来了，身体还站在另一条腿上，这就是"摆姿势"
   而不是"提起来"。现在**根节点也分一部分拉力**（`CARRY_GAIN`），
   所以身体跟着手一起走。

3. **关节只感受自己的子树。** 拎着脚踝的时候，胯的子树是两条腿，
   而躯干是挂在同一个根上的**另一根分支**，除了它自己的脖子以外没人感受得到它。
   于是胯没有理由把身体翻过来，躯干也没有理由垂下来。
   现在**手指在子树里的话，关节扛的就是"另一侧"的全部重量** ——
   被拎着的关节，是被另一边吊着的。

顺带，**地板对"已经被翻过来的身体"松手**：倒吊的身体可以垂到地平线以下，
而且地面不再去单独拧某根骨骼（那就是弯腰的来源）。
只是被拖着在地上走的身体，照旧落在地板上。

`tools/carry_check.py` 是新的，把这些全钉死了：**抬起四分之一个房间的高度，
它就会翻过来**；而且**抓腿上哪一段都一样**。

**第六次（房间变高之后，宠物从屏幕上消失了）。** 房间比画布深，角色要**用一个偏移站到
真正的地面上**，而我把这个偏移算成了自己减自己：给骨骼的位移是 `rootPos − rootHome`，
而 `rootHome` 里已经含了那一段空气 —— 两者相消，于是角色还是站在**画布**的坐标里，
也就是地面上方一千七百像素。它掉下去，落地速度又太快，而地面是**按"把最深的骨头转出地板"**
解决的，不是把整具身体抬起来，于是一路沉下去，屏幕上什么都没有。

现在位移是从**画布自己的原点**量的（`rigRoot`，"站的地方"是
`rootHome = rigRoot + 空气`），另外加了一道兜底：**整具身体都在地面线以下**时
把它放回地面 —— 宠物不见了是发现 bug 最糟糕的方式，而这条兜底只花十九次比较。

**可以同时抓好几个部位**：沙盒里每根手指各抓一个。落在角色身上的手指是"拉"，
落在空处的手指是"缩放"——劈叉和放大互不打扰。

**脚是个 68px 的胶囊**，等于一个真实的支撑面，所以它能站住。
如果你想要"一碰就倒"，把脚的 collider 半径调小即可。

## 关于部位能怎么没：隐藏、断开、接回

规则里有四个动作，管的是"这一节还在不在画面上"：

| 动作 | 做了什么 |
|---|---|
| **隐藏部位** | 把那一节的**图**藏起来。骨架和物理一点都不动——它还在、还有重量、还能被拖 |
| **显示部位** | 把藏起来的那张图放回去 |
| **断开部位** | 这一节**连同它下面所有子级**从世界里移除（抓不到、地面不托、没有重量），**再掉一整块在地上** |
| **接回部位** | 图重新画上，地上那块收走 |

「隐藏部位」原来叫「打坏部位」，但它从来没打断过任何东西——它实现的一直是隐藏，
所以名字改成了它真正做的事；`break` 这个代号没变，老文件照样读得懂。
加「显示部位」是因为**只能藏不能显的动作是个单向门**，和"打开状态/关闭状态"那一对是一个道理。

**「断开」是"这一节真的不在了"**，不是"不画了"。一个状态（`Ragdoll.setGone`）带三个后果，
因为它们本来就是同一句话：

- **手指穿过去**：抓取命中会跳过它，于是你抓到的是它后面那根骨头（一根看不见的骨头挡在
  前面、还能被抓，是这一版最早漏掉的一条）；
- **地面不托着它**：断了一条腿的宠物不会站在那条看不见的腿上；
- **它没有重量**：身体会朝缺的那一侧倒。
- 另外，**正抓着它的手指会松开**（捏着一根不在的东西，等于拖空气）。

掉下去的那块会**带着关节当时的动量**飞出去（所以从一只正在被甩出去的宠物身上扯下来的手，
会朝它本来飞的方向去），落到地面线就停住，滑一小段、转速衰减到停。

**「断开」断的是整条肢体**：命名的那一节连同**它下面所有子级**一起走——断一条胳膊掉的是整条胳膊，
不是一个挂在空中的前臂。掉下去的那一块按**同一个刚体运动**画（绕它被扯断的那个关节转，所有子级
的相对位置都保留着），所以肘和手还在原来的地方。

**那块碰撞箱是自动的**：它带着**自己的骨头**走——断开的那一刻把每根骨头的胶囊量下来（头、尾、
碰撞半径，都相对被扯断的那个关节），此后地面、身体和手指看到的都是**这条肢体本身**，不是一个
包住它的大圆。一版之差是这样的：一个圆会让胳膊**浮在地面上方一整条胳膊的高度**、被身体从老远
推开、还能隔空捡起来。三条都来自同一个错误——把"这块有多大"当成了一个数。

**掉在地上的那块还能玩**（"断开的部位应仍能互动"）：

- **手指能把它捡起来拖**（它画在最上面，所以手指落在谁身上就是谁），松手时把它按手指的速度扔出去；
- **第二根手指转它**（像相册里转照片：第二根手指绕着它的角度就是转过的角度）。没有这一条，
  一块碎片只能平移——**放不回另一个面朝上，落地之后角度就冻死了**；
- **和身体是双向的**：身体把它推开，它**也推身体**——所以一条断胳膊落在宠物背上会把它**压动**，
  从高处砸下来会把它砸得一颤。推身体走的是 `Ragdoll.impulse`（求解器唯一对外的门），
  按接触深度算、有上限：搭着是"一直轻轻推"，砸下来是"推一下重的"。
  （一开始这里只做了单向，理由是"断手不该摇动宠物"——那不是量出来的，只是整齐；你要的是另一种。）

**剩下的取巧只有一条，而且看不见**：那根骨头的关节还在骨架里空转（它自己的角度还在积分），
因为把它彻底切掉意味着把身体拆成两个刚体，而这套求解器从头到尾只有一个根。

（`tools/` 里没有它的镜像测试：残肢是测试场自己的东西，不在求解器里，也没有第二个实现
要和它比。物理那半边仍然由 ragdoll/drag/carry 那几套盯着。）

## 关于测试场这块地

它是一间**屋**，不是一张画：画布（`canvas`，1024×2048）只是图需要多大，
**房间**由 `physics` 说了算——

| | 值 | 意思 |
|---|---|---|
| `worldWidth` | 6144 | 左右墙之间。**6 个画布宽**，不是 3 个 |
| `floorY` | 1980 | 地面线（画稿自己的脚底） |
| `ceilingY` | -1600 | **屋顶**。0 是画稿的上边缘，也就是每只角色一直以来的屋顶 |

改前是 3072 × 1980：横着 2.3 个身位、竖着 1.5 个——**一只宠物被扔上去，两个身长就顶到一块没人画过的天花板**。
现在是 6144 × 3580（y −1600…1980）：横 4.6 个身位、竖 2.65 个。

屋顶是 1.10.1 才有的东西：求解器里那个 `ceiling` 原本是写死的 `0f`，相机也只允许看到 y ≥ 0。
现在它来自角色文件（缺省还是 0，所以老角色一个像素都不变），相机和网格跟着它走。
**默认缩放没有跟着变小**——它一直是"把地面那一段塞进屏幕"，所以场地变大不会让宠物变小；
多出来的空气在屏幕外，扔上去的时候跟手相机自己会往上跟。

## 关于召唤到桌面：一只浮在别的 App 上面的桌宠

侧栏**最下面**那个按钮（**召唤到桌面**）把场上的那只送到桌面上：它浮在你正在用的任何
App 上面，**整块屏幕都是它的地盘**（世界就是屏幕，地面就是屏幕底边）。再点一下那个按钮
（或者控制条上的 **收回**，或者通知上的同名按钮）就送它回家。

- **左上角有一条小控制条**：**可摸宠物 / 点得穿**、**收回**。这两件事必须分开，因为宠物那
  一层是满屏的 —— 一直收触摸的话，底下的 App 就等于被一块透明玻璃盖住了。点「穿透」：
  宠物继续画着、继续按自己的规则动，手指全部穿过去。它自己必须在**另一层窗口**上，不然
  穿透之后就没有东西能把它切回来；
- **穿透为什么光是设个标志不够（1.16.0 修）**：Android 12 起有一条**不可信触摸**规则 ——
  从**不透明**的悬浮窗穿过去的触摸会被系统**直接丢掉**（logcat 里是
  `Untrusted touch due to occlusion by <包名>`）。`TYPE_APPLICATION_OVERLAY` 明确不算
  可信窗口，而"够不够透明"看的是**窗口自己的 alpha**：一组系统警告窗的合成不透明度
  **大于 0.8** 就不放行（Android 12 的默认上限就是 0.8）。我们这个窗口是满屏的、alpha 是 1，
  所以标志设对了、按钮也切了、控制条上的字也变了，**手指还是穿不过去，而且什么都不报**
  —— 这正是"切换功能了也不行"。
  现在穿透时把**两个窗口**（宠物那层和控制条）的 alpha 一起压到 **0.79**：宠物会淡 20%，
  换来的是"点得穿"真的点得穿。可摸时 alpha 回到 1（不透明）。另外 `updateViewLayout` 失败
  （窗口被系统收走过）会**重新挂一次**，两样都没成的话状态**不会假装已经切了**，并且弹一句
  说明 —— 一个说不了话的开关比没有这个开关更糟。
- 抓它、甩它、点它、长按它，和测试场里一模一样（同一套物理、同一套规则、同一个长按事件）；
- **长按侧栏那个按钮**会弹出一个菜单：**召唤道具 / 切换状态 / 摆动作 / 换骨骼套 / 收回**，
  作用于**桌面上那一只**（它在别的 App 上面，够不着它自己的按钮，所以这些开关挂在送它出去
  的那个按钮上）；
- **第一次点它会先要一个权限**：Android 的「显示在其他应用上层」只能由用户在系统设置里给，
  App 只能解释并把你带到那一页（`SYSTEM_ALERT_WINDOW`）。它是**前台服务**，所以桌宠在
  桌面上时一直有一条通知 —— 那也是"收回"的第二条路；
- **两句得写在明面上的话**：①桌面上那只和 App 里那只是**同一个宠物的两个实例** ——
  规则各跑各的（你在 App 里看的时候，桌面上那只并不会暂停），数值和状态从各自加载那一刻
  起就是两份；②**它不存档**：桌面上发生的事不写文件，收回就没了。对一个随时会被收走的
  玩具来说，这是诚实的行为；**要"跑起来的宠物"，用测试场**；
- 悬浮窗只画宠物本身：网格、地面线、调参面板这些**屋子的家具**在桌面模式下不画
  （`setDesktopMode`），拖空白处也不平移镜头（世界就是屏幕，没有"窗外"可看），其余一切照旧；
- **它跟着全局设置走**，而且是**现在**的设置：召唤时读一次，你在 App 里改设置时再推一次；
- **它是同一只，也是同一套身体**（1.15.2 修）。召唤记住的不只是哪一只宠物，还有它**正穿着
  哪套骨骼**：动作预设（`poses.json`）是**按套**存的，身体记错了，规则里那些动作名在这一边
  一个都对不上 —— 而那个症状（"桌面上不摆动作"）看起来像动作功能坏了；
- **预设动作两个实例都拿得到**（1.15.2 修）。动作表以前是**另设**的（一个 `setPoseNames`
  调用），测试场设了、桌面那一只（第二个实例）没设：规则「摆动作 挥手」在测试场好好的，
  召唤到桌面上就**什么都不发生** —— 更糟的是它会**把宠物弄瘫**（查不到名字 → `null` →
  `clearPose`）。现在动作表是 `load` / `swapRig` 的**参数**（没有默认值，忘了就编译不过），
  而"按名字摆动作"查不到时什么都不做，并且在日志里留一句；菜单里挑动作时如果这一套身体
  没有那个名字，会弹一句说明；
- **召唤时它接着摆测试场上那个动作**。
  这里有一个具体的坑值得记下来：`applySettings` 只管重力、特效那些开关，**刚度是另一个
  属性** —— 少了那一句，设置里选"半软"、召唤出来却是全松垮（它停在 0）。
