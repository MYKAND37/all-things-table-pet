# All Things Table Pet

把桌宠做成一个**平台**，而不是一个会动的图片。

## 这个项目想做什么

| 方向 | 用户能做什么 |
|---|---|
| **部件化角色** | 不画整只角色，而是**画一个部位传一个**（一只手臂、一条腿），系统拼装成角色 |
| **可视化逻辑** | 不写代码，用搭积木的方式定义「**触发事件 → 判断条件 → 做出反应**」 |
| **道具系统** | 自定义道具（持续使用 / 装置 / 投掷 / 射击），并让道具和角色产生互动 |

## 架构

```
用户操作（手势 / 拖道具）
        ↓
   道具物理（弹道、持续接触、装备）
        ↓
   命中判定（打到哪个部位？）
        ↓
┌───────────────────────────────────┐
│  事件系统   谁在什么时候发生了什么    │  ← 带时间戳，可回溯
└───────────────┬───────────────────┘
                ↓
        角色数值 H / S / P / SH …       ← 被事件改写
                ↓
        规则层（用户连线的逻辑）          ← 条件 → 动作
                ↓
┌───────────────────────────────────┐
│ 对话类（气泡）│动作类（动画）│状态类（部位状态）│
└───────────────┬───────────────────┘
                ↓
           表现层：骨骼 / 图层 / 物理动画
```

## 几点关于手感的说明

**物理回到了 0.18.0 的求解器，这是手感定的，不是数字定的（1.9.1）。**

从 1.0.0 到 1.9.0，为了治抖动一共加过五样东西：每帧限速（`MAX_IK_RATE`）、IK 增益
（`PIN_JOINT_GAIN`）、力臂保护（`LEVER_MIN`）、手指目标的低通（`PIN_TARGET_ALPHA`）、
以及"拎着/站着"两套地面模型（`carryFloor` / `hanging` + `CARRY_SINK`）。每一样都量过、
每一项都把 `tools/` 里的读数改好看了——其中 `LEVER_MIN` 那一版（1.8.0）确实把"抓关节时
整只宠物跟着一根 0.075px 的力臂转"修掉了。

**但把它们叠起来之后，宠物变成了"对手指有反应"而不是"挂在手指上"。** 所以做了一版
把求解器换回 0.18.0 的测试包（界面还是 1.9.0 的），拿手上比——结论很干脆：
**这一版真的更好，完全没有抖动。**

于是 1.9.1 的 `Ragdoll.kt` 逐行是 0.18.0 的求解器，只多了三样**不碰物理**的东西：
部位的 `collides` / `grabbable` 两个开关、`gravityScale` 重力倍率、以及调参面板要的
四段探针（只读 `rotation`）。

**两件要知道的事：**

1. ~~调参面板上的「IK 增益」和「IK 限速」是死的~~ —— **1.10.0 把它们删掉了。** 0.18.0 的求解器
   里没有这两个数，所以那两个滑杆只是"会动、数字会变、手感不变"；一个动不了任何东西的滑杆
   比没有滑杆更糟。面板现在只留它真能回答的东西：两个数字、四段探针、步进时间、CSV 导出。
   （跟着一起删的还有 CSV 里 `max_ik_rate` 和 `pin_joint_gain` 两列、手指目标那道低通——
   低通是给 1.9.0 的求解器准备的，0.18.0 直接用手给的坐标。）
2. **`tools/ragdoll.py`（Python 镜像）暂时不再描述这个文件**，`mirror_check` 会因此报错。
   这是**故意留着的红**：镜像说 0.18.0 的求解器变号率更差（15~31% vs 0~4%）、而拇指说
   它更稳，两个裁判打架时该被检查的是裁判。把镜像对齐到实际发货的这一套，是接下来的
   第一件事，而不是已经做过的事。

**被点一下，和"按了一会儿"是两件事。** 手指按下算「被抓」，抬手时如果又快又没怎么动，
再补一个「被点一下」。补的那一下有个窗口，原本是 **300ms**，而手机上一次**故意**的点
（不是飞快戳一下）常常要 200–400ms —— 于是有些点算数、有些不算，规则看起来"有时候灵
有时候不灵"。现在窗口是 **500ms**，也就是 Android 自己判定长按的那条线：过了这条线，
按就是按，不是点。而且**不算的时候测试场会写出来**（"点：按了 0.7 秒" / "手指挪了
34px"），因为这个事件是唯一一个不留痕迹的：规则没跑、日志里没有、什么都没发生。

**那条线的另一侧现在是一个事件：「被长按」。** 按住宠物不放，到 500ms 那一刻报一次
（`longPress`，带部位），再抬手不会补一个「被点一下」。所以手指落在宠物身上**有且只有
一种结果**：短的算点、长的算按 —— 而在这一版之前，按久了的下场是一句"你点得太慢"，
也就是说"按住不放"根本没有地方可以写。长按只认宠物，不认桌面：空画布按多久都只是平移
镜头。

**松垮的关节没有静摩擦。** 一个完全对称的松垮身体站在地上是**真平衡**，
会像雕像一样立着不动 —— 这是正确的物理，但不是一个"松垮"该有的样子。
所以加了两处刻意的非物理处理，都只在**松垮档 + 着地 + 几乎静止**时生效：

1. 极小的噪声（角度 2e-5 rad/步，根节点 0.6 px/s²），用来打破对称
2. 关节的**让位**：对自身偏角做正反馈。已经在偏的关节会继续偏，
   直到身体躺下（跨度小于站立时的 55% 就停止，否则永远停不下来）

角阻尼也从 1.4 降到 0.9 —— 1.4 让整个身体像在糖浆里动。

**抓住一个部位时，身体会真的吊下来。** 这件事一共错了四次，前三次是物理，第四次不是：

**第四次（真机上手仍然不倒吊的原因）：钉住的点根本不是你摸到的那一点。**
一根骨骼有个"关节"（头）和一个"末端"，而**大腿的关节就是胯**。
所以不管你是抓大腿中段还是抓膝盖，程序钉住的都是**胯** —— 等于拎着腰把它端起来，
头上再没有东西可以往下垂。现在钉的是**手指碰到的那一点**，沿着骨骼算一个偏移量。
这一条就是"拎着腿"和"拎着腰"的区别。

**还有一个：垮塌反馈在抓着的时候还在放。** 那是给"自己站在地上的软身体"用的，
和它自己的偏角成正反馈。抓着的时候它不该管事；而且那个式子对**根关节**来说，
等于"按身体当前朝向给一个几 rad/s² 的力矩" —— 那不是让位，是踹一脚。
现在抓着时不触发，根关节也永远不参与。

前三服是物理：

| 做法 | 为什么不行 |
|---|---|
| 在被抓的点上施加**力**（一般的 mouse joint） | 平衡态是退化的，身体会飘到天花板停住 |
| 只**平移根节点** | 精确，但手臂根本不用动，于是身体"站"在手指上方，而不是吊在下面 |
| 只做 CCD（每个关节朝手指转） | 能碰到手指，但它**不知道谁重**——髋关节和踝关节一视同仁，而转髋关节等于转动整具身体。于是拎起一只脚时它去转整个身体，然后每一帧再跟重力互相抵消 |

对的是**给根关节的旋转上一条短皮带**：根关节的旋转就是整具身体的朝向，重力对它有更强的发言权。
两个手指往外掰两条腿时需要它（髋自己的限位掰不开），但只能占很小的权重（`ROOT_PIN_GAIN = 0.15`）。
此外，**被一根手指拎着时，整具身体是绕那根手指的摆**——所以要在手指处补一个重力力矩，
否则身体只会把重心收到骨盆下面（蜷在手边），而不是收到手指下面。

根关节自己写的那对限位，是"地面"的替身，所以只在**没人抓它的时候**生效。
在空中自由落体时仍然保留——试过放开，结果每次落地都摊成一团。

**测试场现在把重心画出来了。** 吊着的身体，重心在手指下面；没吊起来的，重心在上面 ——
绿点 / 橙点，再加一条从手到重心的线。这件事看不见就没法调，所以它不该只活在代码里。

**第五次（这一轮的三个原因，是一个问题的三层。）**

1. **房间只有一层楼高。** 角色一千六百九十像素，地面在 1980 —— 从脚踝倒吊，
   手指底下得有整整一个身长，也就是说手要抬到接近天花板。手机上手指只有一块屏幕，
   抬不到那儿：头先碰到地板，然后地面干它该干的事，把脊椎拧开。**这就是"弯腰"。**
   现在房间在地面线上方多了**一个身长**的空气，角色站在**真正的地面**上
   （不是画布自己那条地平线）。骨骼坐标一个都没动：骨架仍然在画布坐标里来回存，
   不会每存一次往下漂一点。

2. **钉住的解法把身体留在了地上。** 链条解算总能靠弯点什么碰到手指 ——
   抓住脚踝往上提，它转的是胯：脚抬起来了，身体还站在另一条腿上，这就是"摆姿势"
   而不是"提起来"。现在**根节点也分一部分拉力**（`CARRY_GAIN`），
   所以身体跟着手一起走。

3. **关节只感受自己的子树。** 拎着脚踝的时候，胯的子树是两条腿，
   而躯干是挂在同一个根上的**另一根分支**，除了它自己的脖子以外没人感受得到它。
   于是胯没有理由把身体翻过来，躯干也没有理由垂下来。
   现在**手指在子树里的话，关节扛的就是"另一侧"的全部重量** ——
   被拎着的关节，是被另一边吊着的。

顺带，**地板对"已经被翻过来的身体"松手**：倒吊的身体可以垂到地平线以下，
而且地面不再去单独拧某根骨骼（那就是弯腰的来源）。
只是被拖着在地上走的身体，照旧落在地板上。

`tools/carry_check.py` 是新的，把这些全钉死了：**抬起四分之一个房间的高度，
它就会翻过来**；而且**抓腿上哪一段都一样**。

**第六次（房间变高之后，宠物从屏幕上消失了）。** 房间比画布深，角色要**用一个偏移站到
真正的地面上**，而我把这个偏移算成了自己减自己：给骨骼的位移是 `rootPos − rootHome`，
而 `rootHome` 里已经含了那一段空气 —— 两者相消，于是角色还是站在**画布**的坐标里，
也就是地面上方一千七百像素。它掉下去，落地速度又太快，而地面是**按"把最深的骨头转出地板"**
解决的，不是把整具身体抬起来，于是一路沉下去，屏幕上什么都没有。

现在位移是从**画布自己的原点**量的（`rigRoot`，"站的地方"是
`rootHome = rigRoot + 空气`），另外加了一道兜底：**整具身体都在地面线以下**时
把它放回地面 —— 宠物不见了是发现 bug 最糟糕的方式，而这条兜底只花十九次比较。

**可以同时抓好几个部位**：沙盒里每根手指各抓一个。落在角色身上的手指是"拉"，
落在空处的手指是"缩放"——劈叉和放大互不打扰。

**脚是个 68px 的胶囊**，等于一个真实的支撑面，所以它能站住。
如果你想要"一碰就倒"，把脚的 collider 半径调小即可。

## 关于逻辑：当 → 如果 → 就

**逻辑管理**现在是一张节点图：可以平移、可以缩放，**点任何一个方块改它**。
一条规则就是一行从左到右的链子：

```
┌────────────────────┐
│ 当：被甩出去        │   ← 点开选事件
└─────────┬──────────┘
          │
┌─────────▼──────────┐
│ 如果：生命 > 0      │   ← 点开改条件
└─────────┬──────────┘
          │
┌─────────▼──────────┐
│ 就：说「哇啊——！」  │   ← 点开改动作
│     痛苦 +20        │
└────────────────────┘
＋如果  ＋就  部位 全身   |   冷却 1.0s  只一次  删规则
```

为什么是图不是卡片列表：卡片列表说的是同样的东西、同样的顺序，而问题就出在这儿 ——
**一列卡片读起来是"一堆东西"，而一条规则不是一堆东西，是一条有方向的链子**，
方向恰恰是难看见的那部分。

方块本身很笨：它只知道自己要显示什么字、以及被点的时候报哪条规则的哪个节点。
规则**是什么意思**在引擎里，方块**写什么字**是构建它的人决定的 ——
所以画的部分可以靠眼睛检查，而意思的部分完全不在 Canvas 的子类里。

### 一套逻辑是给谁的：角色、道具、液体、**部件**

规则是同一套规则，**但"当"和"就"两边都要知道自己在说谁**。所以逻辑面板是**三层**的：

```
                     ┌ 桌宠A ● │ 桌宠B │ 道具 ┐   ← 第一层：文件夹，在图右上角
  角色 │ 部件 │ 粒子 │ 液体                        ← 第二层：这只桌宠的哪一类
  角色 │ hand_L │ head │ …                        ← 第三层：这一类里的哪一个
```

- **第一层是文件夹**，因为"每样东西的规则住在它自己的文件夹里"这件事在界面上也该看得见：
  一只桌宠一个文件夹（● 是"这只正在场上"），外加一个全局的**道具** —— 道具的规则是所有
  桌宠共用的，它不属于任何一只。放在**图的右上角**，免得和一排模块按钮混成一条横栏；
- **第二层**是这只桌宠的四类：**角色**（它自己）/ **部件**（它的每根骨头和每个节点）/
  **粒子** / **液体**（它声明的那几种）；
- **第三层**才是具体写给谁。点进去就是原来那张规则图，一行没变。

**编辑哪一只不需要把它召唤出来**：文件夹选的是"谁的东西"，测试场上是"谁在动"，
两件事分开，所以可以给一只没上桌的宠物写规则。**每样东西的规则住在它自己的文件夹里**：

```
characters/<角色>/logic.json                       角色自己的规则
characters/<角色>/liquids/<液体>/logic.json         一种液体的规则
characters/<角色>/parts/<骨骼>/logic.json           一个部件的规则（和它的图并排）
props/<道具>/logic.json                            一个道具的规则（所有角色共用）
props/object-logic.json                            旧的：全挤在一个文件里（只读，搬家前的）
```

**搬家是加法，不是减法**：读的时候新位置优先，**新位置没有才回退到旧文件**；
写的时候只写新位置，旧文件一辈子不动（那是用户的数据，不是我们的缓存）。
所以升级不会丢任何规则，而每个主体存过一次之后旧文件就自然退休了。

（唯一要小心的那条：**新位置存在但是空文件，不回退**。空的意思是"这个东西没有规则"，
不是"没找到"——回退就等于应用把用户删掉的规则又装回去。这条在这个项目里踩过一次，
所以 `tools/store_check.py` 现在同时盯着它。）

**部件是主体**，这是"让手流汗"变成一条规则的关键：它写在**手**这个主体上，
而不是写在角色身上、每次判定都问一遍"这是不是手"。部件自己的规则

- 听得到**发生在那个部件身上**的事（被抓、被打到、被道具碰到……规则里的"部位"照样可以写前缀，`hand` 管左右两只手）；
- 也听得到**发生在整具身体**上的事（被甩出去、落地、被点一下——手当然也是被扔出去的那具身体的一部分）；
- **听不到别的部件的事**，也听不到道具的事。

"喷粒子""喷液体""说一句话"这些动作，在没有指名部位时会**落在主体自己身上** ——
所以一条长在手上的、每隔一会儿就"喷粒子 汗"的规则，汗就落在手上。

（这一步只加了主体：规则先存在老地方。状态的两级、以及"每种东西一个文件夹"
见 `docs/PART_SUBJECTS.md`，那是接下来的两步。）

**为什么不用两套编辑器**：一支蜡烛烧完和一只角色流血，都是同样三个盒子写出来的。
两套界面意味着两套都要维护、两套都要学，而它们的区别其实只有"谁"。

道具和液体自己的事件：

| 事件 | 什么时候 |
|---|---|
| 出现时 | 这个道具第一次被放上桌子 / 这种液体第一次被喷出来 |
| 每隔一会儿 | 只要它还在场上 |
| 落地 | 它刚碰到地面 |
| 被打到 | 它撞到了角色，`部位` 是被撞到的那一节 |

**一个引擎只在这个主体真的在场上时才跑**：不然一支没人点的蜡烛会自己烧完 ——
"它在不在"是每个客体规则本来都得自己写一遍的条件，所以这一步由引擎替它做掉。

**「落地」这一行现在是真接上了的，而且只是最近才接上。** 表写了很久，但测试场里从来
没有人把事件送给 `liquid:<id>`：液体的引擎一辈子只见过「出现时」和「每隔一会儿」，
所以任何一条 `当 落地` 的液体规则都是死的 —— 不报错、不写日志，就是不发生。
现在液体按名字收「落地」，`值` 是这一帧有多少滴落地（和粒子一个形状：一次喷出来的
四十滴是一声，不是四十条规则）。

判定是**这个液滴第一次被地面拦住**，一辈子只报一次，而这句话本身是量出来的：先试
「它在地上」——静止的水洼每帧都成立，等于每秒六十次；再试「落下的速度够快」——水洼
第二层的滴被邻居挤下去时速度正好 300px/s，120 滴的水洼十秒里误报 8 次；再试「它至少
落了一个滴的高度」——从堆顶滑下来的滴是真的落下来了，可它不是新到的液体。「第一次」
既不会漏也不会重，因为一滴东西只可能第一次到地上一次。

反过来，**角色也能对道具动手**：「推一下道具」（选道具 + 力度 + 方向）和
「清掉道具」。这就是"这些东西可以成为客体"的另一半 ——
客体有自己的逻辑是一件事，角色的逻辑能够伸手动它是另一件事，两件加起来才是一个系统。

道具和液体自己说「说一句话」时，**气泡画在它自己头上**，粒子、液体也喷在它自己的位置。
同一份动作列表，从蜡烛的规则里跑出来烧的是蜡烛，不是宠物。

### 并行分支：一个侦测器，岔开若干执行器

「并行逻辑也有完整的侦测器和执行器，箭头是向下指过去的，就是岔开」。

    当：被点一下 ─┬─ 就：说「干嘛？」
                  ├─ 就：说「别戳我」
                  └─ 就：哭

- 一条**带分支的规则就是一个并行组**，它自己有完整的三个盒子：自己的「当」是组的侦测器，
  自己的「如果」是组的条件，自己的「就」是**第一支**执行器，`branches` 里每一项是另一支；
- **每一支都执行**，按写下的顺序 —— 全部响，不掷骰子；
- **分支有自己的「当」**：它等自己的事件，和组的那条**并行地**等（不是"组的当也成立"时
  才被看一眼 —— 第一版写反过，镜像当场抓到）。分支的冷却和「只发生一次」用**组自己的**：
  一个组是一件事，两个执行器各走各的节奏不是谁要的功能；
- **分支有自己的「如果」**：组说了"是"之后，这一支再问自己一句。问不过就只有**这一支**
  安静，别的支照旧；
- **「否则」不岔开**：条件不成立是另一条路，一个没响的侦测器上挂不了分支；
- 图上画成**岔开**：从侦测器那个盒子底下拉一条竖线下来，每一支一行横着接过去带箭头；
  分支行上的三个盒子（当 / 如果 / 就）点开改的都是**那一支自己的**；
- 存档：没有自己东西的分支还是一个扁平数组（它就是一个执行器）；带自己的当或如果的写成
  `{"on":…, "part":…, "if":[…], "then":[…]}`，两种都读。

（1.11.9 换掉的是原来那套**随机组** —— 同组每次只响一条、随机挑一个。那东西是一个**名字**，
没有地方挂自己的侦测器和执行器，而"并行"要的是每条支线都是一条自己的线。老文件里的组现在
会变成"两条都响"，这正是换掉它的意思。）

（镜像里钉了十八条：全响、顺序、没有分支时和以前一样、组的条件不成立时只有否则响、
带自己的当的分支不被组的当带动、它自己的事件来了才响、部位不对不响、条件不成立的那一支
不跑而别的支照旧、互斥的两支只响成立的那一支、带自己的当的分支如果不过时**不消耗组的
冷却**、以及文件格式的两半 —— 解析读 `"if"`、落盘写 `"if"`、有如果的分支不写成裸数组。）

### 还没碰到它：靠近 / 走开

「被道具碰到」只在**已经碰到**之后才存在，所以"躲开锤子"以前根本写不出来 —— 规则跑起来
的时候锤子已经砸上了。现在多了两个事件：

| 事件 | 什么时候 | 值 |
|---|---|---|
| **有东西靠近** | 某个道具**第一次**进到身边（两个表面之间 90px 以内） | 还剩多少空当 |
| **有东西走开** | 那个道具又出了这个范围 | 离开时的空当 |

- 量的是**同一个胶囊**：最近的那根骨头、减去两个半径 —— 和碰撞用同一套几何，所以「靠近」
  和「碰到」不会对"在不在同一个地方"给出两个答案；
- 事件**带着是哪个道具**（所以规则可以点名锤子，而不是"任何东西靠近都躲"），`部位`是离它
  **最近的那根骨头** —— 写前缀（`hand`）就是"离手近"。它也是**走开**时说的那根骨头，
  所以"往哪边走的"是量出来的，不是猜的；
- **是一个变化，不是一个状态**：站在旁边不动只报一次。要"一直待在旁边"就写「每隔一会儿」
  加一个条件 —— 一个每帧都响的侦测器会让没有冷却的规则一秒响六十次；
- **回来要出得更远一点**（90 × 1.6 = 144px）才能再算一次靠近：停在边界上的道具，身体还在
  呼吸，不能一进一出地抖；
- **关掉碰撞的骨头不算靠近**（和碰到那边同一条约定），**道具从世界里消失不算走开**
  （子弹过期、蜡烛烧完 —— 它没去任何地方，只是不在了）。

**阈值暂时是固定的 90px**，大约一只手的长度（`hand_L` 从手腕到指尖是 100px）：
引擎里还没有"比较事件里的数值"这种条件（`value` 现在只写进日志），一条能说"比 40 更近"的
规则需要规则自己带一个阈值字段 —— 那是另一件有名字的事，不是一个偷偷加上的旋钮。

### 规则可以点名「是谁」

事件里一直带着**是哪个道具**（被道具碰到）或**哪种粒子**（粒子的落地），日志里从 1.10.2 起
也写出来了——"被道具碰到"单独一行是整份日志里唯一答不出"这条规则想问什么"的那种行，
锤子的规则和球的规则读起来一模一样。

缺的那一半是**规则能不能点名**。现在能了：一条规则的「关于谁」可以是任何东西、某一件道具、
或某一种粒子。

    当：被道具碰到 ─▶ 关于谁：锤子 ─▶ 就：说「哎哟」

**两个名字都不写就是"任何东西"**（老规则一个字节都没变），点名的规则只在事件真的来自它时触发。
界面上这一行只出现在**真能带着主语**的三种事件上：被道具碰到、被打到、落地——别的时候给
一个永远匹配得上的筛子是噪音。

（镜像里钉了四条：空 = 任何道具都能触发、点名之后只认那一个、粒子的落地同样、别的粒子不会误触发。
把筛子从引擎里拿掉，第二条立刻红。）

### 有两种问题，答案在世界里

如果里的条件一直是"角色身上的数字"和"它自己的开关"。但有两类问题不在这两处：

| 条件 | 问的是 | 参数 |
|---|---|---|
| **部位** | 「手**比**肩膀**高**」——两节在屏幕上的相对位置 | 哪一节、比哪一节、更高 / 更靠左、至少差多少像素 |
| **绳子** | 「这一节**有没有被绳子连着**」 | 哪一节（留空 = 身上任何一处都算）、连着 / 没连着 |

答案是**测试场给的**：引擎自己不知道骨头在哪、更不知道谁被绳子拴着，所以它拿着一个
`Facts`（`RuleEngine.Facts`）去问世界 —— 而**比较留在引擎里**（哪个方向、多少像素余量）。
这样"手比肩膀高 30 像素"是一条规则，而一份没有世界的引擎（本地镜像、编辑器）照样能回答
"它会怎么说"。

**没有世界可问时，这两种条件读作不成立** —— 和"未知种类的条件"同一条规矩：新版本写的
规则不能让老版本整个文件停摆。

两个细节值得写下来：

- **屏幕坐标 y 向下**，所以"更高"是 y **更小**。这种符号在静止姿势里看不出来，换一个姿势
  就全反 —— 镜像里钉了六条（高/放下、余量 10px 不够 30px 够、靠左比的是 x、有一节不在场上、
  没有世界可问）；
- **前缀照样管用**：条件里写 `hand`，左右两只手被连着都算 —— 和规则里"部位"的其它地方一样。

### 规则也能改画画的顺序：改变部位深度

「就」里多了一个动作：**改变部位深度**（哪一节 + 拉到最前面 / 压到最后面）。

图层深度本来是文件里的一行（`layers` 的 z），规则改不了它，**也不该改** —— 那是用户画的
顺序。所以这是**运行时的覆盖**：只影响这一次会话怎么画，收回测试场、换骨骼套、重新加载都
回到文件里的顺序。"抬手时袖子该在胸前面、手放下时该在后面"就是它。

### 条件是一个一个加上去的模块

**「如果」不是一格，是一串。** 每个条件是一个模块；条件之间那个 **而且 / 或者**
也是模块 —— 它有自己的小方块，点一下就翻过来：

    当：每隔一会儿 ─▶ 如果：痛苦 ≥ 60 ─▶(而且)─▶ 如果：状态 穿着 开着
                  ─▶(或者)─▶ 如果：生命 ≤ 20 ─▶ ＋加一个条件
                  ─▶ 就：说「……」 ─▶ ＋加一个动作

- **「当……就」**：一个条件都不加，就是"总是"。图上那个方块写着「总是」。
- **「当……如果……而且……就」**：加两个条件，中间那个连接词是「而且」。
- **「当……如果……就……否则」**：点最右边的「＋加一个否则」。
- **每个方块都能改、能删；没有的模块用「＋」点出来。**

读法是**从左往右，而且比或者紧**：上面那条读作
(痛苦 ≥ 60 而且 穿着) 或者 (生命 ≤ 20)。规则在**任何一组**成立时触发 ——
这跟任何人写 a and b or c 时的预期是一样的。

以前这里只有一个「如果」格子，**所以"如果……而且……"根本写不出来** ——
不是难写，是没有地方写。

### 「就」后面可以跟一个事件模块

动作里有一个 **发一个信号**。信号是规则自己的事件：一条规则「就」发出它，
另一条规则的「当」接住它（事件列表里的 **收到信号**，名字填在"信号"那一栏）。

于是「被打到 → 等一下 → 说一句话 → 打开状态」可以写成几条各自很短、互相叫名字的规则，
而不是一串必须从头读到尾才知道在干什么的动作。**不写信号名就接住所有信号**，
写前缀就接住同一族。

信号是**排队**发的，不是立刻递归：「当 X 就 发 X」一行就能写出来，
但跑起来是无限递归 —— 排队加上每帧 32 个的上限，把它变成一个"发着发着就没人听了"的信号，
而不是一个崩溃。

**「如果」可以有另一半：「否则」。** 条件不成立时做什么，是另一串动作。
没有「否则」的规则保持老行为：条件不成立就整个跳过，**连冷却都不消耗** ——
所以它可以条件一成立就立刻触发。有「否则」的规则两条路都会走，
冷却管的是**走过的那条**，不然"疼就哼一声、不疼就安静"会每半秒哼一次。

**动作里还有一个「跳到规则」。** 信号是规则之间互相叫名字，但那是**排队**的——
要过一个事件循环才到。跳到规则是**立刻**的：控制权当场交给第 N 条规则，同一帧里继续跑。

三点是刻意的：

- **当和部位不检查。** 跳过去的目标不必是被同一个事件触发的，不然跳转就只是把规则写了两遍，
  而不是够得着它——跳到一条「当 是 每隔一会儿」的规则，从「被点一下」那里跳过去，是通的。
- **目标自己的一切照算。** 它的「如果」决定走「就」还是「否则」，它的冷却和「一次」照常消耗。
  被跳过去不等于复活：已经用过「一次」的规则，跳过去也不会再开火。
- **跳转是这条规则的最后一件事。** 写在它后面的动作**不跑**——和「等一会儿」一样是提前返回，
  区别是「等一会儿」把剩下的动作排队延后，跳转把它们丢掉。日志里会写清楚丢了几个，
  因为一条悄悄半路停下的动作串，数一数之前是看不出来的。

**跳转不可能转圈**，因为整条链被规则条数兜住：**一次事件里每条规则最多开火一次**。
于是 A → B → A 在第二个 A 停下，没有"最多跳几次"这个数要调，也没有会忘记设的那一个。

（这道闸门标在规则**开火**时，不是被**考虑**时。一条被看过又跳过的规则——条件不成立、
冷却没走完——还没轮到它，它在同一个事件里稍后完全可能成立，因为跳过它的那条规则刚动过一个数值。
`tools/logic_check.py` 里有一条测试专门盯着这件事。）

**事件和动作的完整清单，就是代码里的 `EventType` 和 `ActionKind`**，编辑器那两栏直接列它们。
这里不再抄一遍——上一版抄了，抄成了"九种事件、十种动作"，而实际是**十种和十九种**。

**部位可以写前缀**：写 `hand` 会同时匹配 `hand_L` 和 `hand_R`。

**引擎里没有「数值变了」这个事件**，这是故意的：任何对数值的反应都能写成
「每隔一会儿 + 条件」，晚半秒但**不会自己触发自己**。规则改自己正在看的那个数，
正是那种写的人永远解释不清的 bug。

默认那套里有一对**用到了顺序和否则**的例子：**点一下**的那两条规则，
第一条把「穿着」翻过来，第二条**读第一条刚设好的状态**说「好看吗？」或者「干嘛？」——
规则按写的顺序跑，这件事在默认文件里就有。其余默认规则（改了就覆盖，可以「恢复默认」找回来）：被甩出去 → 喊 + 痛苦 20；
落地 → 痛苦 12 + 灰；被打到 → 痛苦 10 + 火花 + 喊；痛苦 ≥ 80 → 一直喊疼；
生命 ≤ 0 → 说「……」+ 松开动作 + 喷血（**只发生一次**）。

## 关于道具

**道具管理**里做道具，**测试场**顶部「道具」按钮放一个到桌上。五种用法：

| 类型 | 怎么用 |
|---|---|
| **持续使用** | 拖到角色身上按住，一直触发（刷子、食物） |
| **装置** | 放在桌上不动，角色碰到才触发（地雷、图钉） |
| **投掷** | 拖起来甩出去，砸到哪算哪 |
| **射击** | 拖出方向松手打出一发；道具留在原地，是个发射器 |
| **钉子** | 点一下钉住：点空白处钉在桌上，点部位就把那一节钉在那儿；再点一下拔掉 |
| **绳子** | 先画一小段绳子，再点两个点：点空白 = 锚在桌上，点部位 = 系在那根骨头上 |

**绳子是有物理的**（1.11.7 重做）：Verlet 链条 —— 重力把每个点往下拉，相邻点按 rest 距离
互相拉回来，两端钉在锚上，地板和边界收尾。**先积完分、再解连杆、最后钉两端**：锚点是世界的
事实（骨头动了、桩就在那儿），绳子不能跟它讲条件，只能挂着。位置就是状态，所以"速度"是
这一帧和上一帧的差 —— 会摆，不需要额外存任何东西。

拉不拉得动身体，量的是**两个锚点之间的距离和绳子自己的长度**，不是某一节连杆被拉长了多少：
一堆堆在地上的绳子，个别连杆看着紧，其实一点都没在拉，按连杆算会得到一根有脾气的绳子。
系上去的时候绳子比两点距离长 18% + 20px —— 正好一样长的绳子是一条直线，永远垂不下去。

- **绳子长度**：0 = 自动（两点距离 ×1.18 + 20px）；写了数就是写死的长度 —— 一根三米的绳
  拴在两米宽的地方，垂在地上；
- **弹性系数**：同一个拉伸量能拽出多大力。1× 默认，小于 1 是软绳（拉得动但没劲），
  大于 1 是蹦极绳；
- **画出来的是你画的那一小段**，沿着链条一节贴一节、转到那一节的方向、拉伸到那一节的长度。
  所以要画的是一小段而不是整根：画整根的绳子只有一种长度能用。**没画过图案也是一根绳子**
  （默认画成带绞纹的粗线）—— 一个必须先画点什么才能用的功能，第一次用的时候看起来就是坏的；
- 旧的**锚点**和**绳段**都删了，存档里读到这两个 kind **读出来是绳子**，不是锤子：
  文件说的是"绳子"，改的是绳子是什么，不是那个道具是干什么用的。

**拖尾**长在**道具**上（`props/<道具>/trail.png`），只有「持续使用」类道具能画：拖着它走过
的地方留下一笔，2.6 秒淡完，最多 220 个（太多先掉最老的）。**按距离留印子，不按帧**：每 26
世界像素一个印子 —— 按帧留的实现，同一段拖动在快的手机上密、在慢的机上稀，而没有任何地方
会报错。印子跟着走的方向转（绕自己的中心转，不是绕角，否则一个正方形的印子会甩出去整整一个
边长），画在**最底下**，宠物踩在自己的拖尾上面。

**画板**（`ui/PaintBoardView.kt`）是上面三样共用的那块 128×128：手指画线，一笔一撤销
（24 步），橡皮是 `PorterDuff.CLEAR` 而不是涂背景色 —— 画布要叠在世界上面，一个不透明的
方块就是把方块画在桌子上。**空画板 = 没有图案**：存一张全透明的图等于把这一笔变成一个什么
都不留下的东西，所以清空再保存会删掉文件，回到默认（粒子回到圆点，绳子回到默认那条）。

道具**不经过规则引擎去推角色**——推力是物理，有没有人写规则都会发生。
规则拿到的是一个事件：「被道具碰到 · 力度 640 · 打在 hand_L 上」，
**怎么算账是角色自己的逻辑说了算**。所以锤子和枕头可以是同一个道具，只是规则不同。

道具**之间**也会碰：两个撞上就分开，重叠**对半分**，谁也不比谁重。
道具的"重量"按设计不在 `PropSpec` 里（就是上一条的理由：锤子和枕头是同一个道具），
所以规格能支撑的分法只有对半——从 `force` 里读一个质量出来，等于凭空发明一个
编辑器从没写过、规则也够不着的数。液体里两滴水重叠时用的也是同一个分法。

唯一不让路的是**被手指按着的那个**：手指拥有它的位置，所以另一个吃下全部的分离量。
按住锤子能把飞过来的东西敲下来，靠的就是这一条；两个都被按着，就谁也不动。

只有**正在靠近**的一对才会反弹。两个道具靠在一起并不算靠近，每帧都把它们弹开就会抖——
这和地面那一遍把同一根静止的骨头转两次，是同一个错误。

道具之间的碰撞**不产生事件**。事件的主语是「谁被什么碰到了」，得是角色或它的某个部位；
两个道具相撞没有这样一个主语。要让"子弹打中炸弹"发生点什么，需要的是**一种新的事件**，
而不是把 `Hit` 掰弯去凑。

道具图不用对位：它不挂在骨头上，图片本身就是那个东西。
**没图的时候画一个绿圈，那就是它的碰撞范围**——调手感的时候比图还准。

## 关于液体

**液体不是网格，是一群互相推开的液滴。**

没有格子、没有压力求解。让它读起来像液体的只有一件事：**重力把它们堆起来，而拥挤把堆摊成水洼**。
其余每一行代码都是为了防止这件事出错：

| 做法 | 不加会怎样 |
|---|---|
| 修正量**累加后一次应用**（Jacobi），不是边找邻居边推 | 结果取决于网格先返回哪个邻居 —— 水洼会抖 |
| 修正量**每帧封顶** | 一次喷出一百滴，两两都重叠，一百个修正加起来是**手榴弹** |
| 速度**从落点反推**，不是保留推力 | 重力每帧给地上的液滴加 40px/s，地面只把位置还回去；不管速度的话，一洼静止的水每一滴都报告自己在以 300px/s 移动 |
| 略远时**互相吸引**（黏性） | 只会推不会拉，水洼会一直摊到撞墙为止 —— 那不是液体，是一袋弹珠 |

**黏度**不是流体属性，就是"拉回去有多用力"：0 像水（流开、摊薄），1 像史莱姆（抱团、整体移动）。

液体本身可以在**逻辑管理 → 液体**里自己加：名字 + **八个色板挑一个** + 黏度。
色板不是取色器 —— 八个色块是个决定，一个色轮是个爱好。

规则里的动作叫**喷液体**（一次四十滴，落地就见分晓），还有**流液体**：每秒多少滴、流多少秒，
位置每一帧重新取自主体自己身上——所以一条长在手上的「流液体 血」，手走到哪儿血就跟到哪儿，
像一道伤口而不是一次喷溅。粒子那边对着的是**喷粒子**和**持续喷粒子**。

**流液体有两种形状**，量出来的差别在"还是流的时候"有多宽：

| | 一柱（`柱状`，默认） | 一团（`乱撒`） |
|---|---|---|
| 落点宽度（20 滴/秒，第一滴着地那一刻） | **18 px** | **502 px** |

柱状给每一滴**同一个方向**（向下）、只抖 ±3°，而且沿着发射点撒而不是撒在一个 12px 的球里，
所以它们一起走、落地是一条线，重力再把它弯成一道弧——那才是"倒水"的样子。乱撒就是喷液体
那种全圆随机，摊在时间上。**这两种不能靠"慢一点喷"互相代替**：四十滴同时生在一个点上会
互相挤爆（`_separate` 那一套），所以形状这件事由方向决定，不由速度决定。

每种液体还有一个**性质**开关：

- **和角色碰撞**（默认）：水滴绕着身体流、堆在脚上。
- **穿过角色**：角色对它不存在，水从身上穿过去（**地面和墙照样拦得住它**——这个开关说的是宠物，
  不是世界）。

（镜像里两边都钉住了：同一次喷、同一根腿，只差这个开关，落点差 490px vs 6px。）

默认那套里，**生命归零时会喷 40 滴血**。

**逻辑管理栏下面现在有一栏「液体」。** 每种液体一个方块，**点一下就往场上喷一把** ——
在这之前，液体是唯一一个除了"写一条规则然后等它触发"以外没有入口的系统，
而这个要求对一个只想看看自己的史莱姆长什么样的人来说太奇怪了。
方块右边写着场上有几滴，长按回到液体编辑。规则照旧能喷。

## 关于状态

**状态是开关，不是数字。** 「穿著」「受伤」这类事实，用数字表达要解释"1 是穿着还是 2 是"，
用开关不用。逻辑管理里自己加，一个角色一套。

它连着两个地方：

- **图层**：在「图层与深度」里给每个部位选一个状态，那个部位就**只在状态打开时才画出来**。
  给衣服的每个部位都选「穿着」，穿衣服和不穿衣服就是同一副骨架的两套图 —— 
  不需要第二只角色。没选状态的部位永远画。
- **规则**：「如果」里可以测状态开着还是关着，「就」里有打开 / 关闭 / 切换三种。

删掉一个状态，引用它的规则读到「关」，引用它的部位**照常画** ——
名字没了就把图永久藏起来，那是找不回来的 bug。

### 全局状态和局部状态

状态分两级，**由谁声明就是谁的**：

- **角色自己的状态**（全局）：在主体是「角色」时加的状态。写着 `穿着`、`受伤` 那种。
- **部件的局部状态**：把主体切到「部件·手」，在同一个状态面板里加的状态就是**手的**。
  手可以有自己的「出汗」，和角色自己的状态**互不相干** —— 名字一样也是两把开关。

规则里的「状态」**只写名字**，在哪个引擎里就是哪一级：写在手身上的规则，
「如果 状态 出汗」问的是手自己的那个出汗。这样写规则的人不用去想命名空间。

图画在哪一级也是有据可查的：一张状态图的**图层标记**，全局的就是状态名，
部件自己的写成 `hand_L:sweat`（关着时画则是 `!hand_L:sweat`）。
渲染器只有一张开关表，就用这个标记当键 —— 于是 `visible()` 一行都不用改，
而**名字撞了也不会画错**。

测试场上面那排开关**两级都会列出来**（局部的那个写着「出汗·手」），点一下就是翻转它 ——
包括"某个部件只有一个状态、还没写过规则"的情况：那个状态的主人（部件的引擎）照样建起来。

### 状态还能换图，不只是藏图

**一条骨骼可以有多张图**，而"哪张图"是**一个文件夹**，不是一个按钮：
「桌宠管理 → 打开一只 → 部位」里，**点任何一个部位**就进它的文件夹，
里面是它所有的图，一行一张，**每行左边是那张图本身**，
右边写着它什么时候画：

    总是画                    → parts/upperarm_L.png
    状态「机械臂」关着时画      → parts/upperarm_L.png（图层上标着"不画机械臂"）
    状态「机械臂」打开时画      → parts/upperarm_L__mech.png

点一行**就是换那一张**（同一个文件，新图），右边是删除，底下是
**＋加一张图** / **＋加一张状态「机械臂」的图** —— 后者会自动建好图层，
和以前那个 **状态版本** 按钮做的事一样，只是现在**看得见自己在干什么**。

（这两个文件名的写法就是**加载契约**：加载器必须同时收下 `parts/<骨骼>.png` 和
`parts/<骨骼>__<状态>.png`。少收后面那种的后果是"文件在硬盘上、文件夹里列着、
图层指着它，而宠物身上没有"——这个 bug 真出过，就是"上传图片时看不见"，
见 `tools/parts_check.py` 里"什么名字能进库"那一节。）

在这之前，图是看不见的：导入一张，之后唯一的证据是宠物看起来不一样了。

删掉一张状态图，**同时会把图层删掉、并且把原来那张恢复成"总是画"** ——
不然那条"不画机械臂"的标记会留着，于是机械臂关掉时那条胳膊会凭空消失，
看起来像 app 坏了，而不是像图被删了。

于是"装上机械臂"就是：同一条 `upperarm_L`，两个文件，一个状态。

状态那栏现在可以选三种：**总是画** / **状态打开时画** / **状态关着时画**。
第三种的写法前面加个 `!` —— 这就是"替换"和"叠加"的区别，
不写的话状态一打开两张图会同时出现。

默认那套里有一对现成的例子：**点一下角色切换「穿着」，扔它的时候如果穿着就会喊「别弄脏衣服！」**。

### 状态多了以后，图层深度怎么改

一只桌宠的状态一多，**图层与深度**那一页就变成「二十行里找三行」—— 而要找的三行，往往还是
同一件衣服的三个部位，位置却分散在整张表里，▲▼ 一次只走一格，走的那一格还可能是别的状态的。

所以那一页顶上多了一行**过滤**：**全部 · 总是画的 · 每个状态一个方块（带层数）**。

- 选了哪一组，就只显示哪一组的行（一个状态的两半都算它的：`mech` 和 `!mech` 是同一组的
  正反面）；**顺序还是那一个顺序**，过滤只决定你看得见哪几行 —— 不是给每个状态各存一份顺序
  （那是两套顺序，迟早对不上）；
- 过滤时 **▲▼ 是在这一组内部换位**：它把这一行和「下一个你看得见的行」对调，别的状态的行
  原地不动。这正是「改某个状态的深度」的意思，也是不加过滤时做不到的那件事；
- 每一行右边那个方块仍然是这一层挂在哪个状态上（点它改）。

### 用不上的图层：三种「画了等于没画」

一个没人用的图层是**安静**的：不报错、不画、这一页里那一行还长得跟别的行一样。三种情况：

| 情况 | 症状 | 这一页怎么处理 |
|---|---|---|
| 它等的**状态已经不存在**（状态被删了，或者包是别人给的） | 永远没人打开它 | 行上标 ⚠，点开可以**改成别的状态**、或者**把那个状态重新建出来**（在哪一级建：标签带骨头就是在那个部件上建） |
| 它要的**图不在硬盘上** | 同上 | 点开直接送到**那根骨头的部位图**页面去导入，或者把这一层删掉 |
| **图画好了，可是表里没有它的行**（`hand_L__mech.png` 这种变体最容易） | 这一页里连找都找不到它 | 打开这一页时自动补一行，状态从文件名读出来（`addVariant` 就是这么命名的），存一次就正式进去了 |

顶上的过滤里有一个 **「用不上 N」**：点它就只剩这些行 —— 一个没人看得见的图层，是没人会去找的
图层，所以它得自己站出来。

### 状态在哪里打开、关掉、看到效果

状态做了三件事，之前只有第 1 件是看得见的，所以「加完状态然后呢」是个真问题：

1. **控制画哪张图**（图层，和上面说的状态版本）
2. **规则能读它**（「如果 状态 X 开着」），也能翻它（打开 / 关闭 / 切换）
3. **可以手动拨** —— 这是这一轮加的

所以现在：

- **测试场上面多了一排开关**：`● 穿着` / `○ 机械臂`。点一下就翻，
  立刻能看到另一张图长什么样。**没有这个东西就写不出关于机械臂的规则** ——
  你没见过它装上去的样子。
- **逻辑管理 → 状态**里每一条现在写着它被用在哪（`用在 2 张图 · 3 条规则`），
  点进去是能做的事：**现在打开/关上**、改名字／初值、
  **看哪些部位有它的图**（点进去就是那个部位的文件夹）、
  **用它做一条规则**（直接生成一条「当 被点一下 如果 状态 X 开着 就 说……」）、删除。

## 关于部位能怎么没：隐藏、断开、接回

规则里有四个动作，管的是"这一节还在不在画面上"：

| 动作 | 做了什么 |
|---|---|
| **隐藏部位** | 把那一节的**图**藏起来。骨架和物理一点都不动——它还在、还有重量、还能被拖 |
| **显示部位** | 把藏起来的那张图放回去 |
| **断开部位** | 这一节**连同它下面所有子级**从世界里移除（抓不到、地面不托、没有重量），**再掉一整块在地上** |
| **接回部位** | 图重新画上，地上那块收走 |

「隐藏部位」原来叫「打坏部位」，但它从来没打断过任何东西——它实现的一直是隐藏，
所以名字改成了它真正做的事；`break` 这个代号没变，老文件照样读得懂。
加「显示部位」是因为**只能藏不能显的动作是个单向门**，和"打开状态/关闭状态"那一对是一个道理。

**「断开」是"这一节真的不在了"**，不是"不画了"。一个状态（`Ragdoll.setGone`）带三个后果，
因为它们本来就是同一句话：

- **手指穿过去**：抓取命中会跳过它，于是你抓到的是它后面那根骨头（一根看不见的骨头挡在
  前面、还能被抓，是这一版最早漏掉的一条）；
- **地面不托着它**：断了一条腿的宠物不会站在那条看不见的腿上；
- **它没有重量**：身体会朝缺的那一侧倒。
- 另外，**正抓着它的手指会松开**（捏着一根不在的东西，等于拖空气）。

掉下去的那块会**带着关节当时的动量**飞出去（所以从一只正在被甩出去的宠物身上扯下来的手，
会朝它本来飞的方向去），落到地面线就停住，滑一小段、转速衰减到停。

**「断开」断的是整条肢体**：命名的那一节连同**它下面所有子级**一起走——断一条胳膊掉的是整条胳膊，
不是一个挂在空中的前臂。掉下去的那一块按**同一个刚体运动**画（绕它被扯断的那个关节转，所有子级
的相对位置都保留着），所以肘和手还在原来的地方。

**那块碰撞箱是自动的**：它带着**自己的骨头**走——断开的那一刻把每根骨头的胶囊量下来（头、尾、
碰撞半径，都相对被扯断的那个关节），此后地面、身体和手指看到的都是**这条肢体本身**，不是一个
包住它的大圆。一版之差是这样的：一个圆会让胳膊**浮在地面上方一整条胳膊的高度**、被身体从老远
推开、还能隔空捡起来。三条都来自同一个错误——把"这块有多大"当成了一个数。

**掉在地上的那块还能玩**（"断开的部位应仍能互动"）：

- **手指能把它捡起来拖**（它画在最上面，所以手指落在谁身上就是谁），松手时把它按手指的速度扔出去；
- **第二根手指转它**（像相册里转照片：第二根手指绕着它的角度就是转过的角度）。没有这一条，
  一块碎片只能平移——**放不回另一个面朝上，落地之后角度就冻死了**；
- **和身体是双向的**：身体把它推开，它**也推身体**——所以一条断胳膊落在宠物背上会把它**压动**，
  从高处砸下来会把它砸得一颤。推身体走的是 `Ragdoll.impulse`（求解器唯一对外的门），
  按接触深度算、有上限：搭着是"一直轻轻推"，砸下来是"推一下重的"。
  （一开始这里只做了单向，理由是"断手不该摇动宠物"——那不是量出来的，只是整齐；你要的是另一种。）

**剩下的取巧只有一条，而且看不见**：那根骨头的关节还在骨架里空转（它自己的角度还在积分），
因为把它彻底切掉意味着把身体拆成两个刚体，而这套求解器从头到尾只有一个根。

（`tools/` 里没有它的镜像测试：残肢是测试场自己的东西，不在求解器里，也没有第二个实现
要和它比。物理那半边仍然由 ragdoll/drag/carry 那几套盯着。）

## 关于测试场这块地

它是一间**屋**，不是一张画：画布（`canvas`，1024×2048）只是图需要多大，
**房间**由 `physics` 说了算——

| | 值 | 意思 |
|---|---|---|
| `worldWidth` | 6144 | 左右墙之间。**6 个画布宽**，不是 3 个 |
| `floorY` | 1980 | 地面线（画稿自己的脚底） |
| `ceilingY` | -1600 | **屋顶**。0 是画稿的上边缘，也就是每只角色一直以来的屋顶 |

改前是 3072 × 1980：横着 2.3 个身位、竖着 1.5 个——**一只宠物被扔上去，两个身长就顶到一块没人画过的天花板**。
现在是 6144 × 3580（y −1600…1980）：横 4.6 个身位、竖 2.65 个。

屋顶是 1.10.1 才有的东西：求解器里那个 `ceiling` 原本是写死的 `0f`，相机也只允许看到 y ≥ 0。
现在它来自角色文件（缺省还是 0，所以老角色一个像素都不变），相机和网格跟着它走。
**默认缩放没有跟着变小**——它一直是"把地面那一段塞进屏幕"，所以场地变大不会让宠物变小；
多出来的空气在屏幕外，扔上去的时候跟手相机自己会往上跟。

## 关于一个部位的属性

「骨骼列表」里每根骨骼多了一个 **属性**：

- **刚度 ×**：这个关节自己的弹簧，**乘在全局刚度上**。0 = 完全松垮（不管测试场那个滑杆），
  1 = 跟别的关节一样，2 = 硬一倍。全局那个"松垮/僵硬"还在，没删——两个一起用才是"整只软、
  但这条胳膊硬"。（这个字段其实一直写在文件里，只是**从来没有人读**：求解器只认全局那个。
  1.10.0 起它真的接上了，默认值也从那个没人读的 0.35 改成了 1.0。
  **1.11.13 补的是第三处**：`saveRig` 从来没把它写回去 —— 编辑器有、求解器读、保存漏了，
  症状正是"这个滑杆没用"，而且一声不响。现在不是 1.0 才写进 `physics.stiffness`，
  回到 1.0 就把键拿掉（"不在"本来就等于 1.0，不该让十九根骨骼第一次保存就全长出 physics 对象）。）
- **旋转范围**（最小 / 最大角度，度）。这是手感来的地方：膝盖能弯多少、
  肩膀能转到哪儿，全都写在这两个数里，而它们原本是照着参考图量完就再也没看过的。
  一个能转 170 度的肩和一个能转 90 度的肩是两种动物，而想知道自己要哪一种，
  唯一的办法是拽着胳膊看它停在哪。
- **碰撞体**：沿骨骼的胶囊，或者中点的圆，加上半径。
  地板、道具、液体看见的就是这个形状 ——
  "为什么它浮在地面上方"和"为什么它陷进桌子里"都是从这里来的。
- **质量不在这里**，因为质量是按碰撞体的面积算出来的：粗的肢体就是重的肢体，
  另外再给一个重量等于同一件事给两个答案。
- **两个开关**（默认都开着）：
  - **参与碰撞** 关掉 → **地板、道具和液体都感觉不到它**。它照样跟着动、照样有重量、
    照样参与摆动，只是世界当它不存在。发带不该把桌子推走，就用这个。
  - **能被拖动** 关掉 → **手指直接穿过去**。为规则而存在的骨骼（"让手流汗"挂的那个点）用它。
  两个是分开的：不能碰的东西仍然可以抓，能碰的东西也可以规定"不许抓"。

**范围不用敲数字了（1.9.2）。** 「摆姿势」那一档本来就能拖关节，所以摆出你想要的角度之后，
工具栏上多出来的两个按钮把它记下来：

    摆姿势 ──拖关节，把胳膊/膝盖甩到你希望它停下的地方──▶「设为最小」或「设为最大」

「设为最小」只动最小那一头，最大那头留在文件里；如果这么一设反而让范围倒过来
（新的最小比原来的最大还大），两个数会互换——这和属性框里"把范围敲反了"是同一条规则，
两边现在共用 `RigEdit.limits`，所以不会各说各话。

**选中一根骨骼，画布上会把它的范围画出来**：关节处一个半透明的扇形，两条边就是能转到
哪儿的两头，骨头本身画在扇形里面——所以"能转到哪"和"现在在哪"是同一眼看到的。
扇形是以**静止方向**为中心的（`minAngle`/`maxAngle` 本来就是相对静止姿态的偏移），
所以摆姿势的时候扇形不动、骨头在里面动，这正是要看的东西。

默认那套骨架里，**胯是 ±360°**（整个自由转动），所以整只宠物可以翻过来倒立；别的关节各自带着
一个量过的范围（膝盖 -150~0、手 ±70、头 ±50……）。

改完点保存会直接写回 `character.json`，回测试场就能感觉到。
（这两个开关**每次都写**，不是只在新骨骼上写 —— 不写的开关就是"下次保存时自己翻回去"的开关，
而那是 `tools/store_check.py` 专门盯的一类 bug。物理那半边有 `tools/ragdoll.py` 的第 4b 组：
关掉一只脚的碰撞，那只脚穿过地面线 49px，而**其余仍然实心的部位照旧站在地面上**。）

## 关于自己搭骨架

**改骨骼**模式下，底部多了 **＋加骨骼** 和 **骨骼列表**：

- **加骨骼**：输入名字（默认 `bone_1`），点一个父级，然后**在画布上点两下** ——
  第一下是关节，第二下是末端。骨骼是画里的东西，唯一诚实的说法方式就是指着画说。
- **骨骼列表**：每根骨骼一行，**按层级缩进**，每行带「改父级」和「删除」。
  列表里还有「清空（只留根）」，这是从零搭一副骨架的起点。
- **双指缩放、拖空白处平移**，右边一栏是骨骼列表，**点名字就放大到那根骨骼** ——
  十九根骨骼里找一只手，在手机上戳图是猜谜，点名字不是。
- **改父级**：**骨骼不会移动**。头尾存的是画布坐标，父子相对关系是烘焙时才推出来的，
  所以换父级换的是"跟着谁动"，不是"在哪里"。
- 骨骼名同时是**文件名**：`parts/<名字>.png`。所以名字里的空格和
  `/ \ : * ? " < > |` 会被换成下划线 —— 名字是骨架和画之间的约定。

三条规矩，编辑器当场拦下来，不会等到烘焙时才炸：

| 规矩 | 为什么 |
|---|---|
| **只有一根根骨骼** | 出现第二根时 `buildSkeleton` 只认最后一根，另一棵树会**整棵消失** |
| **不能接到自己的下级上** | 成环。列表里那些自己的下级是**灰的**，点了会告诉你原因 |
| **根骨骼不能删** | 它的子骨骼会没有归属（要重来用「清空」） |

**删除只在「保存骨骼」时才落盘。** 在那之前"删除"只是一个意图，
中途走掉不保存，你的图还在。

### 调骨骼时看什么：参考图

改骨骼的时候，画布上**本来就该看得见这只桌宠的样子**（拼起来的那一整只画在骨架下面）。它不
见了有两个原因，一个是 bug，一个是缺功能：

- **bug：被状态挡住的图在这儿一直没画过。** 一层图只有它的状态开着才画（`LayerSpec.visible`），
  而这一页从来没有人给它状态表 —— 于是画在「穿着」「机械」后面的图在测试场里看得见，
  在调骨骼的这一页看不见。现在骨架页底栏的 **参考图** 里有这一只的每一个状态（它自己的，
  加上每个部件自己的），点一下打开就好；
- **缺功能：还没导入的图，任何开关都变不出来。** 所以**从手机里选一张图**也能放进来：
  它存在这一套骨骼里（`rigs/<套名>/reference.png`，默认那套是 `characters/<桌宠>/reference.png`），
  画在**最下面**，骨架和拼起来的那只都在它上面。**按比例放得下**（不变形：导出的图是
  1024×2048 的话正好铺满画布），浓淡三档（淡 / 中 / 浓），随时可以去掉。

参考图**不放在 `parts/` 里**：那是"每根骨头一张图"的地方，一张 `reference.png` 摆在那儿
既会被当成某根骨头的画，也会在测试场上被一起画出来。

（`tools/wiring_check.py` 盯着这两半：编辑器必须把状态表交给渲染器，上传的图必须真的
`drawBitmap`。两句话都是"功能看起来在、其实没接上"那种错的机器版本。）

### 骨骼节点：一根骨头上叫得出名字的点

部位是一整根骨头，所以「指尖」「肩膀」这种地方以前没法说 —— 规则能写「手」，不能写「手上
那个点」。**节点**就是那个点：没有长度、没有关节、自己什么都不用解算，它只是一个**名字**。
入口是骨架页底栏的 **＋加节点**（和 ＋加骨骼 并排）：点它，然后**在画布上点骨头上的位置**
—— 落点会投影到**最近的骨骼**上（点在细骨头旁边也算点到它，和这个应用里手指的其他地方
一样宽容），偏移量就是那个落点沿骨头的位置。

- **判定**：道具碰到节点走和骨头**完全同一套**接触（同一个重叠、同一个回弹、同一个 0.25 秒
  节流、同一个冲量），只是事件里的名字是节点而不是骨头 —— 规则问的是"谁被碰到了"，而
  「指尖」比「整只手」是更好的答案。冲量照旧落在骨头上，因为推的是身体；
- **被点一下**：手指按在节点上时，抓的是**节点的偏移**而不是手指投影到的地方；
- **系绳 / 钉钉**：绳子的一端、钉子的落点本来就是一个"骨头上的偏移"，节点只是给它起了名字；
- **隐藏 / 显示**：规则里两种名字都收，节点走自己的一套（它没有图画）；
- **装道具**：节点可以带一个道具，道具每帧跟着那个点走，而且永远是 planted —— 世界不动它、
  手指拿不走、身体感觉不到它（一把每帧推自己手的剑是拿不住的），但它照样把别的道具推开，
  所以挥起来是有用的。隐藏节点就是把东西摘下来。

节点位置存的是**沿骨头的距离**：骨头以后被改长改短，末端节点跟着走，而不是留在半空。
三条约束（`RigEdit.nodeProblem`，编辑器、保存、镜像共用一份）：节点名不能和骨骼重名
（两者都是规则里的名字）、半径不能是 0、挂的骨头必须存在。删骨骼会连同它的节点一起删，
骨头改名时节点跟着改。

**每一次改动立刻写盘**，这一条是踩出来的：节点以前只改在编辑器内存里，而保存按钮在**另一页**，
所以加完看着成功、列表里也有，但沙盒读的是硬盘上的文件 —— 节点根本不存在。用户在哪儿改，
就在哪儿算数，和逻辑面板一个规矩。

## 关于变身

「就」里有一个动作叫**变身**：**整套**换成另一个角色 —— 骨架、图画、道具和那个角色自己的
逻辑，一起换。这是「换骨骼」必然的样子：没有图画的骨头是看不见的，所以换骨骼一定连图画
一起换。

- 由**宿主动手**：角色是文件夹、图画和几个文件，只有 Activity 知道它们在哪儿，测试场只说
  "变成这个"。目标写在动作的 `text` 里，是一个角色的 id；
- 找不到那个角色、或者文件读不出来，就**不换**（找不到时弹一句，文件坏了时退回原来那个）：
  变身成一个空测试场，比这条规则什么都不做更糟；
- **变成自己不算变身**：那只是把世界清空一次，看起来像惩罚；
- 两个保护，都不是类型错、编译器一句话都不会说：**速度上限 0.5 秒**（"A 出现时变 B、
  B 出现时变 A"是两行就能写出来的东西，没有上限它就是每帧重新装载一次），以及**延到下一帧
  做**（动作表在帧中间跑，在中间换掉整个世界，会让这一帧剩下的部分跑在一个已经被换掉的
  世界上面，所以动作只记账，帧首才动手）；
- 已知行为：变身会把桌子也重新摆一次（道具、液体、粒子都清掉，新角色从家位开始）——
  换的是整套，包括地面高度，所以这是有意为之而不是漏了。

## 关于多套骨骼：一只桌宠，几副身体

同一只桌宠可以有几套骨骼 —— 一套「平常的样子」，一套「机械形态」，各自有自己的骨架、自己的
部位图、自己的动作。桌宠管理里点进一只，**名字下面那一行**就是它的骨骼套：默认那套 + 每一套
一个方块，最后是「＋」。

```
characters/<桌宠>/
  character.json  parts/  poses.json     ← 默认那一套（就是包裹本身，老文件零迁移）
  rigs/<套名>/
    character.json  parts/  poses.json   ← 另一副身体：骨架、图、动作都是它自己的
  logic.json  particles/  liquids/       ← 这一只的规则、粒子、液体（不跟着骨骼走）
```

- **换的是样子，不是这一只**。规则动作里有一个**「换骨骼套」**（选哪一套，空 = 默认那套）：
  切过去的时候**数值（H/P）、状态开关、规则、粒子、液体、桌子上的道具全都不动** ——
  「肚子痛到一半变成机械形态还是痛」就是这句话。这和**变身**是两件事：变身换的是**谁**
  （另一只桌宠，它自己的规则和数值，世界整个重新装载），换骨骼套换的是**长什么样**；
- **换完发一个事件**「换了骨骼套」，所以「变成机械形态 → 说一句话」是两条规则，而不是一段
  藏起来的代码；
- **它也有速度上限**（0.5 秒）和**延到帧首执行**：一套「换了这套 → 再换回去」的规则是两行
  就能写出来的东西，而没有上限它就是每帧重建一次身体；
- **身体换掉时松手的东西**：手里抓的、钉在身上的、系在骨头上的绳、被扯断掉在地上的那一块、
  正在喷粒子的发射点 —— 它们说的都是**旧骨架的骨头名字**，新骨架里没有这些名字。所以它们
  留在地上/消失，而不是挂到一个碰巧同名的骨头上（那看起来像隔空取物）。**藏起来的部位跟着
  人走**：那是一个开关，不是旧身体的几何；
- **桌子跟着骨骼套，只在屋子真的不一样时才动**：两套骨骼通常共用一间屋子（屋子是这只桌宠
  的），这时桌子、道具、水、火花一点都不动。新那套如果写了不同的地面/墙，世界会重建，**散着
  的道具会跟着搬过去，水不会**（它的每一滴都在旧屋子的坐标里）；
- 新建一套时可以选择「**复制当前这套**（骨架 + 部位图）」或者「**只复制骨架**」（图自己再画）；
  **长按**一套可以重命名或删掉它。**默认那一套不能删也不能改名** —— 它就是包裹本身，
  全世界的存档都在那儿；
- 动作（pose）**跟着骨骼套走**：一个动作是一堆骨头角度，骨头名字换了它就没有意义。默认那套
  的 `poses.json` 还在老地方，所以谁的动作都不会搬。

## 关于桌宠包：把一只桌宠带走

一只桌宠本来就是一个文件夹，所以「导出」不是一种新格式 —— 就是把那个文件夹写成**一个文件**：

- 桌宠管理 → 某一只那一行的 **导出** → 系统「另存为」 → `名字.atppet`（就是一个 zip）；
- 列表顶上的 **导入桌宠包…** → 选一个 `.atppet` → 它变成**一只新的桌宠**，用包里写的名字。

包里装的是**整个文件夹**：骨架、部位图、别的骨骼套、动作、规则、粒子、液体、参考图。
少装一样的包，装回去就是一只你不认识的宠物。

**导入永远不覆盖**：包里叫「小白」而你这里已经有一只「小白」，新的那只就叫「小白2」——
两个人给自己的宠物起同一个名字，不是弄丢一只的理由。

**一个来自外面的 zip 就是一个来自外面的文件**，读的那一侧按这个对待
（`data/PetPackage.kt`）：

| 规矩 | 为什么 |
|---|---|
| 条目名里有 `..`、以 `/` 开头、带盘符、带 NUL、超长 → **那一条丢掉** | zip 是一串路径，而恶意的那一串里一半的条目是「出去的路」 |
| 条目数 > 4000，或者解出来的总量 > 512MB → **整包拒掉** | zip 炸弹寄出去很小 |
| 没有 `pack.json`、格式号不对、`kind` 不对 → 拒掉 | 选错文件是最普通的错，答案要和「这不是包」一样 |
| 没有 `character.json` → 拒掉，并把解出来的东西删干净 | 列表里半只宠物，比一个没导进来的包更糟 |
| 包里的文件都套在一个文件夹里 → 认出来，把那一层剥掉 | 别人解压看一眼再压缩回去，是他的权利 |

（`tools/package_check.py` 是这一节的镜像：哪些路径会被拒、重名怎么办、套了一层还认不认。
它当场抓到过一个真 bug —— 第一版只剥**第一段**路径，于是「解压再压缩」过的包会被判成
「里面没有桌宠」。）

## 新建、复制、重置

- **＋新建桌宠**：列表顶上，从**出厂素体**复制一只（19 根骨骼那副，带占位图）；
- **复制**：某一行的按钮，把**整个文件夹**再写一份 —— 图、骨骼套、动作、规则、粒子、液体
  全都一起，所以「在原版上试一个想法」碰不到原版；
- **重置骨骼**（调骨骼那一页底栏）：改骨骼是**直接改骨架**的（拖动关节就是改坐标），而回头路
  原先只有「清空」和「删掉整只桌宠」—— 后者会连图、规则、粒子一起丢。现在一个入口三个答案：

| 选项 | 做什么 |
|---|---|
| **回到上次保存的样子** | 丢掉编辑器里还没保存的改动（拖过的关节、加过删过的骨骼）。文件是唯一的真相 |
| **骨架恢复成出厂素体** | 骨骼、层级、图层、IK、物理参数回到内置那副 19 根的素体；**这一套的部位图、动作、规则、粒子和别的骨骼套都不动**（同名的骨头照样认自己的图） |
| **清空重来（只留根）** | 骨骼列表里那件事，放到这里，好让「从头开始」只有一个地方 |

新建、复制、重置都不需要新机制：它们都是**文件夹操作**，所以没有新的存档格式、也没有新的
运行时概念 —— 校验的重点因此不在功能而在边界（重名、坏包、名字里的斜杠）。

### 场上放哪一只

「测试场」顶上那一排的**第一个**就是它：每只桌宠一个方块，当前那只亮着，名字后面写着它正在用的
**身体**（骨骼套）；最后一个「＋」直接去桌宠管理。桌宠管理里每只一张卡上也有 **放到场上**，
当前那只写「✓ 场上」。

两处走同一个函数（`summon`），因为"挑一只上场"只该有一件事发生：换骨架、图画、规则、粒子和
液体。**再点一次当前这只**不会把身体重置成默认那套 —— 它只是把测试场重新读一遍。

**挑宠物是用户的事**：复制一只、导入一个包、改完名字之后，刷新列表会**留住场上那一只**
（连同它正在穿的那套骨骼），而不是跳回列表里的第一只。原来就是跳的，症状是「我刚复制了一只，
桌上的宠物变成了别人」。

## 关于动作

动作（pose preset）存在角色目录**旁边**的 `poses.json` 里，不在 `character.json` 里——
角色包是"素材"，动作是"你的用法"，两者升级互不覆盖。测试场顶部那个 **动作** 按钮打开列表：

- 每条动作左边是**骨架缩略图**。名字三个月后就没意义了，形状不会。
  缩略图只读 spec 画骨架，**不加载部件图片**，所以列表是秒开的。
- 点一条＝角色做这个动作，然后**列表自动关掉**，好让你看。
- 改名 / 删除都在列表里。存动作在**桌宠管理 → 摆姿势 → 存为动作**。

选动作时角色会被**放回原位站好**：不然一只被扔到角落躺着的桌宠，
做的动作就是躺在地上摆造型，什么也看不见。

## 一个只有真机上才会出现的 bug

修好"提脚倒吊"那一版之后，测试场里**什么都没有了** —— 只剩 HUD 和状态条。

原因不在物理，在**读文件**：

    val air = phys?.optDouble("roomAir")?.toFloat() ?: derived()

org.json 的**单参数** `optDouble(name)` 在键不存在时返回的是 **NaN，而不是 null**，
而 NaN 不是 null —— 所以 `?:` 根本不会触发。于是 `air` 是 NaN，地面是 NaN，
每根骨骼的位置是 NaN，视图变换也是 NaN：**画在"不是数字"的坐标上，就等于没画**。
HUD 和状态条是屏幕坐标，不受影响，所以看起来是"别的都在，就是宠物不在"。

Python 那套镜像永远抓不到这个 —— 它们测的是算法，而这是 Kotlin API 的坑。
所以多了 `tools/kotlin_check.py`，三条检查里第一条就是它：

    .opt(Double|Int|Long)(k) ... ?:      ← 一个参数 + elvis，就是 NaN 陷阱

带自测（`--self-test`），而且**验证过它真的能抓到这个 bug**：把那一行改回去，它报错；
改回来，它过。另外两条是括号平衡（省一次五分钟的 CI 往返）和 R.* 引用是否存在。

## 关于验证（这一层也一样）

**规则引擎里没有一行 Android**：它只把"世界要执行的动作"还给调用方，
自己不知道气泡、骨头、粒子是什么。所以整个逻辑层能在本地测——

```bash
python3 tools/ragdoll.py          # 落地、倒吊、铰链限位、松开手的速度
python3 tools/drag_check.py       # 拎着脚踝倒吊、两根手指劈叉、甩出去的速度、拖起来会不会抖
python3 tools/carry_check.py      # 提脚整具身体翻过来（抬起多少、抓哪一段、什么帧率）
python3 tools/logic_check.py      # 冷却、只一次、而且/或者、信号、延时、规则顺序
python3 tools/rig_edit_check.py   # 加/删/换父级、部位属性的角度范围真的被求解器遵守
python3 tools/rig_prop_check.py   # 碰撞推出、接触节流、落地、投掷速度、道具对道具（对半分、按住的不让路）
python3 tools/fluid_check.py      # 水洼会摊平会停、液滴认得自己那种液体
python3 tools/particle_check.py   # 粒子：受不受重力、落在地上留不留印子、颜色和大小是哪种粒子的
python3 tools/parts_check.py      # 图层、状态、画哪张图
python3 tools/store_check.py      # character.json 四处读-改-写：骨架、状态图、深度、改名
python3 tools/settings_check.py   # settings.json：缺键、越界、写坏了都不崩
python3 tools/camera_check.py     # 镜头：默认缩放看得见宠物、放大后丢了它要能找回来、喷的液体落在窗口里
python3 tools/mirror_check.py     # Kotlin 和 Python 两份实现的常数是不是同一个数（漂了就红色）
python3 tools/kotlin_check.py     # Kotlin 源码：NaN 陷阱、枚举重名、括号、资源引用
python3 tools/wiring_check.py     # 布局里的控件有没有人接线、函数有没有人调用
```

**后四个不是物理，是"物理测试永远看不见的那一类"**：

- `store_check.py` 镜像 `CharacterStore` 里**四处会改写 `character.json` 的地方**。
  四处都是**读-改-写用户自己的文件**：物理错了看得见，文件悄悄少了一样东西看不见。
  它已经抓出两个真 bug（保存骨架会删掉状态图、改名会把状态图落下）。
- `camera_check.py` 镜像的是**视口**：默认缩放该看得见宠物，双指放大**丢了**宠物之后
  要能自己找回来，喷出来的液体会不会落在窗口看的地方。**"角色不显示"这个报障出现过两次**，
  两次都是镜头算错但看起来像应用坏了——一次是宠物被放在地面之上掉下去，
  一次是房间变深之后宠物站在最底下、一放大就滑出窗口（跟着走的逻辑**只有横向**）。
  它顶上还会把 Kotlin 那边的两个常数读回来核对：镜像漂了比没有镜像更糟。
- `wiring_check.py` 抓的是"写完了没接线"：布局里有没有哪个**控件**一行 Kotlin 都没提到
  （点了没反应，而且没有任何地方说为什么），以及哪些函数**定义了没人调用**。
  前者是失败，后者只是一份阅读清单——见谁都喊的检查器会被无视。
- `kotlin_check.py` 抓的是 Kotlin API 的坑。最典型的一个：
  `optDouble("roomAir")?.toFloat() ?: 兜底` —— org.json 单参数版在键不存在时返回
  **NaN 而不是 null**，`?:` 永远不触发，于是地面、骨骼坐标、视图变换全变 NaN，
  **宠物画在"不是数字"的地方 = 什么都没画**。这个 bug 出过一次，
  两条检查都带自测，而且都**拿真 bug 反过来验过**（把错改回去，它报错）。

其中 `logic_check.py` 会**直接读 `LogicSpec.kt` 里那套默认规则**，
把事件名、动作名、数值名和 Kotlin 枚举逐个对照——默认规则写错一个字母，
本地就红，不用等装到手机上才发现"点了没反应"。

## 关于验证

物理有两份实现：Kotlin 引擎，和 `tools/ragdoll.py` 这份参考实现（带测试）。
**两份都必须存在**：Kotlin 只能在手机上跑，而手机不是用来调试数值的地方。

参考实现里完整记录了**两条走错的路**，都看起来很合理：

| 做法 | 为什么错 |
|---|---|
| 根节点用 Verlet 积分 | 拴点会瞬移根节点，而 Verlet 把位移当速度，下一步再加一遍 → **一秒内平方到 NaN** |
| 用"力"拴住被抓的点 | 平衡态是**退化**的：力只取决于手离手指多远，而"差一个弹簧长度"在任何身体位置都成立。所有参数都得到**逐字节相同**的错误姿势 |

最后可行的是：**先用 IK 让被抓的链条去够手指，够不到的部分才平移根节点**。


这台机器**编译不了 APK**（没有 JDK / Android SDK），所以：

- **数学**由 `tools/skeleton_tool.py` 在本地验证——它是 Kotlin 引擎的参考实现，
  含往返测试（随机合法姿势 → 取末端 → IK 反解 → 比对）和真实拖拽测试。
- **编译**由 GitHub Actions 验证。

```bash
python3 tools/skeleton_tool.py \
  --spec app/src/main/assets/characters/female_base/character.json \
  --verify --out docs/template_female_base.png
```

改动骨骼数学时**务必先跑这个**——它抓到过两个真实的符号错误，那两个错误在静止姿势下
完全看不出来，只有拖拽才会暴露。

动作列表的缩略图也一样：拟合外框取的是**骨架自己的外框**，不是画布——
用画布的话，一个蹲下的动作会缩成一个小点。`tools/pose_preview_check.py`
把几个姿势画成一张对比图（`docs/pose_preview_check.png`），改缩略图逻辑时对着看：

```bash
python3 tools/pose_preview_check.py
```

**这一版新加的两处验证**（两件新功能各有一条本地断言链）：

- **分支自己的如果**：`tools/logic_check.py` 的镜像里，规则的如果和分支的如果走**同一个**
  `holds_conditions`，测试钉住"不成立的那一支不跑而别的支照旧"、"带自己的当的分支如果不过时

  忘了写"，所以那两半在源码里点名核对。
- **靠近 / 走开**：`tools/rig_prop_check.py` 镜像了 `nearMisses`（和碰撞同一套胶囊）和

**参考图这一版的验证**：`tools/wiring_check.py` 里两句 —— 编辑器把状态表交给渲染器
（那正是"被状态挡住的图永远不画"的机器版本）、上传的图会被画出来；入口表里也多了

**现在有三条本地检查是红的**，而且都不是这一版弄红的（在改动之前的 `HEAD` 上跑，同样红）：

## 关于召唤到桌面：一只浮在别的 App 上面的桌宠

侧栏**最下面**那个按钮（**召唤到桌面**）把场上的那只送到桌面上：它浮在你正在用的任何
App 上面，**整块屏幕都是它的地盘**（世界就是屏幕，地面就是屏幕底边）。再点一下那个按钮
（或者控制条上的 **收回**，或者通知上的同名按钮）就送它回家。

- **左上角有一条小控制条**：**可摸宠物 / 点得穿**、**收回**。这两件事必须分开，因为宠物那
  一层是满屏的 —— 一直收触摸的话，底下的 App 就等于被一块透明玻璃盖住了。点「穿透」：
  宠物继续画着、继续按自己的规则动，手指全部穿过去。它自己必须在**另一层窗口**上，不然
  穿透之后就没有东西能把它切回来；
- 抓它、甩它、点它、长按它，和测试场里一模一样（同一套物理、同一套规则、同一个长按事件）；
- **长按侧栏那个按钮**会弹出一个菜单：**召唤道具 / 切换状态 / 换骨骼套 / 收回**，
  作用于**桌面上那一只**（它在别的 App 上面，够不着它自己的按钮，所以这些开关挂在送它出去
  的那个按钮上）；
- **第一次点它会先要一个权限**：Android 的「显示在其他应用上层」只能由用户在系统设置里给，
  App 只能解释并把你带到那一页（`SYSTEM_ALERT_WINDOW`）。它是**前台服务**，所以桌宠在
  桌面上时一直有一条通知 —— 那也是"收回"的第二条路；
- **两句得写在明面上的话**：①桌面上那只和 App 里那只是**同一个宠物的两个实例** ——
  规则各跑各的（你在 App 里看的时候，桌面上那只并不会暂停），数值和状态从各自加载那一刻
  起就是两份；②**它不存档**：桌面上发生的事不写文件，收回就没了。对一个随时会被收走的
  玩具来说，这是诚实的行为；**要"跑起来的宠物"，用测试场**；
- 悬浮窗只画宠物本身：网格、地面线、调参面板这些**屋子的家具**在桌面模式下不画
  （`setDesktopMode`），拖空白处也不平移镜头（世界就是屏幕，没有"窗外"可看），其余一切照旧；
- **它跟着全局设置走**，而且是**现在**的设置：召唤时读一次，你在 App 里改设置时再推一次。
  这里有一个具体的坑值得记下来：`applySettings` 只管重力、特效那些开关，**刚度是另一个
  属性** —— 少了那一句，设置里选"半软"、召唤出来却是全松垮（它停在 0）。
