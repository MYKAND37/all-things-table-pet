# All Things Table Pet

把桌宠做成一个**平台**，而不是一个会动的图片。

## 这个项目想做什么

| 方向 | 用户能做什么 |
|---|---|
| **部件化角色** | 不画整只角色，而是**画一个部位传一个**（一只手臂、一条腿），系统拼装成角色 |
| **可视化逻辑** | 不写代码，用搭积木的方式定义「**触发事件 → 判断条件 → 做出反应**」 |
| **道具系统** | 自定义道具（持续使用 / 装置 / 投掷 / 射击），并让道具和角色产生互动 |

## 架构

```
用户操作（手势 / 拖道具）
        ↓
   道具物理（弹道、持续接触、装备）
        ↓
   命中判定（打到哪个部位？）
        ↓
┌───────────────────────────────────┐
│  事件系统   谁在什么时候发生了什么    │  ← 带时间戳，可回溯
└───────────────┬───────────────────┘
                ↓
        角色数值 H / S / P / SH …       ← 被事件改写
                ↓
        规则层（用户连线的逻辑）          ← 条件 → 动作
                ↓
┌───────────────────────────────────┐
│ 对话类（气泡）│动作类（动画）│状态类（部位状态）│
└───────────────┬───────────────────┘
                ↓
           表现层：骨骼 / 图层 / 物理动画
```

## 两点关于手感的说明

**松垮的关节没有静摩擦。** 一个完全对称的松垮身体站在地上是**真平衡**，
会像雕像一样立着不动 —— 这是正确的物理，但不是一个"松垮"该有的样子。
所以加了两处刻意的非物理处理，都只在**松垮档 + 着地 + 几乎静止**时生效：

1. 极小的噪声（角度 2e-5 rad/步，根节点 0.6 px/s²），用来打破对称
2. 关节的**让位**：对自身偏角做正反馈。已经在偏的关节会继续偏，
   直到身体躺下（跨度小于站立时的 55% 就停止，否则永远停不下来）

角阻尼也从 1.4 降到 0.9 —— 1.4 让整个身体像在糖浆里动。

**抓住一个部位时，身体会真的吊下来。** 这件事花了三次才对：

| 做法 | 为什么不行 |
|---|---|
| 在被抓的点上施加**力**（一般的 mouse joint） | 平衡态是退化的，身体会飘到天花板停住 |
| 只**平移根节点** | 精确，但手臂根本不用动，于是身体"站"在手指上方，而不是吊在下面 |
| 只做 CCD（每个关节朝手指转） | 能碰到手指，但它**不知道谁重**——髋关节和踝关节一视同仁，而转髋关节等于转动整具身体。于是拎起一只脚时它去转整个身体，然后每一帧再跟重力互相抵消 |

对的是**给根关节的旋转上一条短皮带**：根关节的旋转就是整具身体的朝向，重力对它有更强的发言权。
两个手指往外掰两条腿时需要它（髋自己的限位掰不开），但只能占很小的权重（`ROOT_PIN_GAIN = 0.15`）。
此外，**被一根手指拎着时，整具身体是绕那根手指的摆**——所以要在手指处补一个重力力矩，
否则身体只会把重心收到骨盆下面（蜷在手边），而不是收到手指下面。

根关节自己写的那对限位，是"地面"的替身，所以只在**没人抓它的时候**生效。
在空中自由落体时仍然保留——试过放开，结果每次落地都摊成一团。

**可以同时抓好几个部位**：沙盒里每根手指各抓一个。落在角色身上的手指是"拉"，
落在空处的手指是"缩放"——劈叉和放大互不打扰。

**脚是个 68px 的胶囊**，等于一个真实的支撑面，所以它能站住。
如果你想要"一碰就倒"，把脚的 collider 半径调小即可。

## 关于逻辑：当 → 如果 → 就

**逻辑管理**里一个角色一套规则，画成这样，点任何一个方块改它：

```
┌────────────────────┐
│ 当：被甩出去        │   ← 点开选事件
└─────────┬──────────┘
          │
┌─────────▼──────────┐
│ 如果：生命 > 0      │   ← 点开改条件
└─────────┬──────────┘
          │
┌─────────▼──────────┐
│ 就：说「哇啊——！」  │   ← 点开改动作
│     痛苦 +20        │
└────────────────────┘
＋如果  ＋就  部位 全身   |   冷却 1.0s  只一次  删规则
```

为什么是图不是表单：一条规则难的地方从来不是某个字段，而是**看清这几步按什么顺序发生**。
一排下拉框恰好把这件事藏起来了。

九种事件：出现 / 每隔一会儿 / 被抓起 / 被放下 / 被甩出去 / 落地 / 打到 / 被点一下 / 被道具碰到。
十种动作：说话、数值增减、摆动作、生成道具、喷粒子、推一下、打坏部位、等一会儿。

**部位可以写前缀**：写 `hand` 会同时匹配 `hand_L` 和 `hand_R`。

**引擎里没有「数值变了」这个事件**，这是故意的：任何对数值的反应都能写成
「每隔一会儿 + 条件」，晚半秒但**不会自己触发自己**。规则改自己正在看的那个数，
正是那种写的人永远解释不清的 bug。

默认那套（改了就覆盖，可以「恢复默认」找回来）：被甩出去 → 喊 + 痛苦 20；
落地 → 痛苦 12 + 灰；被打到 → 痛苦 10 + 火花 + 喊；痛苦 ≥ 80 → 一直喊疼；
生命 ≤ 0 → 说「……」+ 松开动作 + 喷血（**只发生一次**）。

## 关于道具

**道具管理**里做道具，**测试场**顶部「道具」按钮放一个到桌上。四种用法：

| 类型 | 怎么用 |
|---|---|
| **持续使用** | 拖到角色身上按住，一直触发（刷子、食物） |
| **装置** | 放在桌上不动，角色碰到才触发（地雷、图钉） |
| **投掷** | 拖起来甩出去，砸到哪算哪 |
| **射击** | 拖出方向松手打出一发；道具留在原地，是个发射器 |

道具**不经过规则引擎去推角色**——推力是物理，有没有人写规则都会发生。
规则拿到的是一个事件：「被道具碰到 · 力度 640 · 打在 hand_L 上」，
**怎么算账是角色自己的逻辑说了算**。所以锤子和枕头可以是同一个道具，只是规则不同。

道具图不用对位：它不挂在骨头上，图片本身就是那个东西。
**没图的时候画一个绿圈，那就是它的碰撞范围**——调手感的时候比图还准。

## 关于自己搭骨架

**改骨骼**模式下，底部多了 **＋加骨骼** 和 **骨骼列表**：

- **加骨骼**：输入名字（默认 `bone_1`），点一个父级，然后**在画布上点两下** ——
  第一下是关节，第二下是末端。骨骼是画里的东西，唯一诚实的说法方式就是指着画说。
- **骨骼列表**：每根骨骼一行，**按层级缩进**，每行带「改父级」和「删除」。
  列表里还有「清空（只留根）」，这是从零搭一副骨架的起点。
- **改父级**：**骨骼不会移动**。头尾存的是画布坐标，父子相对关系是烘焙时才推出来的，
  所以换父级换的是"跟着谁动"，不是"在哪里"。
- 骨骼名同时是**文件名**：`parts/<名字>.png`。所以名字里的空格和
  `/ \ : * ? " < > |` 会被换成下划线 —— 名字是骨架和画之间的约定。

三条规矩，编辑器当场拦下来，不会等到烘焙时才炸：

| 规矩 | 为什么 |
|---|---|
| **只有一根根骨骼** | 出现第二根时 `buildSkeleton` 只认最后一根，另一棵树会**整棵消失** |
| **不能接到自己的下级上** | 成环。列表里那些自己的下级是**灰的**，点了会告诉你原因 |
| **根骨骼不能删** | 它的子骨骼会没有归属（要重来用「清空」） |

**删除只在「保存骨骼」时才落盘。** 在那之前"删除"只是一个意图，
中途走掉不保存，你的图还在。

## 关于动作

动作（pose preset）存在角色目录**旁边**的 `poses.json` 里，不在 `character.json` 里——
角色包是"素材"，动作是"你的用法"，两者升级互不覆盖。测试场顶部那个 **动作** 按钮打开列表：

- 每条动作左边是**骨架缩略图**。名字三个月后就没意义了，形状不会。
  缩略图只读 spec 画骨架，**不加载部件图片**，所以列表是秒开的。
- 点一条＝角色做这个动作，然后**列表自动关掉**，好让你看。
- 改名 / 删除都在列表里。存动作在**桌宠管理 → 摆姿势 → 存为动作**。

选动作时角色会被**放回原位站好**：不然一只被扔到角落躺着的桌宠，
做的动作就是躺在地上摆造型，什么也看不见。

## 关于验证（这一层也一样）

**规则引擎里没有一行 Android**：它只把"世界要执行的动作"还给调用方，
自己不知道气泡、骨头、粒子是什么。所以整个逻辑层能在本地测——

```bash
python3 tools/logic_check.py      # 冷却、只一次、部位前缀、延时、规则顺序
python3 tools/rig_prop_check.py   # 碰撞推出、接触节流、落地、投掷速度
python3 tools/drag_check.py       # 拎着脚踝倒吊、两根手指劈叉、甩出去的速度
```

其中 `logic_check.py` 会**直接读 `LogicSpec.kt` 里那套默认规则**，
把事件名、动作名、数值名和 Kotlin 枚举逐个对照——默认规则写错一个字母，
本地就红，不用等装到手机上才发现"点了没反应"。

## 关于验证

物理有两份实现：Kotlin 引擎，和 `tools/ragdoll.py` 这份参考实现（带测试）。
**两份都必须存在**：Kotlin 只能在手机上跑，而手机不是用来调试数值的地方。

参考实现里完整记录了**两条走错的路**，都看起来很合理：

| 做法 | 为什么错 |
|---|---|
| 根节点用 Verlet 积分 | 拴点会瞬移根节点，而 Verlet 把位移当速度，下一步再加一遍 → **一秒内平方到 NaN** |
| 用"力"拴住被抓的点 | 平衡态是**退化**的：力只取决于手离手指多远，而"差一个弹簧长度"在任何身体位置都成立。所有参数都得到**逐字节相同**的错误姿势 |

最后可行的是：**先用 IK 让被抓的链条去够手指，够不到的部分才平移根节点**。


这台机器**编译不了 APK**（没有 JDK / Android SDK），所以：

- **数学**由 `tools/skeleton_tool.py` 在本地验证——它是 Kotlin 引擎的参考实现，
  含往返测试（随机合法姿势 → 取末端 → IK 反解 → 比对）和真实拖拽测试。
- **编译**由 GitHub Actions 验证。

```bash
python3 tools/skeleton_tool.py \
  --spec app/src/main/assets/characters/female_base/character.json \
  --verify --out docs/template_female_base.png
```

改动骨骼数学时**务必先跑这个**——它抓到过两个真实的符号错误，那两个错误在静止姿势下
完全看不出来，只有拖拽才会暴露。

动作列表的缩略图也一样：拟合外框取的是**骨架自己的外框**，不是画布——
用画布的话，一个蹲下的动作会缩成一个小点。`tools/pose_preview_check.py`
把几个姿势画成一张对比图（`docs/pose_preview_check.png`），改缩略图逻辑时对着看：

```bash
python3 tools/pose_preview_check.py
```
